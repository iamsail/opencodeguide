月底打开账单，能得出的结论通常只有「贵」或「还行」，两种都指导不了下一步。月度复盘要固定的其实是三样东西：一个能重复的时间窗、一个能数的产出分母、一次只改一个配置的决定。单价与上下文的优化属于另一件事，这里只做核算。

## 分母只能是合并的 PR

token 数不是产出；代码行数会被删掉；对话轮次与支出几乎线性相关，等于用支出去解释支出。能数的只有交付物：合并的 PR、关闭的 issue、上线的变更。取数用 git，窗口写死在脚本里，别靠记忆。

```bash
MONTH_START=2026-10-01
MONTH_END=2026-11-01

# 分母：窗口内合并的 PR
git log --since="$MONTH_START" --until="$MONTH_END" --merges --oneline | wc -l

# 扣掉回滚：窗口内的 revert 提交
git log --since="$MONTH_START" --until="$MONTH_END" --grep='^Revert' --oneline | wc -l
```

窗口必须和结算对齐。Console 的预算按 UTC 每月 1 日 00:00 重置，账单天然是自然月；`opencode stats --days 30` 是滚动窗口。两者混着比，跨月比较就没有意义，所以先选定一套口径并写在决策记录里。

## 明细在本地，结算在 Console

`opencode stats` 读的是本机会话：`--cost` 给成本与 token 明细，`--models` 给模型分布，`--project .` 只看当前项目，`--json` 用来存档。Console 的 **Activity › Usage** 按天、模型与人细分费用，**Export usage** 能导出最近 7、30、90 天的 CSV，这是唯一带「人」这个维度的来源。

| 支出 | 是否计入预算 |
| --- | --- |
| Console 付费模型 | 是 |
| 自有提供商上设了价格的模型 | 是，按配置价格计入 |
| 网络搜索（每次 $0.01） | 是，计入全部支出预算 |
| 免费模型 | 否 |
| Go 套餐内的用量 | 否 |
| 用额度支付的 Go 额外用量 | 是 |

这张表解释了一个常见误判：Console 数字小不等于用得省，可能只是大量请求走了不计入预算的额度。做账时固定只用一套数字，另一套只看趋势，不要相加。

## 三种异常形状比总额有用

均值会掩盖问题。先把 `--models` 按模型排一遍，再看会话维度，超支基本落在三种形状里。

| 形状 | 信号 | 处理 |
| --- | --- | --- |
| 贵模型干检索 | 高价模型占 token 大头，对应 PR 改动很小 | 默认模型下移一档，重活显式 `--model` |
| 单会话过长 | 轮次上百、压缩反复触发 | 按任务开会话，稳定事实写进 `AGENTS.md` |
| 返工 | 合并后紧跟 revert 或大改 | 成本算两次、分母只记一次，复盘时剔除 |

第三种最容易被漏掉：返工让成本翻倍而分母不变，每 PR 成本被系统性低估，团队于是以为模型很便宜。分母里剔除返工 PR，比在报表里加一行备注有用。

## 每月 15 分钟：一个脚本加一页决策记录

把取数固定成脚本，每月只传入结算金额，剩下的交给它。

```bash
#!/usr/bin/env bash
set -euo pipefail

SPEND=${1:?用法: ./monthly-cost.sh <本月总花费，美元>}
MONTH=$(date -u +%Y-%m)
OUT=".ai-cost/${MONTH}"

mkdir -p "$OUT"
opencode stats --days 30 --cost   > "$OUT/summary.txt"
opencode stats --days 30 --models > "$OUT/models.txt"
opencode stats --days 30 --json   > "$OUT/raw.json"

MERGED=$(git log --since="30 days ago" --merges --oneline | wc -l | tr -d ' ') || MERGED=0
awk -v s="$SPEND" -v n="$MERGED" 'BEGIN {
  if (n == 0) { print "窗口内没有合并的 PR，先核对分母"; exit }
  printf "合并 PR %d 个，每个 PR 成本 $%.2f\n", n, s / n
}'
```

金额从 **Export usage** 的同窗口合计里取，脚本不做估算。明细文件留在本地并加进 `.gitignore`，仓库里只提交决策记录，否则数字本身会变成噪音。

| 字段 | 填什么 | 为什么 |
| --- | --- | --- |
| 总花费 | 导出 CSV 的同窗口合计 | 唯一能和财务对上的数 |
| 合并 PR | `git log --merges` 计数并扣掉 revert | 分母，必须同窗口 |
| 每 PR 成本 | 脚本输出 | 唯一能跨月比较的值 |
| 本月唯一改动 | 例如默认模型下移一档 | 一个月只动一个变量 |
| 下月观察 | 写明预期变化的信号 | 复盘要有假设，不只是记账 |

会议只需要三个动作：比上月、指出一处异常、改一个配置并提 PR。改两个以上变量，下个月的数字就无法归因。

## 落地动作

1. 在仓库建 `.ai-cost/`，把 `.ai-cost/` 加进 `.gitignore`，只提交 `docs/ai-cost-review.md` 这类决策记录。
2. 用同一个窗口跑一次 `opencode stats --cost --days 30` 和 Console 的 **Export usage**，把两个数字并列写下来，差异原因写清楚。
3. 把上面的脚本存成 `scripts/monthly-cost.sh` 并 `chmod +x`，用上月花费跑一次，把输出填进决策记录并提 PR。
4. 检查 Console 的预算是否覆盖工作区、所有成员、标签成员与每一个服务账户；漏一层就等于没设。

## 常见坑

- **现象**：本地 `stats` 的 token 与账单对不上 → **原因**：本地统计覆盖所有会话，Console 只统计经其网关的请求，预算又只计入其中一部分 → **对策**：固定一套做账，另一套只看趋势，永远不相加。
- **现象**：某月每 PR 成本翻倍，团队开始限用 → **原因**：分母塌了，合并 PR 变少，而不是单价上涨 → **对策**：同表记下 PR 数与改动规模，连续三个月再下结论。
- **现象**：月中被 `429` 挡住，所有人都停摆 → **原因**：额度没有留余量，而预算在请求开始时检查，月底冲量会先撞线 → **对策**：按工作区与成员分层设额度，别用一个总额兜底。
