前端 Bug 最难交接的从来不是代码，而是「点什么、在什么状态下点、点完之后控制台报什么」。让模型读组件源码猜复现路径，本质是让它做阅读理解。Playwright MCP 把浏览器交给它，但结果好坏取决于你给的是「可点击的步骤」还是「一段描述」。

## 模型看到的是可访问性树，不是像素

Playwright MCP 把页面压成一份带 `ref` 的可访问性快照，模型点的是 `ref`，不是坐标。这解释了三件事：快照里的文字就是它眼里的页面；`div` 嵌套再深也不影响它找到按钮，只要按钮有可读文本；反过来，一个只有图标的按钮如果没有 `aria-label`，它大概率点不中。「AI 点不到我的按钮」多数是无障碍标注问题，不是模型能力问题。

`ref` 有生命周期：导航或重新渲染后旧编号即失效。任务里要写明「每次操作前重新取快照」，否则会收到一堆假失败。

先把运行条件备齐，再写配置：

```bash
npx playwright install chromium
npx @playwright/mcp@latest --help
```

第二条命令不是形式主义：这类服务器的启动参数变动频繁，写进配置前先确认参数还在，比事后排查省时间。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "playwright": {
        "type": "local",
        "command": ["npx", "-y", "@playwright/mcp@latest", "--headless", "--isolated"],
        "timeout": { "startup": 60000 }
      }
    }
  }
}
```

`--headless` 让它在没有显示环境的机器上也能跑，`--isolated` 把浏览器配置留在内存里，会话结束即丢弃，不会污染你日常浏览器的登录态。启动超时给到 60 秒，是因为首次运行要拉包并装浏览器，默认 30 秒往往不够。

## 复现 Bug 要给「可点击的步骤」，不是一段描述

能用的任务描述只有四块：入口 URL、账号与初始状态、编号步骤、期望与实际。缺任何一块，模型都会自由发挥，而自由发挥等于编造。

第一条硬约束：第一轮只准做两件事——走到出错位置，取出控制台错误与失败的网络请求，不许改代码。先改代码再复现，你无法区分「它真的看到了」和「它猜了个合理原因」。

观察要写成句子：「点击提交后按钮进入 loading 且未恢复，`POST /api/orders` 返回 500」。这种描述能被人核对，「接口报错」不能。

| 适合交给 Playwright MCP | 不适合 |
| --- | --- |
| 按步骤复现一个可点出来的 Bug | 像素级视觉回归，快照是结构不是渲染 |
| 抓控制台错误和失败请求 | 生产环境的真实支付、删除操作 |
| 验证表单校验与跳转 | 需要验证码或短信验证的流程 |
| 在 staging 上走一遍验收路径 | 依赖你个人浏览器登录态的长流程 |

## 把证据落成文件，而不是留在对话里

对话里的证据会随着上下文裁剪消失，文件不会。让它在 `docs/bugs/` 下写一份报告，再基于报告改代码，评审时你能看到它到底看到了什么：

```md
复现报告：/checkout 提交订单无响应

步骤
1. 打开 http://localhost:3000/checkout
2. 用测试账号 test@example.com 登录
3. 购物车保留 1 件商品，点击「提交订单」

期望
跳转到 /orders/:id

实际
按钮进入 loading 后不恢复，页面停留在 /checkout

证据
- 控制台：Uncaught TypeError: Cannot read properties of undefined (reading 'id')
- 失败请求：POST /api/orders → 500
```

报告里没有控制台输出或网络请求的，退回重做。这一条把「有没有真看」变成了可检查的事实。

## 什么时候不该用它

需要判断视觉的时候不要用。快照里没有颜色、间距、层级遮挡，按钮被浮层盖住它照样认为可点击，这类问题仍然要靠人看。

环境也要分开。`--isolated` 隔离的是浏览器配置，不是副作用，它点下的「删除」是真的删。所有操作指向 staging 或本地，测试账号与真实数据保持距离。确实需要复用登录态时用 `--storage-state` 指向一份存储态文件，并且把该文件写进 `.gitignore`。

还有一个边界：OpenCode 桌面应用自带的 `browser` 命名空间能开标签页、取快照、看控制台，但只存在于应用内，终端会话里没有，那里要用 Playwright MCP。

## 落地动作

1. 执行 `npx playwright install chromium`，再跑 `npx @playwright/mcp@latest --help`，核对 `--headless`、`--isolated` 仍在参数列表里。
2. 把 `playwright` 条目写进 `opencode.jsonc`，`opencode mcp list` 确认 connected，再在会话里让它列出工具，记下归一化后的 `playwright_*` 名字。
3. 挑一个已知前端 Bug，按「URL + 账号 + 编号步骤 + 期望/实际」下任务，要求先产出 `docs/bugs/` 下的报告再动代码。

## 常见坑

- **现象**：模型连续几次点空、报元素不存在 → **原因**：复用了失效的 `ref`，或目标元素没有可读文本 → **对策**：任务里写明每次操作前重新取快照，并给图标按钮补 `aria-label`。
- **现象**：本地正常，CI 里服务器起不来 → **原因**：容器缺 Chromium 依赖且没有显示环境 → **对策**：保留 `--headless`，安装时用 `npx playwright install --with-deps chromium`。
- **现象**：它「修好」了一个你复现不出来的 Bug → **原因**：没有拿到控制台或网络证据就直接改代码 → **对策**：第一轮只准出报告，报告缺证据就退回，不接受口头结论。
