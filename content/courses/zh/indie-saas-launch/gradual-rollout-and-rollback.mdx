出事后第一反应通常是查日志。但收款故障每多持续一分钟，就多一批错误订单，止血比定位重要。更麻烦的是回滚：能否秒级切回上一个部署，取决于平台是否保留历史构建产物。决定损失大小的不是故障，而是开关有没有提前放好。

## 先给损失分类，再决定止损动作

不是所有故障都要停售。先判断属于哪一类，动作完全不同。

收错钱（价格、币种、商品对应错误）必须立刻停售，每笔新单都在扩大退款面。

重复收款或发货（事件重放、幂等失效）要停的是处理链路，不是销售页。

收钱不交付（邮件没发、权限没开）通常不用停售，先补发存量订单比停售划算。

页面承诺错误（政策、交付时间、退款窗口）优先级最低但最伤信任，改页面即可。

分不清时按最坏的一类处理——这是唯一值得保守的地方。

## 三级开关，从快到慢

链接级最快：在支付后台停用某个链接，几秒生效，不用部署。代价是所有使用这条链接的渠道（广告、邮件、社群）一起失效，点击后看到错误页。

构建级次之：用环境变量覆盖链接地址，页面从配置读，重新构建后生效。改的是配置而不是代码。

代码级最慢：回滚到上一个部署。平台保留不可变产物时可一键切回，是秒级；只能重跑构建时就是几分钟。它适合处理代码引入的回归。

反直觉的点：静态导出把值在构建时内联进产物，运行时不读取。改完必须重新构建，只改平台变量不会生效。

```bash
# 构建级换链接：变量名规则为 STRIPE_LINK_<SLUG>_<PLAN>，大写、非字母数字转下划线
STRIPE_LINK_AI_CODING_WORKFLOW_SINGLE=https://buy.stripe.com/replacement \
  npm run build

# 部署后确认产物里已经是新链接，而不是旧的
grep -rl "buy.stripe.com" out/ | head -n 5
```

## 灰度在静态站上只能按渠道做

静态站没有服务端分流，做不了按比例放量。可行的是渠道灰度：链接只发给邮件名单或社群，公开页保持「开售提醒」；确认交付、退款、客服三条链路正常，再打开公开按钮。

判断标准提前写死：前若干笔订单的交付完成率、首日退款申请数、咨询里「没收到东西」的占比。任一越线就关公开入口，把问题锁在名单用户里。

代价是灰度期收入少，名单用户也不代表冷流量；换来的是出错时受影响的人你认识。

## 回滚要演练一次，而且要留下操作位置

上线前主动回滚到上一个版本，再切回来。这一步会暴露三件平时看不见的事：回滚按钮在哪、产物是否可复现、两套部署的变量是否一致。

演练过的回滚和没演练过的区别不是速度，是事故中你还敢不敢按。

把三条止损动作写成一张纸：停用链接在哪一页、覆盖变量在哪个文件、回滚在平台哪一屏。事故中现找入口的代价，通常比故障本身更大。

## 决策表：止损动作选哪个

| 动作 | 生效时间 | 影响面 | 代价 | 适用条件 |
| :--- | :--- | :--- | :--- | :--- |
| 停用支付链接 | 秒级 | 所有使用该链接的渠道 | 已投放广告的点击全部失败 | 收错钱，且只有一条链接在收 |
| 覆盖链接变量并重建 | 一次构建 | 站点全量 | 构建期间旧链接仍在收钱 | 要换链接但不想停售 |
| 回滚到上一部署 | 一次构建加平台切换 | 全站 | 丢掉新功能 | 代码或配置引入的回归 |
| 全额退款加公告 | 小时级 | 已成交订单 | 手续费损失与信任 | 已经收错钱 |

顺序从上往下试：先做一分钟内能生效的那步，关掉出血口，再查原因。

## 落地动作

1. 写下三条止损动作的位置（后台页面、仓库文件、平台按钮），存成 `docs/runbook.md`。
2. 上线前完整回滚一次再切回，确认产物与变量都正常。
3. 回滚后立刻跑验证脚本，确认站点真的恢复。
4. 写死灰度退出标准，例如首日退款申请数越线就关公开入口。
5. 记录谁在几点按了哪个开关。

```bash
#!/usr/bin/env bash
# 回滚或停售后跑一次：确认恢复的是对的那一版
set -euo pipefail
BASE="https://example.com"
for path in / /pricing /thank-you /refund-policy /privacy /terms; do
  code=$(curl -s -o /dev/null -w '%{http_code}' "$BASE$path")
  [ "$code" = "200" ] || echo "FAIL $path -> $code"
done
# 停售期间这条应当失败，别把它当故障告警
curl -s "$BASE/pricing" | grep -q 'buy.stripe.com' || echo "WARN 购买入口不存在"
```

## 常见坑

- **现象**：改了环境变量，线上毫无变化 → **原因**：静态产物在构建时内联，运行时不读 → **对策**：改完必须重建并部署，再把产物 grep 一遍。
- **现象**：停用了链接，广告仍带来错误页点击 → **原因**：停售前没准备降级页 → **对策**：先把按钮指向等待名单，再停链接。
- **现象**：回滚后旧代码和新表结构对不上 → **原因**：只回滚代码，没回滚数据库 → **对策**：迁移保持向后兼容，先加字段不删字段。
