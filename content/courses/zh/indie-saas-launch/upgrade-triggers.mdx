免费版最常见的两个错误正好相反：一种把功能全给出去，指望用户良心发现；另一种到处弹升级窗，把还在摸索的人赶走。升级不是被说服的结果，是被卡住的结果。要做的只有一件事：在正确的时刻让卡点出现，并让它像产品的一部分，而不是收银台。

## 边界画在「重复」上，不画在功能上

限制功能数量看起来合理，实际效果很差：用户第一次打开就撞墙，还没获得价值，判断是「这软件不行」而不是「我得付费」。

限制重复次数相反：第一次用得完整、有产出，第三次才开始收费。此时用户已有参照——这东西确实省了时间。

可用维度是次数、人数、保留期：每月生成多少、能拉几个成员、数据留多久，都能在服务端计量，也能一句话说清。

代价是必须有配额系统：读取用量的检查函数、写入用量的记录点、显示剩余量的界面。没有这套东西，只能在功能上加锁，那通常是最差的位置。

## 四个时机，按付费意愿排序

配额将尽。用量到 80% 时预告，不拦截。此刻用户正在连续使用，是少数愿意读升级说明的时刻。

第二个成员进来。发出第一封邀请是协作需求最直接的证据，也是所有时机里最强的一个——个人用户会为一件事付费：让别人也能用。

导出与带走。PDF、CSV、API、发票。这是「把成果变成可交付或可报销的东西」的时刻，付费意愿远高于「多一个功能」。

时间与里程碑。试用到期，或完成第 N 个项目。时间型触发与用户进展无关，只适合「已经用完一轮」的产品，不适合仍在摸索的。

| 升级时机 | 可观测信号 | 适合的产品形态 | 实现成本 | 代价与风险 |
| --- | --- | --- | --- | --- |
| 配额将尽 | 已用量达到额度的 80% | 高频重复使用的工具 | 低，需计量 | 额度定错会直接压死留存 |
| 加入第二个成员 | 发出第一封邀请 | 协作型、团队会用 | 中，需成员模型 | 个人用户无感，白白增加复杂度 |
| 导出与交付 | 点击导出、生成发票 | 有交付物的工具 | 中，需导出链路 | 导出做太差会变成流失点 |
| 时间与里程碑 | 试用期结束、完成第 N 个项目 | 项目制或决策链短的工具 | 低 | 与用户进展无关，容易误伤 |

先只上一个时机，挑最容易实现的：已有成员表就从第二个成员开始，已有计量就从配额开始。

## 让卡点可观测，而不是到处弹窗

服务端统一判定：所有消耗额度的入口调用同一个检查函数，界面不做第二次判断，否则前后端迟早不一致。

`402` 表示「可以继续，但要付费」，`403` 留给权限问题。混用会让日志和提示全部失真。

只响应用户主动触发的动作：加载时弹窗是打断，点「生成」时提示才是解释。

至少埋三个事件：额度告警展示、升级按钮点击、进入结账。三者的落差说明问题在哪：点击多、结账少，多半是跳转后没承接上下文。

```ts
// 所有消耗入口共用：返回 null 表示放行，返回响应表示拦截
export async function assertQuota(orgId: string, cost = 1) {
  const { used, limit } = await getQuota(orgId);
  const remaining = Math.max(limit - used, 0);

  if (remaining < cost) {
    return Response.json(
      { error: "quota_exceeded", used, limit, upgradeUrl: "/pricing?from=quota" },
      { status: 402, headers: { "X-Quota-Remaining": "0" } },
    );
  }

  await incrementUsage(orgId, cost);
  return null;
}
```

## 什么时候不该有免费版

客单价高、决策链长（企业采购）的产品，用 demo 或销售沟通代替免费版：免费用户不会变成企业客户，只会占掉支持时间。

单次使用的产品用「免费试用 N 天」或只免一次，不要做永久免费档。

算力、存储成本高的产品，免费额度会直接变成成本。判断方法：免费用户月均资源成本是否超过你愿为一个注册付的钱，超过就砍。

## 落地动作

1. 在 `plans` 表里给每档写 `limit_key`（`projects`、`seats`、`exports`）和数值，不要用布尔 flag 表示「有没有这个功能」。
2. 服务端入口统一调用检查函数，前端只展示 `X-Quota-Remaining` 和升级入口。
3. 在 GA4 建 `quota_warning_shown`、`upgrade_clicked`、`begin_checkout` 三个事件，按计划分层看。
4. 只上线 80% 告警这一个时机，跑两周再加第二个。
5. 写下砍掉免费版的判断线：月均资源成本低于一个注册的可接受获取成本时才保留。

## 常见坑

- **现象**：免费用户很多，付费极少 → **原因**：免费额度覆盖了日常使用频率 → **对策**：月度额度降到「够完整评估一次，不够每天用」。
- **现象**：升级页点击不少，支付很少 → **原因**：从卡点跳过去没有上下文，用户不知道买哪档 → **对策**：URL 带 `?from=quota`，落地后高亮对应计划并预填用量。
- **现象**：用户配额耗尽后直接离开 → **原因**：没有提前告警，卡点到提交才出现 → **对策**：80% 时提示剩余量，结果页常驻显示。
