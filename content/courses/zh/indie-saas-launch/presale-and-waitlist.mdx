「上线记得叫我」是最没有信息量的一句话，它的成本为零，所以不能作为任何决策依据。点赞、收藏、转发同样如此。真正能改变决策的信号只有一种：有人在一个还不完整的东西上付了钱，并且知道交付日期还没到。

这条信号之所以强，是因为它同时验证了三件事——需求存在、价格可接受、你在对方心里有信用。

## 等待名单验证的是分发能力，不是付费意愿

留邮箱只说明有人愿意花十秒，不说明他愿意花一百美元。它的价值在于建立一条可以反复触达的通道，而名单会不会冷掉，取决于你有没有稳定的发送节奏：两周没有任何邮件，名单基本就废了。

最小实现是一个表单加一封确认邮件。表单只需要邮箱一个字段，多一个字段都在降低转化。确认邮件必须真的发出，否则你无法区分「填错了」和「不想要了」。

## 预售要先把三件事写在页面上

交付日期要具体到日，不能写「即将上线」。已交付内容要说明现在就能拿到什么——哪怕只是一份可用的模板或前两个模块，也比空头承诺可信。退款条件要写在同一屏，不要藏进 FAQ：未按期交付全额退款，是最容易写、也最能降低对方决策成本的一条。

三项里缺任何一项，你卖出去的就不是预售，是预支信任。

## 用哪种承诺形式，取决于你能承受多少交付压力

| 形式 | 承诺强度 | 退款风险 | 交付压力 | 适用阶段 | 最小实现 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 等待名单 | 无付款承诺 | 无 | 无 | 还没确定做什么 | 一个表单加邮件确认 |
| 早鸟折扣码 | 中：表达购买意愿 | 低 | 中 | 已有定价与交付日期 | 优惠码加购买页 |
| 订金 | 中：锁定意向 | 中 | 中 | 交付周期超过一个月 | 小额付款加尾款入口 |
| 全额预售 | 高：已验证付费 | 高 | 高 | 已有可交付的第一部分 | 收款加交付排期表 |

一个人的默认路径是先跑等待名单，再跑全额预售，中间不跳步。订金适合交付周期长的形态，代价是你要多维护一次尾款催收。

## 收款链路：Payment Link 还是 Checkout Session

只有一次性的单档预售时，用 Stripe Dashboard 里的 Payment link 最快：新建链接、绑定一个 Price、开启限时优惠码，不需要服务端，也不需要部署。缺点是无法按批次写元数据，退款和名单对齐要靠人工。

需要记录批次、交付日期或与自己的订单表对齐时，用 Checkout Session：

```ts
import Stripe from "stripe";

const stripe = new Stripe(process.env.STRIPE_SECRET_KEY!);

export async function createPresaleSession() {
  return stripe.checkout.sessions.create({
    mode: "payment",
    line_items: [{ price: process.env.STRIPE_PRICE_PRESALE!, quantity: 1 }],
    customer_creation: "always",
    client_reference_id: "presale-batch-1",
    success_url: "https://example.com/thanks?session_id={CHECKOUT_SESSION_ID}",
    cancel_url: "https://example.com/pricing",
    metadata: {
      batch: "1",
      deliver_by: "2026-12-31",
    },
  });
}
```

`client_reference_id` 与 `metadata` 会随会话进入后续事件，是订单可追溯的唯一锚点，别省略。付款成功后用 `checkout.session.completed` 这个 Webhook 事件写入自己的订单表，字段至少包含邮箱、金额、批次、承诺交付日期。

账户资质审核还没通过时无法收款。这种状态下先上等待名单，或者用人工转账并手工开收据——本站早期就是这么处理预售的，页面价值不依赖支付是否打通。

## 什么时候不用做

第一份可交付内容还需要三个月才能做出来时，不要做全额预售，改用订金或等待名单。预售卖的是「确定能按时交付的那一部分」，卖超出这个范围的东西，退款和口碑损失会远超收入。

## 落地动作

1. 在预售页同一屏写下三行条款：交付日期、现在就能拿到的内容、未按期交付的退款方式。
2. 在 Stripe Dashboard 建一个 Price，再建 Payment link 或接入上面的 Checkout Session，用一个限时优惠码限定批次。
3. 配好 `checkout.session.completed` 的 Webhook，落库字段写死为邮箱、金额、批次、`deliver_by`，并设一个「卖到 N 单就继续，否则全额退款」的公开门槛。

## 常见坑

- **现象**：预售卖出去了，之后天天被追问进度 → **原因**：没有公开的交付节奏 → **对策**：预售页写明更新日志放在哪个地址，按固定周期更新一次。
- **现象**：退款集中在交付日前后 → **原因**：承诺了做不到的范围，把预售当成融资 → **对策**：只承诺已完成或确定完成的部分，其余写成路线图且不标日期。
- **现象**：名单攒了几千个邮箱，开售第一周零订单 → **原因**：名单来自低价引流活动，和付费人群不是同一批 → **对策**：表单加一个来源字段，分开统计各来源的转化，只对相关来源做判断。
