产品能用、按钮也点了，卡住人的往往不是代码而是开户：材料交上去被打回两轮，或者账户通了才发现结账页收美元、到账是另一个币种，中间那截被换汇和费率吃掉。这两件事都能在写第一行支付代码之前定下来，顺序是主体、账户、币种、费率，反着做就要返工。

## 主体决定你能开哪种账户

Stripe 不支持中国大陆主体，可选路径三条，每条都在拿不同的东西换时间。

| 路径 | 适用条件 | 代价 | 什么时候别选 |
| --- | --- | --- | --- |
| 香港 / 新加坡 / 美国公司 + 当地银行账户 | 未来 12 个月有稳定收款，需要 Stripe 全套能力 | 年审、记账、报税、注册地址与银行账户都要长期维护，开户本身要等几周 | 还没验证有人愿意付钱 |
| MoR（Paddle / Lemon Squeezy） | 无海外主体、不想碰 VAT 与销售税，只想先收钱 | 抽成显著高于 Stripe 直连，以官网当期费率页面为准；品牌与结账页控制更弱 | 要做席位或按用量计费：迁回 Stripe 时客户与订阅数据要重搬 |
| 预售 + 人工收款 | 只有几十个种子用户，验证需求阶段 | 不能自动交付、不能规模化，退款与发票全靠手工 | 客户开始问发票和自动开通 |

判断方法只有一条：把维护主体的年成本（含记账与报税）与未来 12 个月的预计收款额放在一起，看前者占比是否已经吃掉利润。一个人能落地的最小版本，是用测试模式跑通全链路、先用 MoR 或预售收到第一笔钱，再决定是否注册公司。

## KYB 审核的是「你是否真在卖东西」

KYB 不是填表，是证明业务真实、资金能解释。常见材料是公司注册证书、董事与实益拥有人身份证明、地址证明、公司银行账户信息、业务描述和可公开访问的产品页面。

审核员会点开你给的链接。缺服务条款、隐私政策、退款政策、明码标价或可用联系邮箱，任何一项都足以打回。单人最省事的顺序是先把 pricing、terms、privacy、refund 四个静态页面挂上去，再提交账户申请。

业务描述写清三件事：卖什么（软件还是内容）、卖给谁（个人还是企业）、怎么交付（邮件发链接还是登录后观看）。本仓库脚本按 key 前缀区分模式：`sk_test_` 与 `sk_live_` 生成的链接分开记录，别把测试链接发到正式页面。

## 结算币种与到账：每换一次钱都在扣费

账户里有两个与币种相关的设置：余额以什么币种持有、按什么周期打到银行账户。买家在结账页看到的又是第三个币种。默认的多币种余额加自动换汇打款最省事，代价是换汇成本藏在每笔 `fee` 里，结账页看不到。客群集中在单一币种时，把该币种设成结算与打款币种，能少一次转换。

费率不是单一数字：百分比加固定费（随发卡地区与币种变）、跨境附加、换汇、退款时固定费通常不退、拒付另收一笔。具体数值以 Stripe 官网 pricing 页面为准，不要抄文章里的。唯一可信的口径是你自己账户里的 balance transaction：`amount`、`fee`、`net` 三个字段一对，有效费率就出来了。

```bash
# 先用测试模式验证取数逻辑，换正式 key 再看真实费率
STRIPE_KEY=sk_test_xxx

curl -s -u "$STRIPE_KEY:" \
  "https://api.stripe.com/v1/balance_transactions?limit=10" \
  | jq -r '.data[] | [.currency, .amount, .fee, .net, (.exchange_rate // 1)] | @tsv' \
  | awk -F'\t' '{ printf "%s 收 %.2f 费 %.2f 到 %.2f 汇率 %s 有效费率 %.2f%%\n", $1, $2/100, $3/100, $4/100, $5, ($2 ? $3/$2*100 : 0) }'
```

把算出的有效费率写进定价文档，定价时按它倒推，而不是按官网宣传的百分比。什么时候不用管：订单还在两位数、客单价不低时，纠结百分之零点几不如把价格抬一档，把精力放回获客。

## 落地动作

1. 在仓库建 `docs/stripe-kyb.md`，按「注册证书 / 董事身份 / 地址证明 / 银行账户 / 业务描述 / 四个政策页」逐项列，先自查再提交。
2. 上线 `/pricing`、`/terms`、`/privacy`、`/refund` 四个页面，退款政策写明天数与条件，并与结账页承诺一致。
3. 用测试卡 `4242 4242 4242 4242` 在测试模式跑一笔，再跑上面那段 curl，把 `fee` 与有效费率记进 `docs/pricing.md`。
4. 首笔真实订单只用小额，确认 payout 到账日期与金额后再放量，把结算周期写进现金流表。

## 常见坑

- **现象**：材料交两轮都被打回，理由还很含糊 → **原因**：站点打不开或政策页缺失，审核员无法确认业务真实性 → **对策**：先让页面可访问，提交时直接给出四个政策页的完整 URL。
- **现象**：账户通过、能收款，payout 却一直推迟 → **原因**：新账户处于风险观察期，首笔资金结算周期更长 → **对策**：预留至少一个 payout 周期的现金，别把首月收入当已到账。
- **现象**：结账页显示 $49，到账明显少一截 → **原因**：结账币种与打款币种不同，换汇费与跨境费在中间扣掉 → **对策**：定价统一用收款币种，参考价旁标注「以美元结算」。
