把产品写完再验证，等于把三个月的赌注压在一个从未被检验的假设上。验证真正要回答的不是「这个产品好不好」，而是三件更小的事：有没有人看懂你在说什么、看到价格后还愿不愿意往下点、以及他们是否愿意留下可以被再次触达的联系方式。

这五个页面一个周末能上线，不需要后端、不需要登录、不需要数据库。

## 五个页面各验证一个假设

首页回答「这是给谁的、解决什么、替代掉现在的什么做法」。首屏只放一句话加一个 CTA，验证的是定位可读性——如果陌生人读两遍还不确定你在卖什么，后面所有页面都白做。

定价页验证价格预期。把计费单位写清楚（按用户、按次、按月），并给出一个具体数字。失败信号不是「有人抱怨贵」，而是没人停在定价页，或者停留很久却直接离开——后者通常意味着价格与价值描述对不上。

场景页放三个具体工作流，每个用「现在怎么做 → 用它之后怎么做」两栏。它验证的是场景能不能被认出来，失败信号是访客在场景页的停留时间明显短于首页。

对比页写「不用它会怎样」以及和现有做法的差异。这一页验证替代成本，也是唯一一页允许出现竞品名的页面。

最后一页是 FAQ 加信任信息：你是谁、退款怎么算、数据放哪里。它不产生新假设，只负责把犹豫的人推过线。

## 静态文件起站，别先写后端

五份 HTML 加一个 CTA 事件就够了。所有页面共用同一个 CTA 事件名，用参数区分位置，这样按页面拆分数据时不需要改埋点。

```bash
mkdir -p ~/validate/{pricing,use-cases,compare,faq} && cd ~/validate
for d in . pricing use-cases compare faq; do
  printf '<!doctype html><meta charset="utf-8"><title>%s</title>\n' "$d" > "$d/index.html"
done
python3 -m http.server 4321
```

页面里的 CTA 全部带 `data-cta`，点击时打到同一个 GA4 事件：

```html
<script>
  // 所有按钮共用一个事件名，用 cta_location 区分来源
  document.querySelectorAll("[data-cta]").forEach((el) => {
    el.addEventListener("click", () => {
      window.gtag?.("event", "cta_click", {
        cta_location: el.dataset.cta,
        page_path: window.location.pathname,
      });
    });
  });
</script>

<a href="/waitlist" data-cta="hero">加入等待名单</a>
```

接上 GA4 后，在「报告 → 互动 → 事件」里能看到 `cta_click`，再用 `Realtime` 报告确认本地点击真的上报了，别等一周后才发现埋点是空的。

## 看信号，不看访问量

访问量高只能说明渠道给你面子，不能说明有人要这个产品。

| 信号 | 说明什么 | 误判风险 | 一个人怎么采集 |
| :--- | :--- | :--- | :--- |
| CTA 点击 | 说法至少打动了一部分人 | 高：点按钮成本极低 | 页面事件埋点 |
| 留下邮箱 | 愿意被再次触达 | 中：可能只想要免费东西 | 一个表单字段 |
| 定价页滚动到底 | 认真评估过价格 | 中：好奇也会看完 | 滚动事件 |
| 回复邮件并提问 | 已在脑内预演使用场景 | 低 | 人工回复 |
| 主动问「什么时候能买」 | 购买意图接近成立 | 低 | 人工记录 |

连续七天看这四个数：访客数、CTA 点击、留资数、留资后回复数。留资率是唯一值得和渠道一起看的指标，本站给自己定的门槛是七天留资率不低于百分之三，达不到先改首屏文案，不要急着加功能。

## 什么时候不用做

已经有人私下反复问你要这个东西，或者你正在收费做同类委托，直接跳到预售。页面验证解决的是「没人认识你、也没人听懂你」的问题；这两条不成立时，五个页面就是浪费一个周末。

## 落地动作

1. 用一句话模板写首屏：给「谁」，「在什么场景」下，用「什么结果」替代「现在的做法」。三个空都要填具体名词。
2. 按上面的命令建五个目录，每页一屏内容，先不上样式框架，保证手机能读。
3. 加 `data-cta` 与事件埋点，用 `Realtime` 报告确认点击上报成功，再开始算七天窗口。

## 常见坑

- **现象**：访问量不低，留资几乎为零 → **原因**：首屏讲的是技术和功能，不是对方能拿到的结果 → **对策**：把首句改成「谁 + 场景 + 结果」，删掉所有架构名词。
- **现象**：两周过去还在纠结域名和配色 → **原因**：把验证页面当作品牌资产 → **对策**：先用托管平台的默认域名，验证通过后再迁移，接受一次失效链接的成本。
- **现象**：所有 CTA 都指向「联系我们」 → **原因**：承诺成本太高，访客不知道要谈什么 → **对策**：换成单一邮箱字段的等待名单，只留一个输入框。
