大多数 side project 不是死于代码写不完，而是死于形态选错：一个人去做需要销售团队的垂直 SaaS，或者花三个月做一个本该两周上线的工具。形态决定的是获客方式、维护面和收款模型。判断顺序只有一条——能不能一个人长期维护，比能不能做大更重要。

## 工具：一次解决一个具体动作

用户带着明确任务来，几分钟内完成就走。格式转换、批量重命名、图片压缩都属于这类。

选择条件：任务边界清晰、用户不需要录入并沉淀自己的数据、没有协作需求。

代价是单笔金额低、几乎没有复购，获客依赖搜索与目录站，天花板由流量决定，被平台功能或通用模型吞掉的风险最高。硬约束只有一条：一周内做不完，它就不是工具了。

什么时候不用做：如果核心价值必须靠用户持续录入数据才成立，那是 SaaS 的雏形，按工具做只会做出半个产品。

## 垂直 SaaS：持续替一个角色干活

以订阅收款，替某个具体角色处理一件反复发生的事：排班、报价、合规申报、客户回访记录。

选择条件：这个角色你能直接接触到十个人以上，流程有稳定的重复结构，痛点属于流程而不是一次性查询。

代价最大。多租户、权限、数据迁移、客服、税务合规会被逐一带进来，销售周期也明显更长。一个人的版本必须砍到「一个角色、一个流程、一个报表」，其余写进不做清单。

什么时候不用做：如果拿前五个用户必须靠行业介绍，而你没有人脉，先别做订阅制。用工具换名单比用三个月换零用户便宜。

## 信息产品：把顺序和判断打包

课程、模板仓库、检查清单、付费通讯。卖的不是信息，是省掉的试错时间——同类内容公开文档里也有，只是没有顺序和验收标准。

选择条件：你在某个流程上确实有非公开经验（踩过的坑、能直接抄的模板），且目标人群已经在为同类内容付费。

代价是制作周期长、更新义务长期存在、盗版与退款压力不会消失；收入上限取决于分发能力，而不是内容质量。

什么时候不用做：手上没有能触达目标人群的渠道时，它几乎卖不动。信息产品是放大器，不是获客渠道。

## 用维护面而不是想象力打分

这张表列清每种形态要长期支付什么。

| 对比维度 | 工具 | 垂直 SaaS | 信息产品 |
| :--- | :--- | :--- | :--- |
| 首笔收入周期 | 1-2 周 | 1-3 个月 | 3-6 周 |
| 单人长期维护面 | 小：托管与依赖更新 | 大：租户、权限、客服、合规 | 中：内容更新与退款 |
| 获客主要依赖 | 搜索、目录站 | 直接触达、社区口碑 | 自有渠道与内容分发 |
| 收款模型 | 一次性或按次 | 订阅 | 一次性 + 升级包 |
| 被替代风险 | 高（平台功能覆盖） | 中（迁移成本形成护城河） | 中（盗版与免费内容） |
| 失败成本 | 1-2 周 | 1-3 个月加沉没代码 | 数月制作加口碑 |

把候选写成结构化文件再打分。

```bash
mkdir -p ~/indie/shape-audit && cd ~/indie/shape-audit

cat > shapes.json <<'JSON'
{
  "candidates": [
    {
      "name": "批量发票整理工具",
      "checks": {
        "solo_maintainable": true,
        "first_user_known": true,
        "ship_in_14_days": true,
        "payer_is_user": true,
        "no_sales_team_needed": true
      }
    },
    {
      "name": "诊所排班 SaaS",
      "checks": {
        "solo_maintainable": false,
        "first_user_known": true,
        "ship_in_14_days": false,
        "payer_is_user": true,
        "no_sales_team_needed": false
      }
    }
  ]
}
JSON

jq -r '.candidates[]
  | .name as $n
  | ([.checks | to_entries[] | select(.value == true)] | length) as $pass
  | ([.checks | to_entries[]] | length) as $total
  | "\($n)\t\($pass)/\($total)\t\(
      [.checks | to_entries[] | select(.value == false) | .key] | join(",")
    )"' shapes.json
```

第三列是被打掉的检查项。短板超过两项，换形态比硬做更快。

## 一个人能执行的最小版本

每个形态都先降一级：垂直 SaaS 先做成服务三个客户的半自动工具，信息产品先做成一页付费文档，工具先做成三个输入框的单页。降级不是退让，是把验证成本压到一周以内。

## 落地动作

1. 把三个候选按五个检查项填进 `~/indie/shape-audit/shapes.json`，跑一次上面的 `jq`，看谁短板最多。
2. 给每个候选补一句「第一个付费用户具体从哪来」，要写出具体的人、渠道或社群名。写不出来就划掉。
3. 为留下的那个写死 14 天边界，边界外需求一律延后到第一笔收入之后。

## 常见坑

- **现象**：工具做着做着变成半个平台，三个月还没上线 → **原因**：每遇到相邻场景就「顺便也支持」 → **对策**：v1 只允许一个动作、一种输出格式，其余进 backlog 且不承诺时间。
- **现象**：垂直 SaaS 建了两周还在写邀请和权限 → **原因**：先搭平台再找用户，把基础设施当进度 → **对策**：前三个客户用表格加脚本手工服务，确认会付钱再写权限。
- **现象**：信息产品做完了没人买 → **原因**：先做产品后找渠道 → **对策**：先放定价页和预售入口，有人付款再投入制作。
