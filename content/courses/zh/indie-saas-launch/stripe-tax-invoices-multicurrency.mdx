「开了自动算税」和「按买家国家收了税」是两件事。前者是结账页上的开关，后者需要你在该国完成税务登记；开关打开而登记为空的账户，税额算出来是零，结账页却显示得干干净净。

## 税：先看你在哪些国家有申报义务

数字服务的征税权多数落在买家所在地。没在某个国家登记税号，就不该在那里收税；但一旦超过门槛，注册与补缴的义务往往追溯到更早，晚注册并不免除之前的部分。

Stripe Tax 是两步，不是一步：先在 Dashboard 的 Tax 里登记你已注册的国家与地区，再在结账页上打开自动算税（Payment Link 上是 `automatic_tax[enabled]=true`）。只做第二步，税额算出来是 0；只做第一步，结账页不会显示税。这是「开了却没收到税」最常见的原因。

门槛数字会变：欧盟跨境 B2C 用统一小额门槛，英国按滚动十二个月算，美国各州规则各不相同，别凭记忆写数字，用 Dashboard 的门槛监控加税局公告。若主体在中国大陆，Stripe 开户这关就过不去，此时要选的不是税务方案而是 MoR。

| 路径 | 适用条件 | 谁承担申报 | 代价 |
| :--- | :--- | :--- | :--- |
| Merchant of Record（Paddle、Lemon Squeezy 等） | 无海外主体、不想碰税、先验证需求 | 平台 | 抽成更高；发票抬头不是你；定价、退款、结算节奏受平台规则约束 |
| Stripe Tax + 自行申报 | 有海外主体，能承担记账与申报 | 你 | 注册与申报是持续工作，不是一次配置；要算进人力或代账费 |
| 不开自动算税，只在条款里声明 | 只做小额 B2B，买家自行处理 | 你（隐性） | 被追缴时含滞纳金；面向欧盟 B2C 基本不成立 |
| Stripe Tax + 第三方税务服务（如 TaxJar、代账方） | 多国、多币种、已有稳定收入 | 你与代理共担 | 多一套系统与数据口径要对接 |

## 发票不是收据，B2B 客户只认后者

支付成功后 Stripe 会发 receipt，它只证明钱收了，不是可入账的税务发票。税务发票需要账单地址、买家税号、单价与税额分行、发票编号、卖方主体。

打开 `invoice_creation[enabled]=true` 后，Stripe 会生成 invoice 并提供一个可下载 PDF 的页面；账单地址来自结账页收集，所以账单地址收集必须开。欧盟 B2B 客户填写有效 VAT ID 时按 reverse charge 处理，税额显示为 0 不是漏算，而是纳税义务转移给对方——前提是你在结账时收集了税号，否则只能按 B2C 含税开票。

企业采购最常卡在两处：发票上要写公司名与采购单号。公司名要与账单地址的 company 字段一致，采购单号放进 invoice 的自定义字段。国内客户要增值税发票，Stripe 出不了，这类客群要么走国内渠道，要么提前说清只提供收据。

## 三个币种：定价、展示、结算

定价币种写在 Price 上，创建后不可改。所以「支持多币种」在 Stripe 里的真实含义是「每个币种一套 Price 和一套链接」，维护成本随币种数线性上升。

展示币种是客户看到与支付的币种，Stripe 的本地货币展示能力会按买家地区换算并锁定汇率，适合一次性付款；它不改变你的定价币种，到账仍要换回结算币种。结算币种是银行账户的币种，非结算币种收款会在 payout 时换汇，汇率差与手续费体现在 balance transaction 的 `exchange_rate` 与 `fee` 上。收入看着不错、到账少一截，通常就是这一层。

| 策略 | 实现 | 适用条件 | 代价 |
| :--- | :--- | :--- | :--- |
| 单一美元定价 | 一个 Price、一个链接 | 早期，用户全球分散 | 非美元用户看到外币价，转化有损失 |
| 美元定价 + 本地货币展示 | 打开本地货币展示 | 想减少汇率犹豫又不维护多价 | 支持范围随账户与地区变化；到账仍换汇 |
| 多币种独立定价 | 每币种一个 Price 与链接 | 已有明确的主力地区 | 改一次价要改多套；对账要分币种核 |
| 区域购买力定价 | 多套 Price + 按地区路由 | 某地区收入占比已很高 | 单人早期不建议，规则与客服成本都会翻倍 |

页面写清结算币种能省掉大量客诉，这一句比多做三种币种值钱。

## 落地动作

1. 在 Dashboard 的 Tax 设置里登记已注册国家，再用下面的请求建 Price 与链接，把税务行为与发票一次配好：

```bash
set -euo pipefail
: "${STRIPE_SECRET_KEY:?先导出测试模式密钥}"

# 1) Price：把税务行为定下来。exclusive = 标价不含税，inclusive = 价内含税
curl -s https://api.stripe.com/v1/prices \
  -u "$STRIPE_SECRET_KEY:" \
  -d "product=prod_xxx" \
  -d currency=usd \
  -d unit_amount=9900 \
  -d tax_behavior=exclusive | jq '{id, currency, unit_amount, tax_behavior}'

# 2) Payment Link：打开自动算税与发票生成
curl -s https://api.stripe.com/v1/payment_links \
  -u "$STRIPE_SECRET_KEY:" \
  -d "line_items[0][price]=price_xxx" \
  -d "line_items[0][quantity]=1" \
  -d "automatic_tax[enabled]=true" \
  -d "invoice_creation[enabled]=true" | jq '{url, automatic_tax, invoice_creation}'
```

2. 用德国和加州两个账单地址各跑一次测试结账，确认税额出现、invoice PDF 能下载，且上面有主体名、税号与税额三行。
3. 在定价页写一句结算币种（例：以美元结算，本地货币金额仅供参考），并在退款条款里说明汇率差由谁承担。
4. 每季度看一次 Dashboard 的门槛提醒与各币种净收入，把 `fee` 与 `exchange_rate` 加进现金流预测，而不是只看总销售额。

## 常见坑

- **现象**：开了 Stripe Tax，结账页没有税额 → **原因**：Tax 里没登记对应国家，或商品 tax code 没设走了默认分类 → **对策**：先查登记清单，再查 Product 的 tax code，两步都对了才会计税。
- **现象**：企业客户要发票，收到的却是收据 → **原因**：只开了收据邮件，没开 invoice 生成；或结账页没强制收集账单地址 → **对策**：链接上开 `invoice_creation`，并确认账单地址为必填。
- **现象**：销售额不错，payout 少了一截 → **原因**：非结算币种收款换汇，叠加原交易手续费与退款 → **对策**：按 balance transaction 的净额做预测，别用支付总额。
