从竞品站点复制三页政策，是最贵的省事方式：管辖法律写着别人所在的州，退款条款和你页面上的「7 天无理由」互相打脸，而争议发生时，平台和用户要看的正是这一页。模板只解决「有没有」，解决不了「和你的实际做法是否一致」。

下面讲写什么、怎么核对，不构成法律意见；涉及个人数据或跨境销售，最终仍看主体所在地的要求。

## 三份文档各管一件事

隐私政策回答：收集了什么、为什么、交给谁、留多久、怎么要求删除。读者是用户和监管方。

服务条款回答：提供什么、不承诺什么、何时可终止账号、争议怎么处理。读者是用户和支付平台的风控。

退款政策回答：什么条件下退、多久到账、退到哪里、怎么申请。读者是付款前犹豫的人，它直接影响转化率。

三者最容易出的错是互相矛盾，而不是写得不够长。一份三百字但和页面完全一致的政策，比三千字的模板更安全。

## 退款政策是最容易出事的一份

退款政策必须和四处对齐：销售页文案、结账页说明、收据邮件、收款后台。任何一处不同，用户都会拿对自己有利的那份来主张。

写作时用固定四段：可退条件、申请方式、到账时间、不退或部分退的情形。数字要在页面和政策两处一致，靠人工同步迟早会漏。

数字商品的矛盾绕不开：用户要「无理由」，而你已经交付了可复制的文件。退款怎么分级，应该在定价阶段就定下来；政策这一页不发明规则，只负责把它翻译成客服能执行、用户能预期的话。写清判定标准，比「原则不退」更能减少争议。

代价是政策越具体，你被自己的承诺绑得越紧。这恰恰是它有用的原因：含糊条款保护不了你，只会让平台按用户的理解裁决。

## 隐私政策列真实处理者

把实际在用的第三方逐个列出，写清用途与涉及的数据。典型组合是：支付平台（邮箱、账单地址、卡号后四位）、事务邮件服务（邮箱、订单号）、分析工具（页面与事件参数、设备信息）、托管平台（访问日志），做会员中心之后再加入登录与数据库服务。

列多了是给自己挖坑，列少了是实打实的错。判断依据不是「行业惯例」，而是 Network 面板和每月账单——能对上的才写。

用一份结构化文件维护清单，隐私政策页面从它渲染：

```yaml
# content/legal/processors.yaml —— 隐私政策的「第三方处理者」一节由它生成
- name: Stripe
  purpose: 支付、退款、发票
  data: 邮箱、账单地址、卡号后四位
- name: Resend
  purpose: 事务邮件（收据、开通、密码重置）
  data: 邮箱、订单号
- name: GA4
  purpose: 访问统计
  data: 页面与事件参数、设备信息
```

改动只改这个文件，不会出现「新增了服务商但政策页没动」。

## 决策表：三份文档谁来写

| 方式 | 适用条件 | 代价 | 什么时候不用 |
| :--- | :--- | :--- | :--- |
| 生成器（Termly、iubenda 一类） | 主体在欧美，业务形态标准 | 订阅成本；措辞通用，和你的流程有缝隙 | 有企业客户要求定制条款 |
| 模板改写 | 单人、单产品、只卖数字内容 | 每条都要自己核对是否与实际一致 | 涉及用户上传内容或敏感数据 |
| 律师定制 | B2B、客单价高、涉及数据处理 | 按小时计费，每次改流程都要再付一次 | 还没成交第一单 |
| 平台自带条款（Paddle、Lemon Squeezy） | 无海外主体，由平台代收代缴 | 条款由平台定，你只能补充交付与退款 | 需要自有品牌发票与企业合同 |

前三种都能今天开始，成本差在一到两个数量级。判断标准只有一条：这份文档会不会被拿去打官司。不会被拿去打的，模板加核对就够；会的，别省这笔钱。

## 落地动作

1. 用四段结构写退款政策，把窗口天数、到账时间、申请入口填成具体值。
2. 把实际在用的第三方填进 `content/legal/processors.yaml`，只填能说出用途的。
3. 三页挂到页脚，并用绝对路径（`/privacy`、`/terms`、`/refund-policy`）互相链接。
4. 在感谢页和收据邮件里放退款政策链接，别只放页脚。
5. 跑一遍一致性检查，把结果留在发布记录里。

```bash
# 页面承诺与政策页必须出现同一个退款窗口
grep -rn "7 天" content/ --include="*.mdx" --include="*.json" | grep -v node_modules

# 三页是否都能被站内链接到（漏挂页脚等于没有）
for p in privacy terms refund-policy; do
  grep -rq "/$p" content/ || echo "MISSING link: /$p"
done
```

## 常见坑

- **现象**：付款后第五天申请退款，页面写 7 天可退，条款写不退 → **原因**：政策从模板复制，没和销售页对齐 → **对策**：退款规则单一来源，页面、条款、邮件都从它生成。
- **现象**：隐私政策列了十几家服务商，一半没用过 → **原因**：抄了别人的清单 → **对策**：按实际出网请求与账单倒推，只写能对上用途的。
- **现象**：政策页能打开，结账时却找不到 → **原因**：只挂了页脚 → **对策**：结账页与感谢页各放一次链接。
