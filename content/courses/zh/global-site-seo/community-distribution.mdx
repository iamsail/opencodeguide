社区帖子被删、账号被限、评论区被骂「广告」，原因几乎总是同一个：帖子的目的是拿走流量，而不是参与讨论。

好消息是这三个地方的规则都写在明面上。读规则花二十分钟，比被封号后重建账号便宜得多。

## 先查规则，再决定发不发

每个社区、每个子版块、每次活动都有自己的规则页、wiki 或置顶帖，规则会变。查四项就够了：

| 要查的项 | 在哪查 | 不满足时怎么办 |
| :--- | :--- | :--- |
| 自我推广是否允许 | 社区规则页、版块 wiki | 换社区，或改发评论 |
| 允许的形式 | 置顶帖、规则说明 | 把「链接帖」改成「经验帖」 |
| 账号历史要求 | 规则页、版务公告 | 先参与讨论几周再发 |
| 商业内容是否有固定栏目 | 社区活动帖、周更帖 | 等对应栏目，别硬发 |

把结果记成表，下次不用重新查：

```csv
community,self_promo_rules,allowed_format,account_history,post_channel,note
"r/xxx","仅限特定主题日","经验帖 + 评论补充链接","需一定历史","每周主题帖","先读置顶"
"Show HN","允许，必须是自己的作品","Show HN: 名称 – 一句话","无","直接提交","标题不加营销词"
"Product Hunt","需完整产品页","发布日素材 + 首批评论","无","发布日","提前准备截图"
```

## 帖子要能独立成立

判断标准：读者永远不点链接，看完有没有收获？没有，这个帖子就是广告。

结构可以固定成：我遇到的具体问题 → 我试过的做法与失败 → 现在的做法 → 结果数据 → 链接放在最后一段或第一条评论。HN 的 Show HN 有固定格式，标题写清是什么、不加形容词；Reddit 的正文可以长，但第一段必须给结论；Product Hunt 依赖产品页素材和发布当天的评论互动。

链接的位置很关键：正文里放一两个就够，其余放评论。正文塞满站内链接的帖子，会被自动规则和版主同时盯上。

## 三个平台，三种读者预期

- **Reddit**：分版差异极大，同一个产品在 A 版是欢迎的，在 B 版是违规的。先在你目标版块回答别人的问题，攒到有人认识你的账号，再发自己的东西。标题别用营销句式，正文用第一人称写过程和数字。
- **Hacker News**：技术读者多，最恨空洞的发布帖。Show HN 要求是「你自己做的东西」，正文写技术选择、踩过的坑、限制。发布后守在评论区回答问题。
- **Product Hunt**：本质是一个当天的榜单活动。提前准备产品页、截图、演示视频和一段简短说明；发布日协调首批真实用户来评论，评论要写具体使用场景而不是「支持一下」。

## 分发后要记什么

至少记四项：来源（帖子或评论）、引荐访问、注册数、以及四周内是否被别的站点二次引用。

本站是静态站点，社区带来的访问会直接落到具体页面。发之前确认落地页在移动端可读、首屏有结论、没有自动弹窗。

## 落地动作

1. 选两个社区，把规则页读一遍，填进上面的表；任何一项不确定就先不发。
2. 写一篇 600 字左右的帖子，只用「问题 → 失败 → 做法 → 数据」四段，链接放最后，先给三个同行看，问他们会不会点。
3. 发布后 48 小时内只做一件事：回评论。之后把来源、访问、注册记进表，四周后回看哪些帖子带来了二次引用。

## 常见坑

- **现象**：帖子发出去几分钟就被删。→ **原因**：没读该版块的自我推广规则，或账号太新。→ **对策**：先读置顶与 wiki，用评论参与一段时间，再按允许的栏目发。
- **现象**：帖子有浏览量，注册几乎为零。→ **原因**：帖子只讲产品，没讲读者的问题，落地页也无法延续帖子的承诺。→ **对策**：帖子里给结论与数据，落地页首屏复述同一结论。
- **现象**：同一篇帖子复制到五个社区，全被踩。→ **原因**：各社区的读者预期与规则不同，统一文案一眼就是群发。→ **对策**：每个社区单独改标题与开头一段，只保留核心事实。
