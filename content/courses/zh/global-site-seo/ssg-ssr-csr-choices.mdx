最常见的两种翻车方式正好相反：为了一个带筛选的列表页，把整站从静态导出改成 SSR，构建变慢、上线要服务器；或者整站纯客户端渲染，HTML 里只有一个挂载点，首屏白屏两秒，爬虫拿到一张空壳。

渲染方式是内容属性的函数。

## 用三个问题给页面定性

内容是否每次请求都可能不同（价格、库存、个性化推荐）？这个 URL 是否值得被索引？更新频率以分钟计还是以天计。三个答案基本就决定了选择：内容稳定且要收录，用 SSG；内容实时又必须被索引，才考虑 SSR；只服务已登录用户、不需要收录，客户端渲染够用。

| 页面类型 | 建议 | 理由 |
| :--- | :--- | :--- |
| 首页、课程详情、文档、博客 | SSG | 按发布节奏更新，秒开且可预渲染 |
| 列表页首屏（分类、标签） | SSG | 首屏链接必须在 HTML 里才利于发现 |
| 价格/库存实时页 | SSR 或客户端补数据 | 静态值会过期，按可接受的新鲜度取舍 |
| 后台、账户、仪表盘 | CSR | 不需要索引，登录后才可见 |
| 搜索结果、多条件筛选 | 静态壳 + 客户端筛选 | 组合爆炸，不该为每个参数生成静态页 |

## 本仓的硬约束：`output: 'export'` 只允许 SSG

`next.config.mjs` 开了 `output: 'export'`，产物是静态文件，部署在 GitHub Pages 或 Cloudflare Pages 上。这意味着 SSR、ISR、middleware、动态 Route Handler 全都不可用——不是配置问题，而是部署形态决定没有常驻进程。

替代写法是把动态性挪到构建期：动态路由用 `generateStaticParams` 全量展开，并设 `dynamicParams = false`，未生成的参数直接 404，而不是运行时兜底。页面里的 `params` 也已经是 Promise，别再按同步对象访问。

```tsx
export const dynamicParams = false

export function generateStaticParams() {
  return getCourseSlugs().map((slug) => ({ slug }))
}
```

确实需要实时数据时，要承认静态导出不适合：换成带服务端的部署，或把实时部分降级为客户端请求，而不是用 `force-dynamic` 硬撑。

## SSR 的适用面比想象中窄

SSR 只解决一件事：HTML 必须包含请求时刻的数据。适合它的场景通常要同时满足两个条件——数据实时、页面必须被索引；代价是每次请求跑一次渲染，需要常驻服务、缓存层和超时降级。

引入 SSR 常是为了「让爬虫看到内容」，但内容稳定的页面用 SSG 就够。真正需要它的，往往是搜索结果页这类「参数组合多、每个组合都想被索引」的页面，而这时更该先问：这些组合真的有人搜吗？

## 客户端渲染的空壳问题

CSR 页面返回的 HTML 里没有正文。搜索引擎能执行 JavaScript，但要排队渲染，结果既慢又不稳；社交平台抓取器基本不执行 JS，分享卡片会是空的。所以 CSR 只该出现在不需要索引、也不需要分享预览的地方。

若筛选必须在客户端做，就把索引策略写出来：带参数的 URL 保持可访问但不进 sitemap，canonical 指回无参数的列表页，页面上保留一组指向核心分类的静态链接，让爬虫沿内链走到内容页。

## 落地动作

1. 列出站内所有路由，按上面三个问题逐条打分，标出「实时且必须收录」的页面。
2. 对标记出来的页面先确认参数组合是否真有搜索需求；没有就把实时部分改成客户端请求，保留静态首屏。
3. 检查动态路由是否都有 `generateStaticParams` 与 `dynamicParams = false`，跑一次 `next build` 确认产物里没有缺失的 HTML。

## 常见坑

- **现象**：构建报错说路由不能用动态渲染，或上线后 404。→ **原因**：静态导出下写了 SSR 才有的配置，或动态路由没全量生成参数。→ **对策**：把数据获取挪到构建期，补齐 `generateStaticParams` 并设 `dynamicParams = false`，让问题在构建期暴露。
- **现象**：筛选页被收录几千条，内容几乎一样。→ **原因**：参数组合被当成独立页面提交，且没有 canonical 收敛。→ **对策**：带参数 URL 不进 sitemap、canonical 指向无参列表页，只留核心分类的静态入口。
- **现象**：首屏白屏明显，Search Console 显示抓到的 HTML 很小。→ **原因**：正文全靠客户端渲染，HTML 里只有挂载点。→ **对策**：首屏内容改为构建期渲染，客户端只负责交互与增量数据。
