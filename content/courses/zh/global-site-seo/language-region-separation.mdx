多数团队把 `en` 当成英语世界的默认，直到英国用户看到美元价格、看到 `color` 拼写。语言和地区是两个维度，混着写既没有地区体验，也把 hreflang 搞乱了。

## 先判断地区差异是否真实存在

三个问题：价格与税费是否因地区不同；可售商品或服务是否不同；文案的拼写与用词是否不同。三个都是「否」，就只需要语言。任意一个「是」，才值得拆地区。

| 差异 | 是否值得单独建页 | 承载方式 |
| :--- | :--- | :--- |
| 只有拼写差异（color / colour） | 一般不值得 | 同页轻量切换或中性表述 |
| 价格、税、运费不同 | 值得 | 地区目录 + 地区化定价 |
| 可售商品不同（合规限制） | 必须 | 独立页面 + 明确地区声明 |

## URL 只有三种形态，选一种就别混

- `/es/`：只有语言，一页服务所有西语用户。适合差异小、内容少的站。
- `/es-MX/`：语言与地区写在同一个段里。目录清晰，hreflang 直接对应，推荐大多数出海站。
- `/mx/es/`：地区在前。适合以国家为单位组织运营的团队，但对路由与 hreflang 都更绕。

混用最糟：`/es/` 与 `/es-MX/` 内容相同就会互相竞争，hreflang 也说不清主版本。

## 矩阵与 fallback

| 语言 | 地区变体 | 该不该建 | 理由 |
| :--- | :--- | :--- | :--- |
| 英语 | `en` | 建 | 兜底，服务未匹配地区 |
| 英语 | `en-US` / `en-GB` | 分别建 | 定价、含税展示与拼写差异 |
| 西语 | `es` / `es-MX` | 分别建 | 支付方式与运费不同 |
| 中文 | `zh-CN` / `zh-TW` | 分别建 | 用词与支付习惯差异 |

每个「建」都要能回答：这个页面与父级语言页的差异是什么。回答不出来的，合并回父级。

```ts
// lib/locales.ts：地区页缺内容时回退到语言页，避免复制出空页
export const locales = ["en", "en-US", "en-GB", "es", "es-MX"] as const;
export type Locale = (typeof locales)[number];

export const fallbackOf = (locale: Locale): Locale | null =>
  locale.includes("-") ? (locale.split("-")[0] as Locale) : null;

export function pick<T>(dict: Record<string, T>, locale: Locale): T | undefined {
  const fb = fallbackOf(locale);
  return dict[locale] ?? (fb ? dict[fb] : undefined);
}
```

整页复制看着省事，但半年后必然不同步：改一处忘一处，最后连哪份是主版本都说不清。hreflang 上也要体现这层关系：`es-MX` 页列出 `es`、`es-MX` 与 `x-default`。

## 地区差异落在哪几处

拆了地区目录就要有真的差异，否则两页会互相竞争。可落地的差异只有四类：价格与税、可售范围、支付方式、文案用词。前两项决定页面上必须出现什么，后两项决定转化。

| 差异点 | 落地方式 | 检查方法 |
| :--- | :--- | :--- |
| 价格与税 | 结算页按地区取定价表 | 用该地区地址下一单，核对含税总额 |
| 可售范围 | 商品页显示地区可售状态 | 用地区 IP 打开，看是否出现不可售 |
| 支付方式 | 按地区渲染支付列表 | 对照竞品结账页的支付方式 |
| 文案用词 | 词条按 locale 覆盖 | 抽 5 个关键页做母语校对 |

判定标准很简单：把两个地区页并排打开，如果用户看不出区别，这两页就不该存在，合并回父级。

## 落地动作

1. 画出语言-地区矩阵，每格写一句「与父级页面的差异」，写不出来的格子删掉。
2. 定下 URL 形态并写进路由约定，之后新增内容必须遵守，不允许临时加查询参数或开子域。
3. 把 fallback 放进读取内容的函数，并加测试：locale 为 `en-GB` 且缺 key 时必须回退到 `en`。

## 常见坑

- **现象**：`/es/` 与 `/es-MX/` 都被收录，排名忽上忽下。→ **原因**：两页内容几乎相同，hreflang 也没给出主次。→ **对策**：保留一个有独立内容的地区页，另一个 301 或合并。
- **现象**：英国用户看到美元价格。→ **原因**：只做了语言判断，没做地区判断。→ **对策**：地区来自用户选择或结算地址，不靠 `Accept-Language` 推断。
- **现象**：地区页上线后长期不更新。→ **原因**：整页复制，维护成本翻倍。→ **对策**：共用模板，差异参数化，靠 fallback 渲染。
