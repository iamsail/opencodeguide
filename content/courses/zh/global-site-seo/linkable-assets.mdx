外链最难的部分不是发信，是对方打开你的页面后找不到链你的理由。邮件里说产品很棒，收件人打开的却是一个营销首页。

可链接资产解决的就是这个：一个具体页面，里面有一个别人写文章时必须提到的东西——一个能算出答案的工具、一组别处没有的数据、一份能直接下载的模板。

## 三种资产，成本与来源不同

| 类型 | 例子 | 制作成本 | 谁愿意链 | 维护成本 | 适合谁 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 工具 | 计算器、对比器、检查器、生成器 | 中 | 教程作者、行业媒体、社区回答 | 中 | 有明确计算逻辑的产品 |
| 数据 | 自己统计的基准、样本调查、价格监测 | 高 | 媒体、报告、学术与从业者 | 高（要定期更新版本） | 能拿到一手数据的团队 |
| 模板 | 表格、清单、MDX/配置文件、脚本 | 低 | 同行、教程站、社区置顶 | 低 | 任何团队，优先做 |

从模板起步：一周内能做完，能立刻拿到第一批引用，也顺便验证读者关心什么。

## 工具页必须能被静态站点承载

本站是 Next.js 静态导出，没有服务端。工具要么是纯前端计算，要么预生成数据。

把计算逻辑拆成纯函数，页面只负责渲染：

```ts
// lib/seo/calc.ts —— 纯函数，页面只负责渲染
export function estimateMonthsToRank(opts: {
  pages: number;      // 已有可用内容页数
  weekly: number;     // 每周新增篇数
  covered: number;    // 已覆盖的主题数
}) {
  const gap = Math.max(0, 15 - opts.covered);
  const perMonth = Math.max(1, Math.round(opts.weekly * 4));
  return { gap, months: Math.ceil(gap / perMonth) };
}
```

页面要给出三样东西：输入说明、结果解释（不只是数字，要说清这个数意味着什么）、以及「这适用于什么情况 / 不适用于什么情况」。只给数字的工具不会被引用，能被引用的是「数字 + 解释 + 边界」。

## 数据资产的关键是口径，不是图表

任何人做一张图都能画。让数据被引用的，是别人能看到你的方法：样本从哪来、时间范围、纳入口径、排除了什么。页面上固定放一个「方法」小节，写清这四项，再给一句固定的引用格式。

数据必须标版本。发布时写清采集时间，更新时新建版本说明，不要静默改旧数字——引用者链接的是你那个版本。

## 模板资产：越小越好，越具体越好

一个能直接复制走的文件，比一篇教人怎么做的长文更容易被链。可用的模板包括：文章骨架的 MDX 片段、内链矩阵的 CSV、发布前检查清单、Search Console 导出的字段表。放到 `content/` 或 `public/` 下，给独立 URL，页面上同时展示预览和下载。

加三句话：这个模板解决什么问题、字段怎么填、填完怎么用。

## 外链的前提是能被找到

资产做完不等于有人链。至少做四件事：给每个资产独立 URL（不要塞在博客文末）；在相关支撑文里内链过去；页面上放「引用方式」区块，给出可复制的标题 + 链接；把资产加进 sitemap 与站内搜索索引（本站由 `scripts/build-search.mjs` 与 `app/sitemap.ts` 负责，新目录要确认被扫到）。

## 落地动作

1. 用上表给三个候选资产各打一次分（成本、被链意愿、维护成本），只选一个在这个月做完，其余进待办。
2. 把选中的资产做成独立页面，补齐输入说明、结果解释、适用边界与「引用方式」四块。
3. 在现有三篇相关文章里加内链指向它，并记录该页四周内的引荐域名数。

## 常见坑

- **现象**：工具做完了，没人链也没人用。→ **原因**：只解决了一个没人搜的问题，或结果没有解释。→ **对策**：先用关键词工具确认存在搜索需求，再补结果解释与适用边界。
- **现象**：模板页下载量高，外链为零。→ **原因**：文件放在需要登录或跳转的中间页，引用者拿不到稳定 URL。→ **对策**：给直链，页面本身可被搜索收录，下载不设门槛。
- **现象**：数据发了一年就过期，还在被引用。→ **原因**：没有版本号和更新时间。→ **对策**：页面顶部固定显示采集时间与版本，更新时加变更说明，旧版本保留可访问。
