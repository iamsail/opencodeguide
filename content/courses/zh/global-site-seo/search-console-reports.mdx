打开 Search Console 的第一眼，通常是一句「过去 3 个月点击下降 18%」，接下来整周都花在改标题和重写首段上。真正的原因可能只是上个月投了一轮品牌广告。这个工具的默认视图擅长制造焦虑，不擅长解释原因。

## 先固定口径，再看数字

同一个站点，换一种对比方式就能得出相反结论。所以每次打开报表，先固定四件事：日期区间（用完整自然周或自然月，不要拿滚动 28 天窗口做月度对比）、对比对象（优先同比，避开季节性）、拆分维度（设备与国家分开看，移动端和桌面端位置差异很大）、是否包含品牌词（把产品名、域名、创始人名排除后，才是 SEO 真实拿到的流量）。

两个必须先写下来的口径：

- `CTR = 点击 ÷ 曝光`，只在同一查询、同一国家、同一设备下比较才有意义。
- `平均排名 = 该查询全部曝光的排名加权平均`，它不是「你的文章排第几」。一批排名 40 的长尾查询就能把均值从 8 拉到 15，而点击同时在涨。

口径不固定，结论就无法复现。

## 四张报表，一周看一次就够

| 报表 | 必看维度 | 关键口径 | 对应动作 |
| :--- | :--- | :--- | :--- |
| 效果（Performance） | 查询、页面、国家、设备 | 非品牌点击量、`CTR` | 挑出曝光高但 `CTR` 低于自身同位置均值的页面，改标题与摘要 |
| 页面索引 | 「未编入索引」的原因分组 | `未编入数 ÷ 已提交 URL 数` | 先修「已抓取但未编入」与 5xx、重定向链 |
| 站点地图 | 提交数与已发现 URL 数 | 提交数 = 可收录路由数 | 静态导出新增路由后，同步 sitemap 与 hreflang |
| 体验与增强 | Core Web Vitals、结构化数据 | 按 URL 组看，不看站点均值 | 问题集中在客户端渲染的组件，优先拆掉首屏 JS |

其余报表（链接、移动易用性、抓取统计）按月抽查即可。把四张表固定成顺序过一遍，比随机点开更能发现问题。

## 三类波动，三种不同的解释

**平均排名掉了不等于被降权。** 新增内容带来一批排名靠后的查询，均值必然下滑。判断要看「排名进前 10 的查询数」这个绝对量，它涨了就是业务在变好。

**曝光涨、点击没涨不等于被惩罚。** 常见情形是从第 8 名掉到第 12 名：曝光池变大了，位置却不在首屏，点击率自然被稀释。去查具体查询的排名分布，而不是猜算法。

**「已发现但未编入索引」不等于内容差。** 静态导出站点的典型原因是 sitemap 里混入了不该收录的路由（感谢页、分页参数、重复的 hreflang 变体），或者新页面没有任何内链指向，爬虫缺少再来的理由。

## 落地动作

1. 在效果报表里建一个筛选视图：排除品牌词、固定「自然月 + 同比」，加书签，以后只看它。
2. 导出「页面 × 点击 × 曝光 × CTR」，按曝光排序，取前 20 个页面核对搜索结果页里的实际位置，标出真正能改的 5 个。
3. 把四张报表的检查顺序写进周报模板，每次只填「变了什么、为什么、下周改哪一处」。

## 常见坑

- **现象**：每周都看到点击下降，改完标题过两周又涨回来。→ **原因**：用滚动 28 天窗口对比，周末与工作日比例一变曲线就抖。→ **对策**：改成自然月同比，并排除品牌词后重看趋势。
- **现象**：一篇文章曝光几十万、点击只有几百，以为标题没写好。→ **原因**：曝光来自相关搜索与图片结果，位置在第二页边缘，点击率本来就低。→ **对策**：先看该查询的排名分布，10 名以外的不要花时间改标题。
- **现象**：站点地图显示成功，索引里却一直不进新页面。→ **原因**：`output: 'export'` 后新增的目录没加进 sitemap 生成脚本，或路径大小写不一致。→ **对策**：以 sitemap 的 URL 列表逐条 `curl` 验证 200 与 canonical，再提交重新抓取。
