前面几节把 URL 结构与 hreflang 定下来了，这一节看路由怎么落地：在 `output: 'export'` 下让每种语言都有自己的静态页面、自己的 `<html lang>`、自己的 canonical 与 alternates，并且能在 GitHub Pages 加 Cloudflare 上跑通。

## route group 管「哪套壳」，语言段管「哪个语言」

本仓库的目录是每个语言一套路由与布局：

```text
app/
├─ (zh)/                  ← route group，不出现在 URL 里
│  ├─ layout.tsx          ← <html lang="zh">
│  └─ zh/docs/page.tsx    → /zh/docs/
├─ (main)/                ← 英文主站
│  ├─ layout.tsx          ← <html lang="en">
│  ├─ page.tsx            → /
│  └─ en/docs/page.tsx    → /en/docs/
```

圆括号目录不参与 URL，所以 `app/(zh)/zh/docs/page.tsx` 生成 `/zh/docs/`。好处是每个语言可以有独立的 header 文案、字体与导航，不必在每个组件里判断 locale。

| 源文件 | 生成的地址 |
| :--- | :--- |
| `app/(zh)/zh/docs/page.tsx` | `/zh/docs/` |
| `app/(main)/en/docs/page.tsx` | `/en/docs/` |
| `app/(main)/page.tsx` | `/` |

为什么不用单一 `app/[lang]/`：动态段要求 `generateStaticParams` 列出全部语言，新增语言时若忘加，构建会静默少生成一套页面；显式路由在 `git diff` 里一眼能看到多了哪个语言。语言数 ≤ 3 时显式路由更省心，要上十来个语言再考虑 `[lang]`。

## 静态导出必须显式声明参数

静态导出没有服务端兜底：所有动态段都要被 `generateStaticParams` 覆盖，并关掉未声明的参数：

```ts
// app/(zh)/zh/courses/[slug]/page.tsx
export const dynamicParams = false;

export function generateStaticParams() {
  return getCourseSlugs().map((slug) => ({ slug }));
}
```

`dynamicParams = false` 让未列出的 slug 直接 404，而不是在构建期尝试渲染然后失败。Next 16 里 `params` 是 Promise，页面组件与 `generateMetadata` 里都要 `await`，不 await 拿到的是 Promise，字段全是 undefined。

## metadata：canonical 自指，alternates 列全

```ts
// app/(zh)/zh/docs/page.tsx
import type { Metadata } from "next";

export const metadata: Metadata = {
  alternates: {
    canonical: "/zh/docs",
    languages: {
      "zh-CN": "/zh/docs",
      en: "/en/docs",
      "x-default": "/en/docs",
    },
  },
};
```

在 `app/(zh)/layout.tsx` 或 `app/(main)/layout.tsx` 里配一次 `metadataBase: new URL("https://example.com")`，之后写路径会被展开成绝对地址。canonical 一定要在页面层自指，只在根布局写一次会让所有页面都指向同一个地址。

## 语言切换器要保留当前路径

切换语言时丢掉路径是转化杀手：用户在 `/zh/docs/install` 点 English，被送回首页。做法是替换语言段、保留其余路径：

```ts
// components/lang-switch.tsx
"use client";
import { usePathname } from "next/navigation";

const swap = (pathname: string, to: "zh" | "en") =>
  pathname.replace(/^\/(zh|en)(?=\/|$)/, `/${to}`);

export function LangSwitch() {
  const pathname = usePathname();
  return <a href={swap(pathname, "en")}>English</a>;
}
```

静态导出下 `usePathname` 在预渲染时给出当前路由，水合后随导航更新，用它算链接目标即可，不要在点击里用 `router.push` 临时判断。

## 部署到 GitHub Pages 与构建验证

三个坑要提前处理：`trailingSlash: true` 已开启时产物是 `out/zh/docs/index.html`，与静态托管的目录索引一致；站点若部署在 `user.github.io/repo/` 子路径，必须设 `basePath`（通常连带 `assetPrefix`），否则 `/_next/` 资源 404；GitHub Pages 只认根目录的 `404.html`，未收录路径要落到有用的 404。

```bash
npx next build
for p in out/zh/docs/index.html out/en/docs/index.html; do
  echo "== $p"
  grep -o '<html[^>]*>' "$p"
  grep -o '<link rel="alternate"[^>]*>' "$p"
done
```

检查三条：两个文件都存在；各自的 alternate 列表里有指向自己那一行；`html` 标签的 `lang` 与目录一致。

## 落地动作

1. 新增语言时复制 `(zh)` 这套目录，改 layout 的 `lang`、导航文案与路径段，补上 `generateStaticParams`。
2. 把 `alternates` 抽成 `lib/` 里的一个函数，参数只有 `locale` 与 `path`，禁止每页手写。
3. 每次 `next build` 后跑上面的 grep 检查，把「每个语言都有 index.html 且自指」作为上线门槛。

## 常见坑

- **现象**：新语言页面 404，本地 `next dev` 却正常。→ **原因**：缺少 `generateStaticParams` 覆盖，或 `dynamicParams` 仍是默认值。→ **对策**：补全参数生成，设 `dynamicParams = false`，构建后检查 `out/` 有没有对应目录。
- **现象**：部署到 GitHub Pages 后样式全丢。→ **原因**：站点在子路径下运行，`basePath` 未设置，`/_next/` 资源 404。→ **对策**：设 `basePath` 与 `assetPrefix`，或改为绑定自定义域名。
- **现象**：中英文页面的 canonical 都指向英文。→ **原因**：`alternates` 写死在根布局，页面层没有覆盖。→ **对策**：canonical 在页面层自指，根布局只放 `metadataBase`。
