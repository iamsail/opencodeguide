看到竞品排了什么词，然后照着写——结果每一页都在和已经排第一的页面正面竞争。反查的价值不在词表，在结构：他们用什么页面承接哪类需求，哪些需求只被提了一句，哪里留了空。

## 先把对手的站点结构拉下来

```bash
# 拉 sitemap，按一级目录分组，看对手的内容类型与页面数
curl -s https://competitor.com/sitemap.xml \
  | grep -o '<loc>[^<]*</loc>' | sed 's/<[^>]*>//g' > urls.txt
awk -F/ '{print $4}' urls.txt | sort | uniq -c | sort -rn | head -20
```

这条命令回答的是：对手把内容分成几类、哪一类最多。多数站点会露出清晰模式：`/blog/`、`/compare/`、`/docs/`。目录结构本身就是他们的关键词策略。

## 四层拆解，从粗到细

| 层 | 看什么 | 产物 |
| :--- | :--- | :--- |
| 信息架构 | 一级目录、每类页面数、导航入口 | 对手内容类型表 |
| 词覆盖 | 哪些意图有专属页，哪些只被提一句 | 缺口清单 |
| 内链密度 | 每页被几个页面链到 | 可超越的弱页名单 |
| 内容深度 | 有无表格、截图、实测数据 | 改写空间评估 |

只有第四层需要读全文，前三层配一次页面抓取就能做完。

## 三类缺口，优先做第二类

他们没写的词通常是新场景词、地区变体、新集成对象，查法是拿你的词表减去他们的 URL 覆盖。他们写得很浅的词最值得做——有页但只有几百字、没数据、没截图、更新在两年前，需求已被验证而供给不足。他们内链很弱的页可以靠更强的内链挤下去：页面存在但只被首页链过一次。

## 把反查结果变成执行表

| 词 | 对手承接页 | 对手页弱点 | 我要做的页面 | 可内链的站内页 |
| :--- | :--- | :--- | :--- | :--- |
| `best X for Y` | `/blog/best-x` | 无价格、无截图，2023 年更新 | 对比表 + 实测截图 | 定价页、场景页 |
| `X alternative` | `/alternatives` | 只列 3 个，无迁移步骤 | 5 个替代 + 迁移清单 | 文档迁移页 |
| `X for small team` | 无 | 完全未覆盖 | 场景页 | 首页、定价页 |

硬规则：每行都必须写出「可内链的站内页」，写不出来说明还没有承接能力。

## 缺口还是陷阱：先用 Wayback 验一次

他们删掉的页面往往是最贵的教训。把 URL 丢进 Wayback Machine，看它在时间轴上活了多久：

- 存在不到 3 个月就删：多半是上线后发现没转化，别做。
- 存在一年以上、后来被合并：可能是内容迁移，值得做。
- 从来没存在过：真缺口，但先确认需求是否真的存在。

再补一步：把对手某个目录的页面数与这批页面被首页链到的数量对比。页面多、内链少，说明那批页是批量生成的，质量普遍偏低，是最容易超越的区间。

```bash
# 对手 /compare/ 目录下有多少页，其中多少被首页链到
curl -s https://competitor.com/sitemap.xml | grep -c '/compare/'
curl -s https://competitor.com/ | grep -o 'href="[^"]*"' | grep -c '/compare/'
```

## 落地动作

1. 选 3 个对手，各跑一次分组命令，把一级目录与页面数记进同一张表。
2. 用你的词表减掉他们的 URL 覆盖得到未覆盖词；再抽查 10 个他们有页的词，标出「浅」在哪。
3. 填执行表，每行写出对手弱点与你的内链来源，连同「必须有的截图与数据」一起交给写作者。

## 常见坑

- **现象**：照着对手目录抄了一遍，排名始终在后面。→ **原因**：只抄了结构，没补上他们的数据与引用来源。→ **对策**：结构可以抄，内容必须加入他们没有的东西。
- **现象**：做了很多「对手没写」的词，全都没有流量。→ **原因**：对手没写可能意味着这个词没有商业价值。→ **对策**：未覆盖词先过一遍意图筛。
- **现象**：反查做了三份报告，没有一页上线。→ **原因**：报告停在分析层。→ **对策**：每份反查必须产出带 URL 的执行表，否则不算完成。
