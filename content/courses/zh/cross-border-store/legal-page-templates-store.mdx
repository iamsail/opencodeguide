从竞品站点复制四页政策，是最贵的省事方式：管辖法律写着别人所在的州，退款条款和首页的「无理由退」互相打脸，配送政策对关税只字未提——而纠纷时，平台与支付方要看的正是这几页。模板只解决「有没有」，解决不了「对不对得上」。

下面讲写什么、怎么核对，不构成法律意见；涉及跨境销售与个人数据，最终以主体所在地与目标市场的要求为准。

## 四页各回答一个问题

| 页面 | 读者 | 必须回答 | 最常缺的一段 |
| :--- | :--- | :--- | :--- |
| 服务条款 | 用户、支付风控 | 提供什么、不承诺什么、何时可终止 | 责任限制与争议处理 |
| 隐私政策 | 用户、监管 | 收什么、给谁、留多久、怎么删 | 处理者清单与跨境传输 |
| 退款政策 | 犹豫的买家 | 条件、入口、到账、例外 | 与销售页文案不一致 |
| 配送政策 | 买家、支付风控 | 时效、运费、关税、丢件、清关失败 | 进口税费由谁承担 |

最容易出事的是退款与配送这两页，因为它们直接关联钱和承诺。隐私政策是「事实陈述」，写错是错；服务条款用于划边界，写得越具体，被自己的承诺绑得越紧——这恰恰是它有用的原因。

## 配送政策是跨境独有的雷区

本地电商的配送政策可以只写时效，跨境不行。你必须回答四个问题：运费谁出、进口税费谁付、清关失败怎么算、多久没到算丢件。

关税有两种常见安排，必须在页面上写死一种：

- 完税交付：把预估税费打进售价，买家收货不再付款。转化好，但你承担税费估算误差。
- 未完税交付：买家在收货时缴税。售价低，拒收与拒付率上升。

这不是话术问题，是定价问题。选未完税交付却不在页面上说明，等于把纠纷留给客服。

丢件与清关失败要写清责任分界：承运商签收前的丢失、清关资料不全退回、买家拒付税费退运。三种情形退不退运费、退不退货款必须给出不同答案，否则客服每次现编。

## 退款政策要和管理动作对齐

退款政策不是孤立文档，它必须和四处对齐：销售页文案、结账页说明、收据邮件、支付后台的退款设置。任何一处不同，用户都会拿对自己有利的那份主张。

写作用固定四段：可退条件、申请方式、到账时间、不退或部分退的情形。值必须与实际执行能力一致——承诺一个客服跑不完的到账时效，就是在制造投诉。

## 用结构化配置生成页面

把变动最频繁的内容放进配置文件，页面从它渲染，避免「改了页面忘了改条款」：

```yaml
# content/legal/shipping.yaml —— 配送政策页与结账页说明都从这里读
markets:
  - region: "欧盟"
    fulfillment: "本地仓"
    handling_days: "1-2"
    transit_days: "3-5"
    duty: "DDP"          # 税费已含在售价内
    returns: "本地退货地址"
  - region: "美国"
    fulfillment: "跨境直邮"
    handling_days: "2-3"
    transit_days: "7-15"
    duty: "DDU"          # 进口税费由收件人承担
    returns: "退回中国，运费由买家承担"
lost_parcel:
  before_delivery: "卖家补发或退款"
  stalled_days: 10        # 超过承运商理赔窗口即启动调查
  customs_failure: "按退运处理，扣除已发生的往返运费"
refund:
  window_days: 30         # 必须与销售页、收据邮件一致
  method: "原路退回"
  excludes: ["已拆封的化妆品", "定制商品"]
```

这些值是示例占位，实际填什么由你的成本与能力决定。真正的收益是：页面、结账说明、客服话术都引用同一个文件，改一处就全局生效。

## 一致性检查与最小版本

四页能打开只是起点。用一条命令检查关键词是否在多处出现同一说法，把不一致的地方揪出来：

```bash
# 退款窗口、关税口径、配送时效必须在页面与政策里同源
grep -rn "window_days\|duty:\|transit_days" content/legal/ content/store/ \
  | grep -v node_modules

# 四页是否都被站内链接到（漏挂页脚等于没有）
for p in terms privacy refund-policy shipping-policy; do
  grep -rq "/$p" content/ || echo "MISSING link: /$p"
done
```

最小版本是：四页各一屏、只说真话、互相链接、挂在页脚与结账页。订单还是个位数时不需要律师定制，也不需要政策生成器——需要的是这四页和实际做法一致。

## 落地动作

1. 先写配送政策：把关税口径与丢件责任分界定下来，这两个决定影响定价。
2. 用四段结构写退款政策，窗口与到账时间填成你能执行的值。
3. 把四页的变动内容抽进 `content/legal/` 下的配置文件，页面改为渲染。
4. 跑一次上面的 grep，把不一致处改到只剩一处来源。
5. 在结账页与感谢页各放一次退款与配送链接，不只放页脚。

## 常见坑

- **现象**：买家收到税单后拒收，投诉「页面没说」→ **原因**：未完税交付却未在配送政策与结账页写明 → **对策**：关税口径写进配置，并在结账页显示一次提示。
- **现象**：首页写可退，条款写不退，争议判给买家 → **原因**：政策从模板复制，未与销售页对齐 → **对策**：退款规则单一来源，页面、条款、邮件都从它生成。
- **现象**：政策页能打开，纠纷时却找不到入口 → **原因**：只挂了页脚 → **对策**：结账页、感谢页、收据邮件各放一次链接。
