季度复盘最常见的形态，是十几页截图加一句「继续优化」。开完会没人知道下个季度该做什么，也没人知道哪些事要停。复盘不是汇报，它只回答三个问题：赚没赚、钱花在哪、下一步做什么——而且要给出可以否决的结论。

## 先定口径，再填数字

口径必须在季度初定好，季度末改口径等于重新发明历史。四个固定项：成交以 Stripe 支付成功为准，退款按实际退款月份计，广告费按账户实际花费，履约按物流账单。

```json
{
  "quarter": "YYYY-Qn",
  "currency": "USD",
  "revenue": { "gross": 0, "refunds": 0, "net": 0, "orders": 0, "aov": 0 },
  "cost": { "cogs": 0, "fulfillment": 0, "paymentFees": 0, "ads": 0, "tools": 0 },
  "margin": { "grossProfit": 0, "grossMarginRate": 0, "contributionAfterAds": 0 },
  "acquisition": { "newCustomers": 0, "cac": 0, "cacMax": 0, "paybackMonths": 0 },
  "channels": [{ "name": "", "spend": 0, "orders": 0, "cac": 0, "share": 0 }],
  "retention": { "repeatRate": 0, "cohortLtv": 0 },
  "decisions": { "expand": "", "stop": "", "nextThree": [] }
}
```

填不满的字段标「未知」，未知超过三成，说明这个季度的结论只能当参考，先补数据再决策。

## 三道闸门决定能不能扩张

扩张（加预算、开新市场、加 SKU）要同时过三道闸门，缺一道就是赌：

1. **毛利闸门**：`真实毛利 = 净收入 − 商品 − 履约 − 支付费 − 退款损失 − 广告 > 0`，且连续两个月为正。
2. **可复现闸门**：`CAC < CAC_max` 且能说清它为什么低——是素材、是渠道、还是短期红利。说不清就不能放大。
3. **承载闸门**：履约时效、客服响应、库存周转在扩张后仍能维持。旺季前扩市场，最容易在这里翻车。

三道全过，扩张的幅度也要有上限：单次不超过现有规模的固定比例，让一次失败不至于伤到现金。

## 决策树：三种结论，各自的动作

| 结论 | 判定 | 下季度动作 |
| :--- | :--- | :--- |
| 加投放 | 三闸门全过，回收期短于现金流可撑月数 | 按比例加预算，同步加素材产能 |
| 换市场 | 毛利为正但 CAC 触顶，且瓶颈是本地支付或物流 | 先做一个市场的最小验证，不铺开 |
| 收手或收缩 | 毛利为负且两项以上指标连续两季恶化 | 砍 SKU 与渠道，保留现金流 |

「换市场」不是「多开几个国家」，而是把当前市场的瓶颈换掉：支付方式缺就补支付，尾程贵就换履约方式。开新市场前先确认现有市场已经稳定，否则只是把问题复制一遍。

## 复盘会怎么开

三十分钟，三段：十分钟看数字（只讲偏差超过预期的三项），十分钟讲一个失败案例（讲原因不讲情绪），十分钟定结论（三件必做事、一个停止项、负责人与截止日）。

停止项必须有。只列要做的事，团队会不断增加项目，最后每件都做不完。

## 落地动作

1. 用上面的 JSON 结构建一份季度文件，把上个季度的数字填进去，未知字段列成清单并指定数据源。
2. 按三道闸门逐条判定，写下「过 / 不过」和依据；任何一条不过，就在结论里写明不扩张的理由。
3. 把结论拆成三件必做事加一个停止项，写进下季度第一周的日历，并指定负责人。

## 常见坑

- **现象**：每季度都复盘，结论永远是「继续优化」。→ **原因**：没有闸门与判定标准，数字只是被展示，没有被用来否决。→ **对策**：用三道闸门做二元判定，结论必须包含一个停止项。
- **现象**：上个季度看着赚钱，这个季度发现是压货换来的。→ **原因**：只按成交口径算收入，库存与退款滞后没有计入。→ **对策**：退款按实际发生月份计，把库存周转放进承载闸门。
- **现象**：扩了一个新市场，两个市场一起变差。→ **原因**：现有市场的瓶颈没解决就复制，团队精力被摊薄。→ **对策**：先解决瓶颈再扩张，新市场只做最小验证。
