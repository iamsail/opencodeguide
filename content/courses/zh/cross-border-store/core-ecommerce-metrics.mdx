后台仪表盘上有一排数字：成交额在涨、订单在涨、转化率在涨，银行账户里的钱却没涨。原因几乎总是同一个——看的是平台口径的「收入」，不是扣完退款、履约、支付费和广告之后的真实毛利。指标不是并列展示的仪表，它们有先后顺序，先算错的会一路错下去。

## 五个指标有先后

| 指标 | 定义 | 分母 | 最常见口径错误 |
| :--- | :--- | :--- | :--- |
| AOV | 成交额 ÷ 订单数 | 订单数 | 把运费与税算进成交额 |
| 退款率 | 退款订单 ÷ 成交订单 | 成交订单 | 只算全额退款，漏掉部分退 |
| 真实毛利 | 收入减全部变动成本 | 按订单或按批 | 漏掉广告与支付费 |
| CAC | 广告花费 ÷ 新客订单数 | 新客订单 | 用全部订单当分母 |
| LTV | 一个客群终身贡献的毛利 | 按队列 | 用平均值代替留存曲线 |

顺序是：先确认真实毛利为正，再算 CAC 是否低于可承受上限，最后才用 LTV 判断能花多少钱买客。毛利为负时谈 LTV，只是把亏损推迟到未来。

## 真实毛利：五项必须扣干净

`真实毛利 = 成交额 − 商品成本 − 履约成本 − 支付手续费 − 退款损失 − 广告费`

每一项都要能被账单验证：商品与头程来自采购单，履约来自物流账单，支付手续费来自 Stripe 的费率结算记录，退款损失要乘上「不可回收比例」（退回的货不一定能二次销售），广告费来自账户实际花费而不是平台估算的转化价值。

一个可用的中间量是「不含广告的毛利率」，它决定你最多能花多少钱获客：

`CAC_max = 客单价 × 不含广告毛利率 − 单件履约与退货损耗`

## CAC 的分母必须是新客

用全部订单当分母会把复购算成获客效率，CAC 被系统性低估。做法是给每个订单打「首单 / 复购」标记，首单的判定按邮箱或 Stripe 客户 id 去重。

不同渠道的 CAC 差异极大，混在一起算只能得到一个没有决策价值的平均数。至少按渠道分开，并且剔除品牌词与直接访问——那部分流量的成本接近零，会掩盖付费渠道的真实效率。

## LTV 用队列，不用平均值

`LTV = 客单价 × 毛利率 × 累计复购次数`

平均值的问题在于它把不同批次客群混在一起。按首次购买月份建队列，逐月看留存与累计贡献：

`队列 LTV(t) = 队列累计毛利 ÷ 队列首单客户数`

再算回收期：`CAC 回收期 = CAC ÷ 每月人均毛利贡献`。回收期长于你的现金流能撑的月数，即使 LTV 很好看也不能加预算。

## 用一段 SQL 把口径固定下来

```sql
-- 月度队列口径：首单月份为队列，只统计已支付且未退款的订单
with first_order as (
  select customer_email, min(date_trunc('month', paid_at)) as cohort_month
  from orders where status = 'paid'
  group by 1
), joined as (
  select o.customer_email, f.cohort_month,
         date_trunc('month', o.paid_at) as order_month,
         o.amount_cents - o.refunded_cents as net_cents,
         o.unit_cost_cents + o.shipping_cents + o.payment_fee_cents as var_cost_cents
  from orders o join first_order f using (customer_email)
  where o.status in ('paid', 'partially_refunded')
)
select cohort_month, order_month,
       count(distinct customer_email) as buyers,
       sum(net_cents - var_cost_cents) / 100.0 as gross_profit
from joined group by 1, 2 order by 1, 2;
```

口径固定之后，任何一个月的数据都能和上月对比；改口径必须先改这段 SQL，而不是在表格里手工调整。

## 落地动作

1. 用真实毛利公式把最近三个月的数字重算一遍，缺的项标「未知」而不是估，未知项超过两项就先补数据源。
2. 在订单表里加「首单标记」与「退款金额」两个字段，重算 CAC 与退款率，与仪表盘对比差异。
3. 按首次购买月份建三个月队列，算出 LTV 与 CAC 回收期，写进投放的预算上限说明里。

## 常见坑

- **现象**：成交额每月新高，利润为零。→ **原因**：把平台口径的收入当利润，退款、履约与广告没扣。→ **对策**：用真实毛利公式重算，把广告当变动成本而不是固定开支。
- **现象**：CAC 看着很低，加预算后立刻亏。→ **原因**：分母混入了复购与品牌词订单，付费渠道的真实成本被稀释。→ **对策**：按首单与新渠道口径重算，分渠道设上限。
- **现象**：LTV 算出来是客单价的好几倍，实际复购很少。→ **原因**：用了平均值或把未发生的复购按年化推算。→ **对策**：改队列法，只算已发生的累计毛利。
