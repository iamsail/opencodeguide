每周憋一条视频，投出去没有量；或者一条素材硬投五个市场，前两秒就被划走。卡点通常不在设备和演技，而在于你把「脚本」当成灵感，而不是当成可以拆开、替换、复用的参数。

## 脚本是五段结构，不是灵感

一条能投的视频可以拆成五个位置：钩子、问题、演示、证据、行动。钩子占开头最短的一段，任务是让人停止滑动；问题承接钩子，用一句话描述买家的处境；演示是产品在动，这是唯一必须实拍的段落；证据给它一个可核对的东西，材质特写、使用结果、买家原话都行；行动只留一个动作，别同时要求关注、下单、领券。

比例按视频总长的相对份额控制，不要在脚本里写死秒数。每条视频只讲一个卖点，讲两个就等于两个都没讲。

## 一个卖点拍 N 条：控制变量

真正的产能来自矩阵，不是创意。同一段演示画面，配三个不同的钩子，就是三条可独立投放的素材，成本只是重录开头。同理，同一段钩子可以配不同的演示顺序。

三个维度足够起步：钩子（提问、反常识、痛点直述）、开场画面（产品特写、使用场景、包装开箱）、结论（价格、配件、售后）。每次只动一个维度，否则投放数据无法归因。

## 批量剪辑流水线

目录即约定，文件名即素材 ID：`raw/<sku>/<shot>.mov`、`subs/<lang>.srt`、`out/<sku>/`。剪辑不靠手工拖时间线，靠脚本重复执行：

```bash
#!/usr/bin/env bash
# 用法: ./build.sh SKU LANG
set -euo pipefail
SKU="${1:?usage: build.sh SKU LANG}"
LANG_CODE="${2:?usage: build.sh SKU LANG}"
mkdir -p "out/$SKU"

for f in raw/"$SKU"/*.mov; do
  base="$(basename "$f" .mov)"
  ffmpeg -y -i "$f" \
    -vf "scale=1080:1920:force_original_aspect_ratio=increase,\
crop=1080:1920,subtitles=subs/$LANG_CODE.srt:force_style='FontSize=16'" \
    -c:v libx264 -crf 20 -preset veryfast \
    -c:a aac -b:a 128k \
    "out/$SKU/${base}_${LANG_CODE}.mp4"
  echo "built ${base}_${LANG_CODE}.mp4"
done
```

这段脚本做三件事：统一画幅（原比例不同的源素材先放大再居中裁切）、把字幕烧进画面（多数投放场景下比外挂字幕可靠）、用体积可控的编码参数批量出片。整套流程可以在本机跑完，不需要剪辑软件与授权。

## 字幕优先于配音

机翻配音的语调会在前两秒暴露「这不是本地内容」，而字幕只承担信息。更省的做法是保留原声、加目标语言字幕，再让同一个人重录开头一两句，成本低且能一稿多市场。字幕按意群断行，一行只放一个短句，让它在静音浏览时也能读。

## 最小可行版本

一条素材、三个钩子、一个市场。先测钩子，钩子能留住人，再回头优化演示与证据；钩子留不住，后面拍得再好也没人看到。

什么时候不做短视频：客单价低、决策靠比价、商品视觉差异小的品类，视频的边际成本高于图片与详情页，此时把预算放到商品页与评论区更划算。

## 落地动作

1. 选一个卖点，按五段结构写一版脚本，每段只写一句话，念一遍计时。
2. 只重录开头，做出三个钩子版本，其余画面全部复用。
3. 把源素材按 `raw/<sku>/<shot>.mov` 归档，跑一遍上面的脚本，导出竖版与目标语言字幕，文件名带 SKU、钩子编号与语言。

## 常见坑

- **现象**：同一条视频投多语言，某个市场的完播明显更差。 → **原因**：钩子里的文化梗、计量单位与场景不通用。 → **对策**：钩子按市场重写，正片复用，字幕单独校对。
- **现象**：批量导出后字幕被裁掉一半。 → **原因**：源素材画幅与目标画幅不一致，居中裁切切掉了边缘。 → **对策**：拍摄时留安全区，字幕烧在安全区内，导出后抽查首尾两帧。
- **现象**：素材越拍越多，却说不清哪条有效。 → **原因**：没有命名规范，投放后台的素材名和文件名对不上。 → **对策**：文件名即素材 ID，后台素材名与之一一对应，复盘时按 ID 汇总。
