换了按钮颜色，跑了三天，宣布「测试成功」——这是小团队最常见的 A/B 现场。样本不够、变量没隔离、指标随手换，这种结论比纯靠直觉更危险，因为它看起来有数据支撑，还会被写进复盘继续误导后面几个月的投放。

## 先定一个主指标，再谈改什么

主指标只选一个，选离钱最近且你能稳定统计的那个：落地页看下单转化率，素材看点击后的加购率。分母必须写死，是按访问算还是按加购算，一句话定下来，中途不改。

同时设护栏指标：退款率、客单价、客服工单量。主指标涨而护栏崩，这一次不算赢——靠误导性素材换来的转化，退款会把它连本带利收回去。

## 一次只改一个变量，但层级要选对

变量有三个层级：素材层（钩子、开场画面）、首屏层（主张、标题、主图）、报价层（价格、运费、赠品）。层级越高，影响越大、所需样本越少，但改动风险也越大，因为报价动的是利润结构。

同时改两层，赢了也说不清赢在哪，下一次无法复用。想快，就串行：先测首屏，再测素材。

## 流量不够就不要做 A/B

先算最小可检测效应：把你想捕捉的相对提升乘以当前基线转化率，得到绝对差值。样本量近似为十六乘基线乘补数，再除以差值的平方（双侧置信与统计功效取常用默认值）。这个估算不追求精确，它的用途是告诉你「够不够」，而不是「跑几天」。

```python
def sample_per_arm(p0: float, rel_lift: float, z_a: float = 1.96, z_b: float = 0.84) -> int:
    """每个变体所需样本量的近似值：双侧 95% 置信、80% power。"""
    p1 = p0 * (1 + rel_lift)
    p_bar = (p0 + p1) / 2
    delta = abs(p1 - p0)
    if delta == 0:
        return 0
    return int(
        (z_a * (2 * p_bar * (1 - p_bar)) ** 0.5
         + z_b * (p0 * (1 - p0) + p1 * (1 - p1)) ** 0.5) ** 2 / delta ** 2
    )

# 若两倍结果大于你一周的访问量，这个实验在你当前阶段做不出来
```

算出来做不出来时，有三条替代路径：做前后对比（同一素材换周比较，承认它有季节与投放干扰）、做定性（找真实用户看首屏，复述他理解到的主张）、只做「明显更差」的排除而不做「微小提升」的确认。

## 实验表与停手规则

| 字段 | 写什么 |
| :--- | :--- |
| hypothesis | 改什么、影响哪个指标、为什么 |
| variant | 唯一变量，其余全部冻结 |
| primary_metric | 一个主指标，含分母定义 |
| guardrails | 退款率、客单价、工单量 |
| sample_planned | 上面代码算出的每变体样本 |
| decision_rule | 达到什么就全量、回滚或继续 |
| stop_condition | 时间上限与样本上限，先到者为准 |

停手规则必须在开跑前写死。中途反复查看数据、看到领先就停，是假阳性的主要来源；真实实验跑到一半往回摆是常态。

## 最小可行版本

一周一个实验，只测首屏的一句话主张。它潜在影响最大、改起来最便宜、失败也不伤利润结构。

什么时候不做 A/B：日均订单还是个位数时，任何分流都读不出信号，这个阶段的正确动作是客服访谈、看竞品的页面结构、把退货理由归类，而不是做统计。

## 落地动作

1. 写下本周唯一假设，格式固定：把首屏从 A 改成 B，主指标会上升，因为某类买家担心的是……
2. 用上面的代码算每变体样本量，与你一周的访问量对比；不够就换更大的变量，或直接改做定性。
3. 建一张实验表，字段照上表，每个实验一行，包括失败的——失败记录决定下一轮测什么。

## 常见坑

- **现象**：实验判定赢了，全量上线后回到原样。 → **原因**：实验期叠加了促销、换季或投放预算变化。 → **对策**：冻结其他变量，并在实验表里记下同期外部变化。
- **现象**：连测三个变体都「没有显著差异」。 → **原因**：改动幅度小于样本能分辨的最小效应，比如只换了按钮颜色。 → **对策**：先算最小可检测效应，落在噪声里的变量不值得测。
- **现象**：实验一直不结束。 → **原因**：只设了时间没设样本，或只有一个上限。 → **对策**：时间与样本双上限，先到为准，到点按预设规则决策，不再追加。
