开户第一周最容易做的事，是把预算摊到十几个广告组，每组每天几美元，三天后每组几十个点击、零个订单，于是得出「这个品不行」。其实什么都没测出来：样本小到连一次转化都撑不住，系统也一直停在学不会的状态。冷启动不是花钱买量，是花最少的钱买到一次可信的判断。

## 冷启动只回答一个问题

「这个品、这个市场、这套素材，能不能以低于上限的成本拿到订单。」先把上限写成式子：

`CAC_max = 客单价 × 毛利率（不含广告） − 单件履约与退货损耗`

`测试预算 = CAC_max × 需要观察的订单数`

第二个式子里唯一需要判断的是「需要观察的订单数」：它取决于你的转化波动，波动越大就要越多，让一两单的运气不足以改变结论。预算撑不住这个数，说明你还不该投这个市场，应该先提客单价或压履约成本。

## 三个平台的结构差异，差在学习单元

| 维度 | Meta | Google | TikTok |
| :--- | :--- | :--- | :--- |
| 学习单元 | 广告组（受众与版位） | 关键词意图或素材组 | 素材本身 |
| 预算该压在哪 | 少数广告组集中花 | 搜索按意图分层，素材组独立跑 | 每条素材单独拿量 |
| 冷启动期素材量 | 少而稳，够覆盖卖点即可 | 覆盖购买意图，不要贪长尾 | 消耗快，需要持续补 |
| 最常犯的错 | 一个组里混多个受众 | 关键词太宽，匹配到没有购买意图的词 | 只上一条，三天后说没量 |

三者的共同点是：系统都需要在单位时间内拿到足够转化才「学会」，但阈值随市场、账户历史与优化目标变化。这个阈值写在各自帮助中心的「学习期 / Learning phase」文档里，按账户当前的市场版本查，别拿旧截图当规则。查询路径统一：广告后台 → 帮助中心 → 搜「学习期」。

## 最小结构与预算配置

```json
{
  "account": "m7-cold-start",
  "currency": "USD",
  "unitEcon": { "aov": 0, "grossMarginRate": 0, "fulfillmentLoss": 0 },
  "derived": {
    "cacMax": "aov * grossMarginRate - fulfillmentLoss",
    "testBudget": "cacMax * targetConversions",
    "dailyCap": "testBudget / testDays"
  },
  "structure": {
    "campaigns": 1,
    "adSets": 2,
    "creativesPerAdSet": 4,
    "optimizationEvent": "purchase"
  }
}
```

数字全部留空，因为它们只能来自你自己的毛利表。填完先自检一次：`testBudget` 若小于「最低限度的转化样本」，就还没到能投的规模；`dailyCap` 若低于平台能起量的水平，说明该缩结构而不是摊薄预算。

## 冷启动期三条纪律

一次只改一个变量：改预算、改素材、改受众会打断学习，三条一起改就永远归不了因。

按天看，不按小时看：上午的波动没有信息量，频繁调预算只会让系统反复重启。

先确认承接跑通再谈加预算：商品页到加购、加购到 Stripe 结账的成功率没测过，投进来的流量会白漏一半。

## 停止条件要写成规则

- 花费达到 `k × CAC_max`（k 取 2–3）且订单为 0：关掉这条，换钩子，不加预算。
- 有订单但 `CAC > CAC_max` 连续一个观察周期：降预算、换素材，先别动受众。
- `CAC < CAC_max` 且订单数达标：加预算，单次幅度不超过现有日预算的一档，避免重置学习。

## 落地动作

1. 打开毛利表，把客单价、毛利率、履约与退货损耗抄进 `unitEcon`，算出 `CAC_max` 并写进投放账户备注。
2. 按 `testBudget ÷ dailyCap` 定出测试天数，在日历上标出复盘日；复盘日之前只允许改素材，不允许改受众。
3. 把上面三条停止条件写成一句话贴在账户里，每次调预算前先读一遍。

## 常见坑

- **现象**：一周花了预算，只有零星订单，无法判断品是否可行。→ **原因**：预算被拆成十几个小广告组，每组样本量都低于可判断水平。→ **对策**：按 `CAC_max × 目标转化数` 反推预算，先砍结构数量再谈加钱。
- **现象**：刚有点起色，一加预算成本立刻翻倍。→ **原因**：加预算同时改了受众或素材，学习被打断，被记成「加钱就贵」。→ **对策**：加预算时冻结素材与受众，单次幅度只提一档。
- **现象**：广告数据好看，账户里没收到钱。→ **原因**：只看了点击与加购，没有对齐 Stripe 的支付成功事件。→ **对策**：以 `checkout.session.completed` 为准统计成交，把结账成功率并进判断。
