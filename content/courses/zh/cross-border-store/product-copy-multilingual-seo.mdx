把中文详情页丢给翻译工具，得到的是语法正确但没人想读的说明书；再让它多吐几个关键词，标题就变成词堆。问题不在语言，而在你还没有把「参数」变成「为什么值得买」。翻译只能搬运已经想清楚的东西。

## 卖点不是形容词，是参数到场景的桥

一个可用的卖点拆成三层：参数层回答「它能不能做到」，场景层回答「什么时候会痛」，证据层回答「凭什么信你」。三层里任何一层缺失，写出来的就是形容词。

以防水为例：参数层写防护等级与结构，场景层写具体的倒霉时刻（雨天、洒水、海边），证据层挂检测报告、实拍视频或可见的接缝工艺。三层必须能互相钉住。参数支持不了场景，就是夸大；场景找不到证据，就是拒付与退货的原料。

## 多语言不是直译，是按市场重写

直译通常在三个地方崩：计量与量词、搜索习惯、可用的表述。单位不换算，买家要在脑子里做算术；当地人是搜品类词还是搜问题句，决定标题的主关键词；某些功效表述在部分市场不能用于商品描述，判断依据是当地消费者保护与广告规则，不是同行怎么写。

所以每种语言至少要重写三处：标题、首屏第一句、三条 bullet。参数表可以机翻后人工校对，因为它不承担说服。

## 可复制的文案卡

每个 SKU 与每个语言各一份，AI 只填字段，不自由发挥：

```yaml
# product-copy.yaml
sku: SKU-001
market: de-DE            # 语言与市场分开记，同一语言可能对应多个市场
title: ""                # 主关键词 + 一个差异 + 适用对象，长度按目标展示位裁
h1: ""                   # 与 title 不同义，承接首屏
bullets:
  - ""                   # 每条 = 场景 + 参数 + 证据 ID
  - ""
  - ""
faq:
  - q: ""
    a: ""                # 只答能被参数支撑的问题
evidence:
  - id: ""               # 被 bullet 引用
    type: photo | test-report | material-spec | review
claims_blocked: []       # 本市场不可用的表述，逐条列，生成前注入
```

## 用 AI 批量生成，判断留在人这边

输入给 AI 的是文案卡、目标市场、禁用词表、长度上限；输出只允许标题一条、首屏一段、bullet 三条、FAQ 三条。一次只做一个市场，因为禁用词与搜索习惯不同，混在一起生成只会得到平均化的废话。

批量之前，先人工写一条「金标准」，用它校准语气与信息密度。没有金标准就批量跑，你会得到几十条同样平庸的文案，而且分辨不出哪条更差。

## 最小可行版本

一个 SKU、一个语言、一张文案卡、三条 bullet。标题用「核心关键词 + 一个差异 + 适用对象」的固定句式，不玩花活，先把可读性与可举证性做对。

什么时候可以不做：SKU 很少、靠单一爆品且现有详情页已经能稳定转化时，文案按模板填即可，把预算挪到图片与首屏；多语言也不必一次铺开，先用主市场跑出真实客服问题，再复制到第二语言。

## 落地动作

1. 选一个当前有真实流量的 SKU，按上面的 yaml 建文案卡，参数从包装与供应商资料里抄，不凭记忆。
2. 给三条 bullet 各挂一个证据 ID；挂不上的删掉，而不是把它写模糊。
3. 让 AI 生成 5 条标题候选，按「含主关键词 / 有可验证差异 / 不超展示长度」三项各打一分，留一条。

## 常见坑

- **现象**：翻译后的详情页读起来没毛病，但不转化。 → **原因**：直译保留了原文的信息顺序，而买家的决策顺序是痛点先于参数。 → **对策**：按「场景 → 证据 → 参数」重排，而不是逐句翻。
- **现象**：AI 文案里冒出「最好」「第一」「根治」这类词。 → **原因**：训练语料里的营销表达，且没给禁用词表。 → **对策**：把本市场不可用的表述写进 `claims_blocked`，生成前注入、生成后逐条核。
- **现象**：五个语言同时上线，客服问题集中爆发。 → **原因**：每个市场都有一批「你以为通用」的表述。 → **对策**：单市场跑通再复制，复制时只换标题、首屏与 bullet。
