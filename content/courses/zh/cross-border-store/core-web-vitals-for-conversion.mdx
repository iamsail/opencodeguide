本地 Lighthouse 跑出高分，投放落地页的跳出率依然难看，这两件事并不矛盾：你测的是无痕窗口里的桌面浏览器，用户用的是三年前的中端安卓。性能问题几乎从来不是「站点慢」，而是「某个模板在某种设备上慢」。

## 实验室分数和真实用户不是一回事

Lighthouse 是实验室数据：固定设备、固定网络、干净缓存、单次加载。真实用户数据来自平台提供的聚合报告，或你自己埋的 RUM：真实设备、真实网络、复访缓存、真实交互。判断站点好坏要看真实用户数据的分位数分布，而不是某一次跑分。

三个核心指标对应三件不同的事：LCP 是首屏主要内容出现的时间，INP 是交互到界面响应的延迟，CLS 是加载过程中的布局位移。三者没有替代关系——图片优化到极致也不会让一个重 JS 的筛选器变得跟手。具体阈值以 web.dev/vitals 当前公布的为准，这里不写死数字，因为 Google 调整过，抄教程里的数经常过期。

量测顺序：先做模板级分位数（首页、商品页、集合页、落地页），再做设备与网络分段。平均值没有意义，尾部的慢用户才是掏钱前放弃的那批人。

## 广告侧到底发生了什么

广告平台把落地页体验作为质量与相关性的参考信号之一，具体权重不公开，任何「修好 LCP 就能降多少成本」的说法都不可信。能确定的是一条因果链：首屏慢 → 跳出高 → 转化事件少 → 出价系统学不到足够样本 → 同等预算拿到更少的成交。这是间接但确定的代价，也会在素材疲劳后放大。

所以不要为了猜算法去堆指标。广告落地页的第一屏是这条链路里唯一你能完全控制的变量：把首屏做快，比争论质量分公式有用。

## 按模板定预算

| 模板 | 常见 LCP 元素 | 主要修法 | 不要做 |
| --- | --- | --- | --- |
| 首页 | 首屏大图或视频 | 响应式图 + 给首图更高加载优先级 | 拿视频首帧当首屏主体 |
| 商品页 | 主图、变体切换 | 预加载首图，变体图按需加载 | 首图靠 JS 渲染后再插入 |
| 集合页 | 第一张卡片图、字体 | 限制首屏第三方脚本，字体子集化 | 首屏挂评论或 A/B 工具 |
| 落地页 | 头图与标题字体 | 静态直出首屏，交互组件后置 | 首屏放倒计时或弹窗 |
| 结账 | 由平台托管 | 只量测，不改 | 在结账页加自定义脚本 |

第三方脚本按「是否阻塞首屏」分类：客服、评论、A/B、像素默认延迟到交互或空闲后加载；必须早加载的（如反欺诈）单独评估，并在预算里给它留位置。

## 量测与回归

```ts
// app/rum.ts —— 在 layout 里引入，按模板打标签上报
import { onLCP, onINP, onCLS } from "web-vitals/attribution";

const template = document.body.dataset.template ?? "unknown";

for (const report of [onLCP, onINP, onCLS]) {
  report((metric) => {
    navigator.sendBeacon(
      "/api/rum",
      JSON.stringify({
        name: metric.name,
        value: metric.value,
        template,
        device: navigator.userAgentData?.mobile ? "mobile" : "desktop",
        attribution: metric.attribution,
      }),
    );
  });
}
```

上报两周就能看出哪个模板拖后腿。CI 里对首页与商品页设性能预算，拿最近一次基线做对比阈值，超出就挡 PR——回归通常来自新加的第三方脚本，而不是你自己的代码。

## 落地动作

1. 接 RUM，按模板与设备上报三个核心指标，先有基线再谈优化。
2. 用 DevTools 的 performance 面板确认每个模板的 LCP 元素具体是什么，只修那一个元素。
3. 把首屏第三方脚本列成清单，逐个改成延迟加载，观察一周的转化变化。
4. 在 CI 里对首页与商品页设预算，阈值取最近一次基线。

## 常见坑

- **现象**：实验室分数很高，真实用户数据很差 → **原因**：测的是桌面高速网络，用户在中端移动设备上 → **对策**：以真实用户数据决策，跑分只用于回归对比。
- **现象**：图片压到很小，LCP 依然慢 → **原因**：LCP 元素其实是标题字体，或图片被 JS 延迟插入 → **对策**：先确认 LCP 元素，再决定修图还是改渲染路径。
- **现象**：上了 A/B 工具后转化下降 → **原因**：同步加载的脚本阻塞首屏，两组都被拖慢 → **对策**：脚本异步化，先确认性能影响再判断文案效果。
