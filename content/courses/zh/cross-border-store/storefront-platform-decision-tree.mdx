建站选型最后往往退化成品味之争：谁的模板好看、谁的后台顺手。但真正提前锁死你的不是主题，而是订单和客户数据放在谁手里，以及结账页上你到底能改到什么程度。这两件事定下来之后再改，成本是上线前的数倍。

## 先看四项约束，不看功能清单

四种方案都能卖货，功能对比表几乎没有决策价值。先回答四个问题，任何一项不成立，其余三项都不必讨论。

- **收款主体**：能否拿到 Stripe、PayPal 支持的经营主体与当地银行账户。Stripe 不支持中国大陆主体，常见路径是香港、新加坡或美国公司；主体拿不到时，换成自建站一样收不了款，只能先用平台代收或 Merchant of Record。
- **履约复杂度**：单仓、少 SKU、不预售，平台原生能力够用；多仓、定制、按批次发货，就要看订单能不能被外部系统接管、库存能不能原子扣减。
- **结账定制深度**：是否需要按会员身份改价、按地区隐藏支付方式、增减填写项。这一项决定你在结账上能走多远，也是唯一能逼你换方案的约束。
- **维护人力**：平台店的日常维护接近零；自建站每个月都要有人处理依赖升级、证书、webhook 重试与线上报错。

最容易低估的是维护人力：把「我能写」当成「我会一直维护」。

## 四种方案的硬边界

Shopify 把结账托管在自己手里，主题只负责店面，结账内的改动只能走 Checkout Extensibility 的扩展点与 Functions——想在结账页塞自己的脚本，这条路是关的。Shopline 面向亚洲市场，后台语言与本地支付方式更友好，代价是生态弱一些。WooCommerce 让你同时拥有代码和数据，但插件、服务器、安全补丁与支付合规都回到你这边。Next.js 自建自由度最高，代价是税务、面单、退货、客服后台不会因为你写了前端就出现。

| 方案 | 结账托管 | 结账内可编程 | 数据归属 | 主要代价 |
| --- | --- | --- | --- | --- |
| Shopify | 平台 | 扩展点与 Functions，受计划限制 | 平台内，可通过 API 导出 | 深度定制受平台边界约束 |
| Shopline | 平台 | 有限 | 平台内 | 生态与可编程性较弱 |
| WooCommerce | 自己 | 完全，但要全部自己写 | 完全自有 | 服务器、安全、插件冲突 |
| Next.js 自建 | 自己 + Stripe | 完全 | 完全自有 | 履约与合规系统从零搭 |

## 按阶段判定，而不是按能力判定

```text
Q1 有可用的海外收款主体吗？
├─ 没有 → 先用平台代收或 Merchant of Record；自建解决不了主体问题
└─ 有
   Q2 结账是否要按用户身份改价 / 隐藏支付方式 / 拆单？
   ├─ 是 → 先确认平台扩展点在你要的计划上是否开放
   │        ├─ 开放 → 平台店，定制放扩展点
   │        └─ 不开放 → 自建（这是唯一硬理由）
   └─ 否
      Q3 有能持续维护前端与服务端的人吗（每周固定投入）？
      ├─ 没有 → 平台店，把时间放在选品与投放
      └─ 有 → Q4
         Q4 商品与内容要被多渠道复用（App、线下、B2B 门户）？
         ├─ 是 → 无头电商 API + 自建前端
         └─ 否 → 平台店足够，自建是净成本
```

这棵树只回答一个问题：你现在缺的是能收款的通路，还是能改的结账。多数人在第一阶段就上了第四阶段的方案，把时间花在搭后台而不是验证市场。命中最下方分支的条件通常只有一个：结账必须按身份变化，且扩展点在你要的计划上不开放。

## 迁移的代价要先算

平台店迁出去，商品和图能导出，订单历史、客户账号、订阅与 URL 权重都要逐项处理。URL 不做 301 映射，自然流量会断崖；webhook 不做重放，已付款订单会丢。反过来，自建迁回平台更痛：会员价、捆绑、定制字段只能用应用重新拼一遍。选型时把「两年后可能往哪边迁」写进文档。

## 落地动作

1. 把四项约束的答案写成四行，贴在选型文档顶部；有「不确定」的那一行先去确认，不要边搭边猜。
2. 用上面的树跑一遍，把命中路径写成一句结论，例如「单仓、无会员价、只有我能维护 → 平台店」。
3. 结论是自建时，第一版只做「商品列表 + 商品页 + Stripe 托管结账 + 订单邮件」，购物车、会员、优惠券推迟。
4. 结论是平台店时，先确认目标扩展点在计划上是否开放，再定主题改到什么程度。

## 常见坑

- **现象**：在主题编辑器里翻遍也找不到结账页模板 → **原因**：结账不属于主题，主题代码在结账步骤不生效 → **对策**：结账改动只查 Checkout Extensibility 文档，不要动主题。
- **现象**：自建站上线一个月，发现算不出税、出不了面单 → **原因**：把税务与物流当成「以后接个 API」的事 → **对策**：选型阶段就把税务与物流的接入方式写进清单，按占售价比估成本。
- **现象**：换站后自然流量掉了一半 → **原因**：URL 结构变了却没有 301 映射，外链与收录全部失效 → **对策**：迁移前导出全站 URL 建映射表，逐条验证跳转。
