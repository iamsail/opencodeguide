商品页上多一条真实评论，往往比改一版详情页更能提转化。于是很多店开始「做评论」：找人写、只放好评、删掉差评。短期有效，代价是把可验证性换成了不可验证性——用户迟早会发现，平台与监管也会。

## 评论的价值在可验证，不在数量

一条带订单号、带使用场景、带缺点的评论，比十条「很好用」有用。用户判断的是「这个人跟我像不像」，不是星级。

所以收集流程要解决三件事：这条评论是谁买的、他用了多久、他说的缺点是什么。第三件事最难，也最能建立信任。

## 收集：只邀请已购用户，且不筛选

邀请对象从订单表里取，不从表单里收。触发点放在「签收后若干天」，让用户有使用时间；跨境订单的签收事件来自物流商回调，缺失时可退化为「发货后固定天数」。

```bash
# 评论邀请的取数口径（示意）：只取已签收、未退款、未退订的订单
# 实际执行写在你的数据仓库或定时任务里，不要在浏览器端拼查询
SELECT order_id, customer_email, sku, delivered_at
FROM orders
WHERE status = 'delivered'
  AND refunded_cents = 0
  AND marketing_consent = true
  AND delivered_at < now() - interval '7 days'
  AND review_invited_at IS NULL;
```

三条纪律：不筛人（不能只邀请好评用户）、不代写（可以给提示问题，不能给成稿）、不隐藏（差评可以回复，不能删除）。

带激励的邀请必须披露，也不该影响星级：「留评返券」可以说，但要写明「无论好坏都发」。

## 展示：结构化数据要能对应真实评论

商品页用结构化数据标记评论时，标记的内容必须与页面上可见的评论一致。没有评论就不要标评分，否则属于虚假标记，搜索结果里会被人工处置。规则入口在 Google Search Central 的结构化数据政策与「商品评论」文档，改版前查一次。

```json
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "示例商品名",
  "sku": "SKU-XXX",
  "aggregateRating": {
    "@type": "AggregateRating",
    "ratingValue": 4.6,
    "reviewCount": 128
  },
  "review": [
    {
      "@type": "Review",
      "author": { "@type": "Person", "name": "已购用户 A" },
      "datePublished": "2026-09-12",
      "reviewRating": { "@type": "Rating", "ratingValue": 4 },
      "reviewBody": "按描述合身，袖口略紧，洗后没有变形。"
    }
  ]
}
```

两个坑：`ratingValue` 与 `reviewCount` 必须由数据库统计，不能手写；页面显示的条数要与它对得上。本站是静态导出，评论在构建时拉取进 JSON-LD，新增评论需要重新构建，别让标记过期。

## 合规红线

| 做法 | 风险 | 替代 |
| :--- | :--- | :--- |
| 买评论、刷单 | 平台处罚、支付风控、法律风险 | 只邀请已购用户 |
| 只展示好评、隐藏差评 | 虚假宣传 | 展示全部，公开回复差评 |
| 改写用户原话 | 失去可验证性 | 保留原文，另加官方回复 |
| 未披露的激励 | 误导消费者 | 明确标注激励与发放条件 |
| 直接用买家晒图 | 著作权与肖像权 | 取得书面授权并记录范围 |

## UGC 的授权与二次使用

买家晒图用于广告，需要拿到明确授权：使用范围（哪些渠道）、期限、是否可修改、如何撤回。授权记录要能按人检索，用户要求删除时必须能删干净，包括已经投出去的素材。投放平台对 UGC 广告另有规则，上线前在平台政策中心查「用户生成内容」相关条目。

## 落地动作

1. 写好一条评论邀请模板，只发给已签收未退款的订单，问题里明确要求提到一个缺点。
2. 在商品页加结构化数据，字段全部从数据库取，并用搜索平台的富媒体测试工具验证一次。
3. 建一张授权记录表（用户、渠道、期限、撤回方式），把已有的 UGC 素材逐条补登记。

## 常见坑

- **现象**：评分很高，转化没提升，退货率反而升。→ **原因**：评论全是「很好用」，用户预期被抬高，实际体验对不上。→ **对策**：邀请时要求提缺点，展示时保留具体使用场景。
- **现象**：结构化数据上线后被搜索平台警告或降权。→ **原因**：标记了页面上不存在的评分，或评论条数与标记不一致。→ **对策**：字段全部来自数据库，页面与标记同源生成。
- **现象**：投放用了买家晒图，被投诉下架。→ **原因**：只有口头同意，没有授权范围与期限。→ **对策**：用可检索的授权表，写清渠道、期限与撤回方式。
