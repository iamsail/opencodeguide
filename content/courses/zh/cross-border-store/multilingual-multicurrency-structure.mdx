多语言最常见的顺序错误是：先用插件把页面翻译了，上线半年后发现 URL 结构选错，hreflang 收不敛，最后只能整站改路由。翻译是可以重做的，URL 结构不行——它连着外链、广告落地页和收录记录。

## 三种结构，先选那个不可逆的

| 维度 | 子目录 `/de/...` | 子域 `de.example.com` | 独立域名 `example.de` |
| --- | --- | --- | --- |
| 权重继承 | 共享主域 | 部分独立 | 完全独立，需重新积累 |
| 部署与运维 | 一套代码一套部署 | 可按语言拆分部署 | 每个域名单独运维与证书 |
| 团队分工 | 适合小团队 | 适合分国家团队 | 适合本地品牌与合规要求 |
| 主要代价 | 语言间共享技术风险 | 配置分散、分析要合并 | 成本最高、内容要重做一遍 |
| 适用阶段 | 起步与小团队 | 单市场做大后拆分 | 有本地实体与本地团队 |

小团队起步用子目录即可，它最省事也最容易被搜索结果正确归组。只在一种情况下先不要国际化：目标市场就一个、语言就一种。为了「看起来国际化」上线一堆机器翻译的页面，拖累的是整站的收录质量。

## 语言和地区是两个维度

- hreflang 的语言与地区分开写：只做语言就只写语言，做地区差异再补地区。
- 每个语言页要有自指 canonical，不要全部指向默认语言——这是「只收录了英文」的最常见原因。
- x-default 指向语言选择页或默认语言页，用于没有匹配的情况。
- 不要用 Accept-Language 自动跳转：会挡住爬虫，也会让分享出去的链接在别人手里变成另一种语言。用可见的选择器 + cookie 记住偏好。
- 切换器要保留当前路径，不要一律丢回首页，否则用户每次都得多点两下。

```ts
// lib/i18n.ts —— 每个语言页自指 canonical，alternates 统一生成
export const locales = ["en", "de", "ja"] as const;
export type Locale = (typeof locales)[number];
export const defaultLocale: Locale = "en";
const ORIGIN = "https://example.com";

export function alternates(locale: Locale, path: string) {
  return {
    canonical: `${ORIGIN}/${locale}${path}`,
    languages: {
      ...Object.fromEntries(locales.map((l) => [l, `${ORIGIN}/${l}${path}`])),
      "x-default": `${ORIGIN}/${defaultLocale}${path}`,
    },
  };
}
```

## 币种是展示层，不该进 URL

同一个语言页面给不同用户显示不同货币时，不要为每个币种生成独立地址：同一内容的多份 URL 会制造重复页，hreflang 也收不敛。内容地址只承载语言与地区，币种交给 cookie 或账户偏好。

- **语言切换改 URL，币种切换改偏好**，两者不要互相触发跳转，否则用户切完币种会被带离当前页。
- **自指 canonical 与 hreflang 只随语言与地区变化**，切币种不改变 canonical。
- **该用独立地址的情况**：不同地区的可售商品、含税方式、配送范围确实不同。这时差异是内容层面的，用地区目录承载，而不是加币种参数。
- **投放需要落地页带币种时**，用查询参数并让 canonical 指向无参数版本，避免广告链接把重复内容喂给搜索引擎。

币种背后的定价币、展示币、结算币三层模型与汇率缓冲，放在支付模块单独讲；这里只需记住结构上的一条：币种差异不写进 URL 路径。

目录结构还决定了内容成本：语言数乘以地区数乘以 SKU 数，就是你要长期维护的页面数。翻译不是一次性的，商品上下架、价格调整、政策变更都要乘以这个倍数。所以地区只在差异真实存在时才拆，一个地区目录对应一个真实的运营差异，而不是对应一个你可能进入的市场。

## 落地动作

1. 先定 URL 结构再写内容；地区差异大时用 `/{lang}-{region}/`，否则 `/{locale}/` 就够。
2. 在 layout 层统一生成 hreflang 与自指 canonical，不要每页手写。
3. 做一个可见的语言与币种切换器，选择存 cookie，服务端与客户端读同一份偏好，且不自动重定向。
4. 用上面的公式建一张币种表，把缓冲率写成一个可改的常量，不要散落在代码里。
5. 上线后每周看各语言目录的收录与跳出，判断是翻译质量还是结构问题。

## 常见坑

- **现象**：只收录了默认语言 → **原因**：其它语言没有独立 URL，或 canonical 全部指向默认语言 → **对策**：每语言独立 URL + 自指 canonical + hreflang 互指。
- **现象**：页面显示价与扣款金额不一致 → **原因**：展示币与结算币不是同一层，或四舍五入规则不同 → **对策**：结账页显式标注结算币种，展示与扣款用同一套规则计算。
- **现象**：切到德语后又跳回英文 → **原因**：Accept-Language 自动跳转覆盖了用户选择 → **对策**：用户显式选择优先，自动跳转只在没有任何偏好时生效。
