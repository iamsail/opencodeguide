DDU 订单在客户门口被收一笔钱，多数人只当它是差评风险，其实那是三笔成本叠加：钱本身、拒收后的往返运费、争议记录。DDP 也不是多付点税，它改变的是你在交易里的角色。

## 客户在门口被收钱，成本比税高

拒收的包裹去程已花，回程更贵，退回的货多半不能按原价再卖，客户还可能顺手开争议。DDU 的隐性成本是拒收率乘以（去程、回程、货值折损）之和，再叠加争议对账户的影响。

DDP 的成本是显性的：关税、清关代理费、垫付的现金流。差别不是哪个便宜，而是你选哪一类成本：随机爆发在少数订单上，还是平摊到每一单。

## DDP 是多接一个角色

做 DDP 你就是进口方：自己持目的国税号，或让清关代理以进口方名义申报。随之多出三项义务：申报要素（商品编码、原产地、申报价值）、进口环节增值税的处理、申报错误的责任。

第二项最常算错。进口 VAT 能抵扣时是现金流占用，不是成本；不能抵扣才是成本。同一税率下两种情形负担差很多，取决于你在当地有没有注册与申报能力，和税率表无关。

## 关税怎么估：三个变量，一个来源

商品编码：前六位国际通用，后面按各国税则细分，选错编码等于选错税率。申报价值口径：多数国家按成交价加运保费，具体以目的国规定为准。原产地：决定是否适用优惠税率，通常需要原产地证明。

来源只有一个：目的国海关官网的税则与官方关税数据库，查完记下日期。第三方博客的税率表会过期，还常常只给最惠国税率，忽略你实际适用的类别。

低申报则是另一回事：省下的钱可算，代价不可算：补税、罚金、查验扣货、账户被支付渠道标记。合规成本能进预算，罚金不能。DDP 场景下风险还会集中，出问题赔的往往是一整批货。

## 把税放进售价的三种做法

| 做法 | 客户体验 | 你的风险 | 结算复杂度 | 适用 |
| :--- | :--- | :--- | :--- | :--- |
| 含税标价（DDP） | 最好，看到即到手价 | 税率变动与申报责任 | 高，需要成本模型 | 高客单、B2B、退货敏感的品类 |
| 结账时估算 | 较好，但最后一步才见税额 | 估算偏差自己吸收 | 中，按目的地分区计算 | 多市场、单量中等 |
| 不含税（DDU） | 最差，客户在门口被收钱 | 拒收与争议由客户行为决定 | 低，只管发出 | 低客单、价格敏感、试水阶段 |

税额算不准，三种做法都站不住。用同一套模型算单件落地成本：

```ts
function landedCost(p: {
  goodsCost: number;        // 采购成本，含国内段运费
  firstLegShare: number;    // 头程分摊到件
  dutyRate: number;         // 按商品编码查当期税则
  importTaxRate: number;    // 进口 VAT / GST 税率
  importTaxRecoverable: boolean; // 你在该国能否抵扣
  clearanceFee: number;     // 清关与代理费，按票或按件
  lastMile: number;
  paymentFeeRate: number;   // 支付手续费占售价比
  returnProvision: number;
}): number {
  // 完税价格口径以目的国规定为准，这里按「货值 + 头程」近似
  const dutiable = p.goodsCost + p.firstLegShare;
  const duty = dutiable * p.dutyRate;
  const importTax = (dutiable + duty) * p.importTaxRate;
  const taxCost = p.importTaxRecoverable ? 0 : importTax; // 可抵扣时是占用
  const subtotal = dutiable + duty + taxCost + p.clearanceFee + p.lastMile + p.returnProvision;
  return subtotal / (1 - p.paymentFeeRate); // 覆盖手续费的最低售价
}
```

## 小团队的最小可行版本

先只对一个市场做 DDP，通常选客单价最高、退货最敏感的那个，用模型算出最低售价，看毛利是否站得住。其余市场继续 DDU，但要在配送政策页写清「进口税费由收件人承担」，结账页再提示一次。

什么时候可以不做：单量没起来、客单价低到清关与代理费占比过高、或目的国要求先注册税号才能申报。这几种情况下，把 DDU 的预期管理做扎实更划算。

## 落地动作

1. 列出销量前三的目的国，逐一到该国海关官网查品类的商品编码与税率，记录查询日期与链接。
2. 用 `landedCost` 算出这三个国家在两个价格带上的落地成本，标出毛利为负的组合。
3. 检查结账页与支付渠道的税费规则：是否单列、是否结账时收取、退款怎么退，写成一条说明。
4. 在配送政策页补税费归属说明，中英各一版，避免客户拿「含税价」截图来争论。

## 常见坑

- **现象**：改 DDP 后转化率上去，毛利反而掉了 → **原因**：只加了关税，漏掉清关代理费、不可抵扣进口税与退货运费 → **对策**：用落地成本模型全项核算，关税只是其中一行。
- **现象**：同一商品编码，两家货代报的税率不一样 → **原因**：编码细分不同，或申报价值是否含运保费的口径不同 → **对策**：以目的国税则原文为准，要求货代给出编码与依据。
- **现象**：客户在结账最后一步看到税额后弃购 → **原因**：税费出现太晚，与商品页价格不一致 → **对策**：商品页给含税预估并与结账页一致；做不到就明示不含税。
