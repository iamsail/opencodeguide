把页面上的「$」换成「€」不是本地化，只是把汇率风险从买家身上挪到自己身上。三个币种一旦不一致，退款、对账、广告素材里的价格都要跟着改，麻烦在这里，不在显示。

## 三个币种，别混成一个

定价币种是你按什么标价，展示与支付币种是买家看到并实际支付的，结算币种是最后进入你银行账户的。三者一致最省事；不一致就会产生换汇损耗、多币种会计和退款歧义。

本地货币展示通常能提升转化，因为它去掉了买家的心算；代价是价格要持续维护、退款按原币处理、对账多一列、投放素材里的价格会过期。这笔账要在动手前算，而不是上线后发现多了一个每月要维护的价格表。

## 不要用实时汇率直转

实时折算会让价格每天都在变：广告素材、比价站抓取、老客户的记忆全都会对不上，而你很难解释「为什么昨天更便宜」。做法是设一个基准价、一个固定缓冲、一个固定更新节奏，比如按月更新，并把缓冲写进毛利模型。

```text
local_price = charm_round( base_price_usd × fx_rate × (1 + fx_buffer) )
```

fx_buffer 覆盖换汇成本与结算周期内的汇率波动，具体取值取决于你的结算币种、更新频率和退款率。这里没有通用数字，只有一个原则：缓冲要按最坏情况估，因为它同时承担了退款时你退回去的那部分汇率差。

## 取整规则要写进代码

```ts
// 把美元基准价换算成可长期维护的展示价；fxRate 由汇率源注入，不写死
type Market = {
  currency: string;
  unit: number;      // 取整步长（EUR 用 1，JPY 用 100）
  endings: number[]; // 档位内的尾数偏好
  buffer: number;    // 覆盖换汇成本与波动，按最坏情况估
};

const MARKETS: Market[] = [
  { currency: "EUR", unit: 1, endings: [0.9, 0.99], buffer: 0.04 },
  { currency: "GBP", unit: 1, endings: [0.9, 0.99], buffer: 0.04 },
  { currency: "JPY", unit: 100, endings: [80, 90], buffer: 0.05 },
];

function charmRound(value: number, m: Market): number {
  const head = Math.floor(value / m.unit) * m.unit;
  const up = m.endings
    .map((e) => head + e)
    .filter((p) => p >= value)
    .sort((a, b) => a - b);
  return up[0] ?? head + m.unit + m.endings[0];
}

export function localPrice(baseUsd: number, fxRate: number, m: Market) {
  const raw = baseUsd * fxRate * (1 + m.buffer);
  return { currency: m.currency, amount: charmRound(raw, m) };
}
```

要点在最后一步：价格一旦发布到支付平台，多数情况下不能原地改金额，只能新建价格对象。所以更新节奏不能太频繁，否则你会在后台堆出一串废弃价格，还得决定哪个链接对应哪个。

## 什么时候只做美元

单一市场、订单少、客单价低时，本地化的收益小于维护成本。折中做法是以美元结算并在页面标注，另给一个「参考价」并注明汇率与更新日期，参考价不参与支付。仓库里的课程页就是这么处理的——页面明确以美元结算，人民币参考价定期核对——它把「看起来本地化」和「财务上只有一个币种」分开了。

## 退款与部分退款的币种坑

退款按原币退回，汇率差由你承担；部分退款要按原币金额的比例计算，不要用美元金额反算再折算。对账时保留两列：原币金额与结算币种金额，否则月末永远差一点。

## 落地动作

1. 定一个基准币种，其余币种全部由它换算，禁止手工改单个市场的价格。
2. 把取整函数与缓冲写成可测试的代码，补一条单测：任意基准价算出的结果都不带多余小数。
3. 页面标注结算币种；参考价注明汇率日期，且不参与结账金额。
4. 退款脚本按原币金额走，不要先折成美元。

## 常见坑

- **现象**：本地价格看起来比美元便宜一截，毛利被吃掉。 → **原因**：缓冲只覆盖了名义汇率，没覆盖换汇费和退款回流。 → **对策**：把缓冲拆成换汇成本、波动、退款损耗三项分别估，再合并成一个系数。
- **现象**：改了汇率，支付平台里的价格没变。 → **原因**：已发布的价格对象通常不能改金额。 → **对策**：把改价当发版流程走——新建价格、灰度、旧链接先保留一段时间。
- **现象**：部分退款后对账差几分钱。 → **原因**：用美元金额反算原币，四舍五入方向不一致。 → **对策**：以原币金额为唯一事实来源，结算金额只作为派生值。
