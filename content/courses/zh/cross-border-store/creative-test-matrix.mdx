一次做十条「不同」的素材，跑完发现三条赢、七条输，却说不出赢在哪、下次怎么复制——这是素材测试最常见的浪费。素材不是一整块创意，它是三个可以单独替换的层；测试的价值不在于多，而在于每次只让一层变化，让结论能被下一次复用。

## 素材是三层，不是一整块

hook 决定人是否停下来：第一句话、前几秒的画面、标题的首行。卖点决定他为什么买：一条素材只讲一个，讲三个等于没讲。场景决定他觉得「这说的是我」：谁、在什么时刻、解决什么麻烦。

三层分开的好处是：hook 输了不必重做卖点，卖点输了不必重拍场景。绝大多数「素材不行」的结论，其实是三层混在一次拍摄里，无法定位。

## 先固定场景，再让 hook 与卖点交叉

第一轮固定一个场景，跑 hook × 卖点的网格：

| | 卖点 1：省时间 | 卖点 2：更省心 | 卖点 3：更耐用 |
| :--- | :--- | :--- | :--- |
| hook 1：反常识断言 | C1 | C2 | C3 |
| hook 2：痛点直述 | C4 | C5 | C6 |
| hook 3：结果先行 | C7 | C8 | C9 |

九宫格不是九条都要拍成片。先用图文或低成本剪辑跑一遍，把每格记成一个编号，赢的格子再升级成视频。第二轮只对赢的格子换场景，看它在第二个使用情境里是否还成立；不成立，说明赢的是 hook，不是卖点。

## 命名与记录：没有编号就没有结论

```json
{
  "creative_id": "cb-01-h2-b1-s3",
  "hook": "h2",
  "benefit": "b1",
  "scenario": "s3",
  "format": "video|image|carousel",
  "landing_path": "/products/xxx",
  "started_at": "YYYY-MM-DD",
  "spend": 0,
  "impressions": 0,
  "hook_rate": 0,
  "ctr": 0,
  "cvr": 0,
  "orders": 0,
  "cac": 0
}
```

编号规则建议「轮次-序号-三层代号」，让任何一个数字都能倒推回是哪个格子。记录里必须有落地页路径：素材赢了但落地页不同，结论作废。

## 判定分三级，顺序不能反

`hook_rate = 三秒留存 ÷ 曝光`，`CTR = 点击 ÷ 曝光`，`CVR = 成交 ÷ 点击`，`CAC = 花费 ÷ 成交订单数`。

先看 hook：留存低于自己历史的中位，说明前三秒没抓住人，直接换 hook，别改卖点。留存合格再看 CTR：点得动说明卖点表达成立。最后看 CVR：点进来不买，问题常在落地页与价格，不在素材，别拿素材背锅。三级都不合格却还在加预算，是素材测试里最贵的错误。

## 样本不够时，宁可少测

一个格子的曝光撑不起判断时，扩展格子只会放大噪声。判断标准是「每个格子至少能观察到预期订单数」，用 `CAC_max × 预期订单数` 反推每格预算，再决定这一轮跑几格。预算不够就跑 4 格，不要跑 9 格。

## 落地动作

1. 写出你的 hook、卖点、场景三份候选清单各 3 条，给每条一个短代号，禁止同一条素材同时承载两个卖点。
2. 用上面的九宫格排出第一轮，按 `CAC_max × 预期订单数` 算每格预算，只保留预算撑得住的格子。
3. 把 `creative_id` 命名规则和字段写成模板，交给拍摄与剪辑的人，投放前逐条填完再上线。

## 常见坑

- **现象**：测了二十条素材，总结不出任何规律。→ **原因**：每条素材同时换了 hook、卖点与场景，差异不可归因。→ **对策**：改用编号矩阵，一轮只让一层变化。
- **现象**：CTR 很高，转化率极低，素材越投越亏。→ **原因**：hook 抓的是看热闹的人，卖点与落地页承诺不一致。→ **对策**：把判定顺序改成留存→点击→转化，并逐条核对素材承诺与商品页首屏。
- **现象**：赢的素材换到第二个市场直接失效。→ **原因**：以为是通用卖点，实际赢的是本地语言习惯或场景细节。→ **对策**：换市场时先只换场景层，保留 hook，验证是不是场景绑定。
