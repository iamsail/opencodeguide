在你的项目中创建 `opencode.jsonc` 来配置 OpenCode。添加 schema 以启用编辑器校验，然后只设置你需要的选项。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-5-5",
}
```

你也可以让 OpenCode 代你更新此文件。

## 格式

OpenCode 支持 JSON 和 JSONC。需要注释或尾随逗号时使用 JSONC。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  // Use this model by default.
  "model": "anthropic/claude-sonnet-5-5",
}
```

## 配置位置

将受管的、整机范围的设置放入系统配置目录：

| 平台 | 目录 |
| -------- | --------------------------------------- |
| macOS    | `/Library/Application Support/opencode` |
| Linux    | `/etc/opencode`                         |
| Windows  | `%ProgramData%\opencode`                |

系统目录的工作方式与全局目录相同。除 `opencode.json(c)` 外，它还为机器上的每个用户加载 `agents/`、`commands/`、`skills/` 和 `plugins/`：

```text
/etc/opencode/
├── opencode.json
├── agents/review.md
├── commands/release.md
└── skills/deploy/SKILL.md
```

在 macOS 上，OpenCode 还会读取 MDM 工具为 `ai.opencode.managed` 域部署的受管偏好设置。用户专属配置文件会取代整机范围的配置文件：

```text
/Library/Managed Preferences/<user>/ai.opencode.managed.plist
/Library/Managed Preferences/ai.opencode.managed.plist
```

受管设置具有最高优先级，因此用户和项目无法覆盖其所设置的值，受管偏好设置会覆盖系统目录。仅靠设置无法阻止用户添加提供商、MCP 服务器、智能体或插件；要强制执行限制，请在受管配置中使用[策略](/zh/docs/configure/policies#precedence)。

将适用于所有项目的用户设置放入全局配置：

```text
~/.config/opencode/opencode.json(c)
```

将项目设置放入以下任一文件：

```text
/home/user/projects/my-app/opencode.json(c)
/home/user/projects/my-app/.opencode/opencode.json(c)
```

OpenCode 会从当前目录一直搜索到文件系统根目录。它首先按从最远目录到最近目录的顺序合并直接的 `opencode.json(c)` 文件，然后按相同顺序合并 `.opencode` 目录内的文件。这意味着每个被发现的 `.opencode` 配置都会覆盖所有直接配置。除非你需要这种行为，否则请在整个目录树中统一使用其中一种形式。

例如，从 `/home/user/projects/acme/packages/web` 启动 OpenCode：

```text
/etc/opencode/opencode.json
~/.config/opencode/opencode.json

/home/user/projects/acme/
├── opencode.json
└── packages/
    └── web/
        ├── opencode.json
        └── src/
```

OpenCode 按从最低到最高的优先级应用这些文件：

1. `~/.config/opencode/opencode.json`
2. `/home/user/projects/acme/opencode.json`
3. `/home/user/projects/acme/packages/web/opencode.json`
4. `/etc/opencode/opencode.json`

包配置会覆盖仓库配置中的同名设置，仓库配置覆盖全局配置。系统配置覆盖以上所有配置。不冲突的设置会被保留。来自全局与项目文件的[策略](/zh/docs/configure/policies#precedence)按相反顺序求值，系统策略的优先级高于它们全部。

## Schema

完整的 OpenCode 配置 schema 位于 [opencode.ai/config.json](https://opencode.ai/config.json)。

在配置文件中添加 `$schema` 字段，即可在支持 JSON Schema 的编辑器中启用校验与自动补全：

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json"
}
```

请以该 schema 作为可用字段、可接受值与嵌套配置结构的权威来源。

### Shell

设置终端与 shell 工具使用的 shell。

```jsonc
{
  "shell": "/bin/zsh",
}
```

### 模型

以 `provider/model` 格式设置默认模型。根级默认值目前不会保留 `#variant`；智能体与命令中的模型引用则可以选择 variant。

```jsonc
{
  "model": "anthropic/claude-sonnet-5-5",
}
```

模型选择与本地模型详见[模型指南](/zh/docs/configure/models)。

### 智能体

选择会话未明确指定时所使用的主要智能体。

```jsonc
{
  "default_agent": "build",
}
```

内置与自定义智能体详见[智能体指南](/zh/docs/configure/agents)。

### 更新

在全局配置中控制更新检查。将 `update` 设为 `"disable"` 可跳过检查，设为 `"notify"` 可在安装前显示可用更新，设为 `"auto"` 可自动安装更新。省略时，`update` 默认为 `"notify"`。

自动安装不会重启正在运行的服务器。请手动重启以激活已安装的更新。
项目级的值会被忽略。

```jsonc
{
  "update": "notify",
}
```

### 用户名

设置用户名。OpenCode 会接受该字段，但不会在对话中显示它。

```jsonc
{
  "username": "alice",
}
```

### 权限

定义有序的规则，在智能体对匹配资源使用工具之前允许、拒绝或询问。

```jsonc
{
  "permissions": [
    {
      "action": "shell",
      "resource": "git push *",
      "effect": "ask",
    },
  ],
}
```

规则匹配与可用动作详见[权限指南](/zh/docs/configure/permissions)。

### 策略

通过有序声明来允许或拒绝使用某个提供商、硬性拒绝权限检查，或阻止 MCP 服务器、技能或插件；范围更大的配置可以覆盖这些声明。

```jsonc
{
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "anthropic", "effect": "allow" },
    { "action": "tool.use", "resource": "shell:git push *", "effect": "deny" },
  ],
}
```

匹配规则、跨配置文件的优先级以及 Console 托管的策略详见[策略指南](/zh/docs/configure/policies)。

### 智能体

覆盖内置智能体，或定义拥有自己的模型、指令、模式和权限的专用智能体。

```jsonc
{
  "agents": {
    "reviewer": {
      "description": "Review changes without editing files",
      "mode": "subagent",
      "system": "Focus on correctness, security, and missing tests.",
      "permissions": [{ "action": "edit", "resource": "*", "effect": "deny" }],
    },
  },
}
```

全部智能体选项与基于文件的智能体详见[智能体指南](/zh/docs/configure/agents)。

### 快照

启用或禁用撤销与还原行为所使用的文件系统快照。

```jsonc
{
  "snapshots": false,
}
```

撤销与重做行为详见[快照指南](/zh/docs/configure/snapshots)。

### 文件监视

忽略不应触发文件系统更新的文件和目录。

```jsonc
{
  "watcher": {
    "ignore": ["dist/**", "coverage/**"],
  },
}
```

### 格式化工具

在 `write`、`edit` 或 `patch` 工具修改文件后对其进行格式化。将 `formatter` 设为 `true` 可启用可用的内置格式化工具。

```jsonc
{
  "formatter": true,
}
```

内置与自定义格式化工具详见[格式化工具指南](/zh/docs/configure/formatters)。

### 媒体

控制 `read` 工具加载的超大图片在发送给模型之前如何缩放或拒绝。

```jsonc
{
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880,
    },
  },
}
```

图片处理与限制详见[附件指南](/zh/docs/configure/attachments)。

### 输出

设置从工具结果中保留的最大行数与字节数。

```jsonc
{
  "tool_output": {
    "max_lines": 2000,
    "max_bytes": 51200,
  },
}
```

### 搜索

选择 OpenCode 进行网络搜索的方式。使用 `"random"` 可自动选择可用的提供商。

```jsonc
{
  "websearch": {
    "provider": "random",
  },
}
```

提供商、凭据、选择方式、速率限制与禁用搜索详见[网络搜索指南](/zh/docs/configure/websearch)。

### MCP

配置本地和远程 Model Context Protocol 服务器。全局的 `mcp.timeout` 值适用于配置文件中定义的服务器；每个服务器的 `timeout` 会覆盖它们。

```jsonc
{
  "mcp": {
    "servers": {
      "playwright": {
        "type": "local",
        "command": ["bunx", "@playwright/mcp"],
      },
    },
  },
}
```

远程服务器、OAuth、环境变量与超时详见 [MCP 指南](/zh/docs/configure/mcp-servers)。

### 上下文压缩

控制自动上下文压缩，以及它保留多少最近的上下文。

```jsonc
{
  "compaction": {
    "auto": true,
    "keep": {
      "tokens": 15000,
    },
    "buffer": 20000,
  },
}
```

本地摘要仍是默认方式。对于自动与手动请求，可通过提供商或模型策略选择启用提供商原生的上下文压缩：

```jsonc
{
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-6.1-sol": { "settings": { "compaction": { "type": "summary" } } },
      },
    },
  },
}
```

模型级设置会覆盖提供商设置。自动上下文压缩使用所选模型的可用输入预算。提供商检查点会在本地摘要用于保留尾部内容的同一 `compaction.keep.tokens` 预算内保留最近的用户消息。顶层的 `compaction.auto: false` 会禁用新的自动上下文压缩，而不会丢弃已安装的检查点。预算设定与溢出恢复详见[上下文压缩指南](/zh/docs/configure/compaction)。

### 预热

通过周期性的瞬时请求保持最近活跃的模型会话处于预热状态。预热默认禁用；将其设为 `true` 可使用 4 分钟的空闲间隔和 30 分钟的活跃窗口。

```jsonc
{
  "warming": {
    "prompt": "Do not perform any work. Reply with exactly: OK",
    "interval": "4 minutes",
    "duration": "30 minutes",
  },
}
```

请求行为、自定义方式与成本考量详见[预热指南](/zh/docs/configure/warming)。

### 智能体技能

添加 OpenCode 应当用于搜索智能体技能的目录或 URL。

```jsonc
{
  "skills": ["./team-skills", "https://example.com/.well-known/skills/"],
}
```

技能结构与 `.opencode/skills/` 下的自动发现详见[技能指南](/zh/docs/configure/agent-skills)。

### 命令

将可复用的斜杠命令定义为具名的提示词模板。

```jsonc
{
  "commands": {
    "review": {
      "description": "Review the current changes",
      "template": "Review the current diff for correctness and missing tests.",
    },
  },
}
```

参数、模型、智能体与基于文件的命令详见[命令指南](/zh/docs/configure/commands)。

### 指令

声明额外的指令文件、glob 或 HTTP(S) URL。OpenCode 会将它们与所发现的 `AGENTS.md` 文件一并加载。

```jsonc
{
  "instructions": ["CONTRIBUTING.md", "docs/guidelines/*.md"],
}
```

项目指令与 `AGENTS.md` 详见[指令指南](/zh/docs/configure/rules)。

### 引用

将本地目录或 Git 仓库作为具名的辅助上下文提供使用。

```jsonc
{
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Product behavior and terminology",
    },
    "effect": {
      "repository": "Effect-TS/effect",
      "branch": "main",
    },
  },
}
```

简写形式、可见性与路径解析详见[引用指南](/zh/docs/configure/references)。

### 工作树

设置新本地工作树的父目录。OpenCode 会附加所请求或生成的工作树名称。

```jsonc
{
  "worktree": {
    "directory": "../worktrees",
  },
}
```

相对路径基于项目保存的规范检出进行解析。这同样适用于全局与项目配置；绝对路径按原样使用，`~/` 则基于用户的主目录解析。

例如，以下全局配置将新工作树放在各项目自己的 `.lane/trees/` 目录下：

```jsonc
{
  "worktree": {
    "directory": ".lane/trees",
  },
}
```

若无此设置，创建时将使用服务器数据目录下的 `worktree/<first-six-project-ID-characters>`。工作树的创建与刷新会从项目保存的规范检出加载配置，包括其他克隆共享其项目 ID 的情况。修改该设置不会移动已有工作树。

Git 是内置默认值。注册了策略的[插件](/zh/docs/develop/plugins#worktrees)会自动成为该插件运行时中的默认值。项目操作使用规范检出的运行时。策略相关的选项属于该插件，而非 `worktree` 配置对象。

### 插件

从包或本地插件目录加载插件。当插件接受选项时，使用对象形式。

```jsonc
{
  "plugins": [
    "opencode-example-plugin",
    {
      "package": "./plugins/local",
      "options": {
        "enabled": true,
      },
    },
  ],
}
```

插件加载与配置详见[插件指南](/zh/docs/configure/plugins)。

### 提供商

配置提供商，并添加或覆盖其模型、请求设置、请求头与模型变体。

```jsonc
{
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol-custom": {
          "modelID": "gpt-6.1-sol",
          "name": "GPT-6.1 Sol Custom",
          "limit": {
            "context": 200000,
            "output": 32000,
          },
        },
      },
    },
  },
}
```

提供商的 `settings.transport: "websocket"` 会选择其会话 WebSocket。

凭据、自定义端点、提供商包、WebSocket 传输与模型配置详见[提供商指南](/zh/docs/providers)。

## 变量

你可以在配置文件中使用变量替换来引用环境变量与文件内容。将引用放在 JSON 字符串内。

### 环境变量

使用 `{env:VARIABLE_NAME}` 替换环境变量：

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "{env:OPENCODE_MODEL}",
  "providers": {
    "anthropic": {
      "settings": {
        "apiKey": "{env:ANTHROPIC_API_KEY}",
      },
    },
  },
}
```

如果环境变量未设置，它将被替换为空字符串。

### 文件

使用 `{file:path/to/file}` 替换文件内容：

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": {
        "apiKey": "{file:~/.secrets/openai-key}",
      },
    },
  },
}
```

文件路径可以是：

- 相对于配置文件所在目录
- 绝对路径，或以 `~/` 开头表示你的主目录

如果文件不存在，它将被替换为空字符串。

这些适用于：

- 将 API 密钥等敏感数据保存在单独的文件中。
- 在多个配置文件之间共享通用配置片段。

## 实验性

<Callout type="warning">
  实验性设置可能在任何版本中变更、损坏或被移除，且不另行通知。不要在稳定工作流中依赖它们。
</Callout>

所有实验性设置都位于 `experimental` 键下：

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "experimental": {
    "todo": true,
    "subagent_depth": 2,
    "portable_shell_scanner": true,
    "background_compaction": true,
    "location_idle_timeout": "4 hours",
  },
}
```

### 待办事项

将 `todo` 设为 `true` 可为智能体提供 `todowrite` 工具，用于跟踪多步骤工作。默认为 `false`。

### 子智能体深度

`subagent_depth` 设置子智能体可以启动自身子智能体的嵌套深度。默认为 `1`，即子智能体不能再启动另一个子智能体。

### 可移植 shell 扫描器

将 `portable_shell_scanner` 设为 `true` 可替换权限检查所使用的默认 tree-sitter shell 扫描器。默认为 `false`。其行为详见[权限](/zh/docs/configure/permissions#scanner)。

### 后台上下文压缩

将 `background_compaction` 设为 `true` 可在需要之前于后台写入上下文压缩摘要，从而使自动上下文压缩不会暂停会话。默认为 `false`。工作原理详见[上下文压缩](/zh/docs/configure/compaction#background-compaction)。

```jsonc
{
  "experimental": {
    "background_compaction": true,
  },
}
```

### 位置空闲超时

`location_idle_timeout` 控制项目位置在多长时间内没有会话活动后，OpenCode 会卸载其服务。它接受如 `"2 hours"` 这样的时长，默认为 `"60 minutes"`。正在运行的会话和后台任务会保持位置处于加载状态。将其设为 `false` 可永不卸载空闲位置。项目配置可覆盖全局值。

```jsonc
{
  "experimental": {
    "location_idle_timeout": false,
  },
}
```

### 已弃用的策略

`experimental.policies` 已弃用。请改用顶层的 [`policies`](/zh/docs/configure/policies)。旧键仍然有效，并会合并进 `policies`。
