Codex 使用 OpenAI Responses API，因此可以调用通过 Responses 提供的模型，例如 GPT、Grok 和 Muse Spark。

## 配置

将 Console 添加为 `~/.codex/config.toml` 中的模型提供商，并将其设为默认。

```toml title="~/.codex/config.toml"
model = "gpt-6.1-sol"
model_provider = "opencode"

[model_providers.opencode]
name = "OpenCode Console"
base_url = "https://opencode.ai/inference/openai/v1"
env_key = "OPENCODE_API_KEY"
wire_api = "responses"
```

Codex 会在基础 URL 后追加 `/responses`，并从 `env_key` 读取密钥。创建一个[个人 API 密钥](/zh/docs/console/harnesses#get-an-api-key)，然后导出它。

```bash
export OPENCODE_API_KEY="oc_sk_..."
codex
```

<Callout>
  Codex 仅从 `~/.codex/config.toml` 读取模型提供商。项目的 `.codex/config.toml` 无法设置它们。
</Callout>

## Go

使用 Go 的基础 URL，以及来自具有 [Go](/zh/docs/console/go) 订阅的工作区的密钥。

```toml title="~/.codex/config.toml"
model = "gpt-6-luna"
model_provider = "opencode-go"

[model_providers.opencode-go]
name = "OpenCode Go"
base_url = "https://opencode.ai/inference/go/openai/v1"
env_key = "OPENCODE_API_KEY"
wire_api = "responses"
```

## 模型

将 `model` 设为接受 Responses API 的模型。可用 `--model` 为单次运行覆盖该设置。

| 套餐 | 模型 |
| ------------- | -------------------------------------- |
| 按量付费 | GPT、Grok 和 Muse Spark 模型 |
| Go | GPT、Grok、Muse Spark 和 DeepSeek V4 |

```bash
codex --model grok-4.7
```

Claude、Gemini 以及大多数开放模型在 Codex 中尚不可用。在此之前可使用 [Pi](/zh/docs/console/harnesses/pi) 或 [Hermes](/zh/docs/console/harnesses/hermes) 来接入它们。

<Callout>各 Harness 对所有模型的支持即将推出。</Callout>

Codex 不了解其目录之外模型的上下文窗口或推理设置。它会对这些模型使用通用默认值并打印警告，该警告可忽略。

## 配置档案

通过配置档案并列保留按量付费与 Go。在 `~/.codex/config.toml` 中定义两个提供商，然后添加一个切换到 Go 的配置档案文件。

```toml title="~/.codex/go.config.toml"
model = "gpt-6-luna"
model_provider = "opencode-go"
```

```bash
codex --profile go
```

## Console MCP

添加 [Console MCP](/zh/docs/console/harnesses#console-mcp) 服务器，并从浏览器登录。

```bash
codex mcp add opencode-console --url https://opencode.ai/console/mcp
```

如果登录未自动启动，请手动执行。

```bash
codex mcp login opencode-console
