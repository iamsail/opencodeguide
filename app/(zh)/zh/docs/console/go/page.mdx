OpenCode Go 为你提供对热门开放编码模型的可靠访问，并提供两种按月订阅方案：

| 方案        | 价格         | 包含用量                              |
| ----------- | ------------ | ------------------------------------------- |
| **Go**      | **$10/月** | 以更低成本访问下列模型       |
| **Go Plus** | **$40/月** | 下列模型均享更高用量上限 |

Go 的工作方式与 OpenCode 中的其他提供商相同。订阅 OpenCode Go 后即可获得你的 API 密钥。该服务**完全可选**，不使用它也能正常使用 OpenCode。

该服务主要面向国际用户，提供稳定的全球访问。

## 工作方式

1. 登录 [OpenCode Console](https://opencode.ai/console)，订阅 Go 或 Go Plus，添加账单信息，然后复制你的 API 密钥。
2. 在 TUI 中运行 `/connect`，选择 **OpenCode Go**，然后粘贴你的 API 密钥。

   ```text
   /connect
   ```

3. 运行 `/models` 以选择可通过 Go 使用的模型。

   ```text
   /models
   ```

<Callout>
  Go 与 Go Plus 适用于仅有单个成员的工作区，例如注册时创建的 **Personal** 工作区。使用 Go 订阅的工作区无法邀请成员。
</Callout>

### 启用受限模型

工作区隐私设置同样适用于 Go。默认情况下，会屏蔽使用请求数据进行训练的付费端点，允许的区域为 **Europe & United States**。未保存隐私设置的工作区还会对来自中国的请求开放 **Global**。

在 **Settings › Privacy** 中，所有者或管理员可启用：

- **DeepSeek V4.1 Flash 与 V4 Pro：** 在 **Regions** 下选择 **Global**。
- **Muse Spark 1.3 Contributor 与 Muse Spark 1.2 Contributor：** 打开 **Allow paid endpoints that train on request data**。

各模型的训练与数据保留条款详见[隐私](#privacy)。

## 我可以在哪里使用它？

OpenCode Go 面向 [OpenCode](https://opencode.ai) 及其他会产生类似类型请求的编码智能体（agent）而设计。我们会监控流量，防范会降低其他用户体验的滥用行为。

你的客户端应当：

1. 发送典型的编码智能体流量
2. 使用自身的 user agent 标识自己，例如 `my-coding-agent/1.0`，而不是通用的 SDK 或 HTTP 库名称。
3. 为每个对话在 `x-opencode-session` 中发送稳定的会话（session）ID，以便我们优化路由与提示缓存。

参见 [Harness](/zh/docs/console/harnesses)，了解如何在 Claude Code、Codex、Hermes、Pi 与 Raycast 中配置 Go。

### 超出限制的用量

如果你的 Console 余额中还有额度，可在 **Go** 页面开启 **Extra Usage**。开启后，当你达到用量限制时，Go 会回退到你的[按量付费余额](/zh/docs/console/models#pricing)，而不是阻止请求。

### 为何部分模型的用量较低

在 Go 中，包含的每月用量因模型而异。

对大多数模型，我们通过批量折扣与预留 GPU 算力实现这一点，再将节省的成本以更高的每月用量让渡给你。

对部分模型，我们尚无机会议定折扣或以更低成本部署它们——要么因为模型较新，要么因为其公开定价已经过折扣。

对于这些模型，你获得的用量仍略多于直接向模型提供商付费；这就是它们包含的每月用量较低的原因。

## 背景

开放模型已经变得非常出色。在编码任务上，它们的性能现已接近专有模型。由于多家提供商可以竞争性地提供这些模型，它们通常便宜得多。

然而，要获得可靠、低延迟的访问并不容易。各提供商在质量与可用性上参差不齐。

<Callout type="tip">我们测试了一组与 OpenCode 协作良好的精选模型与提供商。</Callout>

为解决这一问题，我们做了几件事：

1. 我们测试了一组精选的开放模型，并与其团队沟通如何以最佳方式运行它们。
2. 我们与若干提供商合作，确保这些模型被正确地提供服务。
3. 我们对模型/提供商的组合进行了基准测试，并整理出一份我们愿意推荐的列表。

Go 与 Go Plus 均提供对这些模型的访问；请选择与你的使用量相匹配的方案。

## 目标

我们创建 OpenCode Go 的目标是：

1. 以低成本的订阅，让更多人**能够使用** AI 编码。
2. **可靠**地提供对最佳开放编码模型的访问。
3. 精选针对编码智能体使用场景**经过测试与基准评估**的模型。
4. 通过允许你同时在 OpenCode 中使用任何其他提供商，做到**无锁定**。
