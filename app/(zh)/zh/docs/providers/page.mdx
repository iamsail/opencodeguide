OpenCode 内置了来自 [models.dev](https://models.dev) 的提供商与模型目录。对于大多数提供商，请先连接账户，然后选择模型。

## 设置

运行 `/connect`，选择提供商并输入其凭证。然后运行 `/models` 选择其中一个模型。

```text
/connect
/models
```

## Go

[OpenCode Go](/zh/docs/console/go) 是一项可选订阅，提供由 OpenCode 团队测试过的编程模型。在[控制台](https://opencode.ai/console)中订阅，复制你的 API 密钥，然后以 **OpenCode Go** 身份进行连接。

```text
/connect
# Select OpenCode Go, then paste your API key.
/models
```

参阅 [Go 指南](/zh/docs/console/go)了解用量限制、端点与隐私详情。

## ChatGPT

使用 ChatGPT Plus 或 Pro 计划代替 OpenAI API 密钥。连接 **OpenAI**，然后选择 **Sign in with ChatGPT** 或任一旧版 **Codex** 登录方式。用量计入你的订阅计划，因此这些模型不显示费用。

```text
/connect
/models
```

### 上下文限制

默认情况下，OpenCode 会将这些登录方式的上下文窗口上限设为低于各模型的真实上限。该上限与 Codex 的默认值一致，因此你的套餐用量消耗速率与其他 OpenAI 产品相近。

| 模型 | 输入上限 |
| --------------------- | ----------- |
| GPT-6.1 Sol 及更新版本 | 500,000 |
| 更早的模型 | 272,000 |

如需退出该行为，请在配置中禁用该上限插件。`-` 前缀表示关闭内置插件；其余插件保持启用。

```jsonc title="opencode.jsonc"
{
  "plugins": ["-opencode.provider.openai-context-caps"],
}
```

## 自定义

当某个提供商的 API 尚未收录在目录中时，可添加提供商。以下 OpenAI 兼容示例一并定义了凭证、运行时包、端点和首个模型。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "name": "Acme",
      "env": ["ACME_API_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://llm.acme.example/v1",
      },
      "models": {
        "qwen3-coder": {
          "name": "Qwen 3 Coder",
        },
      },
    },
  },
}
```

`providers` 对象以模型引用中使用的提供商 ID 作为键，例如 `acme/qwen3-coder`。

| 字段 | 用途 |
| --- | --- |
| `name` | 显示名称。 |
| `env` | 可提供凭证的环境变量名称，按优先顺序排列。 |
| `package` | 运行时提供商包。 |
| `canonical` | 内置提供商 ID，本提供商继承其目录默认值。 |
| `compatibility` | 应用于该提供商所有模型的请求与响应兼容性覆盖。模型的 `compatibility` 可覆盖个别字段。`supportsThinkingBlockBinding` 与 `supportsEffortUpdates` 仅限模型级。 |
| `settings` | 传递给运行时包的类型化 OpenCode 控件与 JSON 选项。 |
| `headers` | 添加到请求的字符串值 HTTP 头。 |
| `body` | 合并到请求体的 JSON 字段。 |
| `models` | 要添加或覆盖的模型，以 OpenCode 模型 ID 为键。 |

## 端点

覆盖 `settings.baseURL` 可让目录中的提供商经由代理或兼容端点发出请求。其现有的包、模型与连接仍然适用。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "anthropic": {
      "settings": {
        "baseURL": "https://llm-proxy.example.com/anthropic",
      },
    },
  },
}
```

`settings` 与具体包相关。只有当所选包支持该字段时才会生效。

## 请求

`headers` 用于附加 HTTP 头，`body` 用于应合并到每个请求体的 JSON 字段。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "headers": {
        "X-Gateway-Tenant": "engineering",
      },
      "body": {
        "metadata": {
          "application": "opencode",
        },
      },
    },
  },
}
```

当提供商仅有部分流量需要覆盖时，也可在模型或变体上设置这两个字段。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "headers": { "X-Model-Tier": "coding" },
          "variants": [
            {
              "id": "batch",
              "body": { "service_tier": "flex" },
            },
          ],
        },
      },
    },
  },
}
```

## 超时

HTTP 请求等待响应头最多五分钟，流式响应块之间最多十五分钟。将提供商的 `settings.headerTimeout` 或 `settings.chunkTimeout` 设为毫秒数可更改上限，设为 `false` 可禁用该限制。`settings.timeout` 额外限制从发送到响应完成的整个请求时长；它没有默认值。这些配置项在整个提供商范围内生效，而非按模型或变体生效。在 WebSocket 传输上，`chunkTimeout` 改为限制帧之间的间隔，默认为三十分钟。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "anthropic": {
      "settings": {
        "headerTimeout": 600000,
        "chunkTimeout": false,
      },
    },
  },
}
```

超过任一限制的请求将以传输错误失败。OpenCode 会对超时请求最多重试三次后放弃。

## 请求编码

`settings.encoding` 以 `"zstd"` 或 `"gzip"` 压缩 HTTP 请求体，或以 `"none"` 发送纯 JSON。可在提供商、模型或变体上设置；取最具体的值。仅启用端点能解码的编码：大多数提供商与网关会拒绝压缩请求体。在使用 ChatGPT 登录且未配置自定义 `baseURL` 时，OpenAI 默认为 `"zstd"`；API 密钥则发送纯 JSON。WebSocket 消息不受影响。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "encoding": "none" },
    },
  },
}
```

## 模型

在提供商的 `models` 映射中添加或覆盖模型。映射键是 OpenCode 使用的模型 ID；`modelID` 更改发送给提供商的 ID。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding",
  "providers": {
    "openai": {
      "models": {
        "coding": {
          "modelID": "gpt-6.1-sol",
          "name": "GPT-6.1 Sol Coding",
        },
      },
    },
  },
}
```

| 字段 | 用途 |
| --- | --- |
| `modelID` | 发送给提供商的模型或部署 ID。 |
| `name` | 显示名称。 |
| `family` | 用于对相关模型分组的模型系列。 |
| `releaseDate` | 发布日期，格式为 `YYYY-MM-DD` 或 `YYYY-MM`。 |
| `package` | 该模型的运行时覆盖。 |
| `settings` | 模型级 OpenCode 控件与包相关的 JSON 设置。 |
| `headers` | 额外的字符串值请求头。 |
| `body` | 额外的 JSON 请求体字段。 |
| `capabilities` | 工具支持、可接受的输入与输出媒体类型、温度支持，以及推理控件。 |
| `compatibility` | 请求与响应兼容性覆盖。 |
| `variants` | 具有各自 `settings`、`headers` 与 `body` 的命名变体。 |
| `cost` | 每百万 token 的输入、输出及可选缓存定价。 |
| `limit` | 上下文、输入与输出 token 上限。 |
| `disabled` | 为 `true` 时从可选列表中移除该模型。 |

参阅[模型](/zh/docs/configure/models)了解选择、默认值、能力、上限、费用与变体。

## Azure

Azure 的标准目录端点除凭证外还需要资源名称。设置一次 `settings.resourceName`，然后连接 API 密钥，或按[提供商账户](/zh/docs/cli/providers)所述使用来自 Azure CLI 的 Microsoft Entra ID 会话。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "azure": {
      "settings": {
        "resourceName": "my-models",
      },
    },
  },
}
```

可在 [Azure 门户](https://portal.azure.com/) 或 [Microsoft Foundry](https://ai.azure.com/) 中找到 **Resource name**。它也是端点的第一部分，例如 `https://my-models.openai.azure.com/` 与 `https://my-models.services.ai.azure.com/`。

```bash
az cognitiveservices account list \
  --query "[].{name:name,resourceGroup:resourceGroup}" \
  --output table
```

如需使用 Entra ID，请安装 [Azure CLI](https://learn.microsoft.com/en-us/cli/azure/install-azure-cli) 并登录，然后在连接 Azure 时选择 **Microsoft Entra ID (Azure CLI)**。

```bash
az login
```

若配置或环境尚未提供资源名称，请在连接时输入。随连接保存的资源名称优先于配置；如需更改请重新连接。

Azure CLI 连接使用 Azure CLI 中所选的账户。对于其他租户或订阅中的资源，请显式选择二者。

```bash
az login --tenant TENANT_ID
az account set --subscription NAME_OR_ID
```

`AZURE_RESOURCE_NAME` 可向 OpenCode 服务器提供资源名称，无需配置。旧版 `AZURE_COGNITIVE_SERVICES_RESOURCE_NAME` 变量同样有效。

### 部署

Azure 仅通过部署提供模型，因此 OpenCode 会列出你资源下的部署并显示它们，而非整个 Azure 目录。该列表会在启动后、连接后以及切换账户后于后台加载。若要纳入之后新增的部署，请重启 OpenCode 或重新连接。

- 在连接的列表加载完成之前，或加载失败时，整个目录保持可用。
- 同一连接的重新加载失败时，保留其上一次完整清单。
- 切换账户绝不会显示前一账户的清单；新账户从整个目录开始。
- 部署从其目录模型继承上限、费用与能力。

部署名称即其模型 ID，采用小写，因为 Azure 在名称中忽略大小写，例如 `azure/gpt-production`。以模型命名的部署（如 `gpt-6-luna`）保留目录 ID。当其他部署被添加或移除时，这些 ID 保持稳定。

OpenCode 通过部署所部署的模型将部署与目录匹配；当 Azure 对模型的拼写不同时（例如用 `gpt-4` 表示 GPT-4 Turbo），则按名称匹配。以其他模型命名的部署（例如部署 `gpt-6-luna` 的 `gpt-6.1-sol`）将显示该模型的名称、上限与费用。

使用 Azure CLI 时，OpenCode 通过 Azure 管理 API 列出部署，这需要对资源的读取权限。若失败，以及始终在使用 API 密钥的情况下，将使用该资源的旧版部署清单。发现过程会在发布列表前读取所有分页。自定义 `settings.baseURL` 时保留目录。

当部署的模型不在目录中（例如微调模型），或需自行将模型 ID 映射到部署时，请显式配置部署。OpenCode 会记录一条警告并指名这些部署。显式配置的模型始终保留。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "azure": {
      "models": {
        "gpt-6-luna": {
          "modelID": "gpt-production",
        },
      },
    },
  },
}
```

你的身份需要具备以下角色之一：

- 针对 Azure OpenAI 模型：**Cognitive Services OpenAI User**。
- 针对其他 Foundry 模型：**Cognitive Services User**。

如果请求使用了错误租户的令牌，请使用所需租户重新登录。

```bash
az login --tenant TENANT_ID
```

## Bedrock

Amazon Bedrock 使用 AWS 默认凭证链。命名的 AWS 配置文件是最简单的持久化设置；OpenCode 也识别访问密钥环境变量、Web 身份与容器凭证。

```bash
aws configure sso --profile work
aws sso login --profile work
```

在提供商设置中选择配置文件与区域。已配置的 `profile`、`AWS_PROFILE`、`AWS_ACCESS_KEY_ID`、Web 身份令牌文件或容器凭证 URI 会激活该提供商；仅有区域则不会。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "amazon-bedrock": {
      "settings": {
        "profile": "work",
        "region": "us-west-2",
      },
    },
  },
}
```

若未显式指定区域，OpenCode 依次使用 `AWS_REGION`、`AWS_DEFAULT_REGION`，最后为 `us-east-1`。对于私有或 VPC 端点，设置 `baseURL` 并保持相同的配置文件与区域。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "amazon-bedrock": {
      "settings": {
        "profile": "work",
        "region": "us-west-2",
        "baseURL": "https://bedrock-runtime.vpce.example.com",
      },
    },
  },
}
```

Bedrock API 密钥使用 `AWS_BEARER_TOKEN_BEDROCK`。其他 AWS 变量用于 SigV4，不会作为 OpenCode API 密钥账户存储。

## Vertex

Google Vertex 使用应用默认凭证（Application Default Credentials，ADC），并在其模型可用前需要一个项目。先创建本地 ADC，然后在提供商设置中设置项目与位置。

```bash
gcloud auth application-default login
```

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "google-vertex": {
      "settings": {
        "project": "my-project",
        "location": "us-central1",
      },
    },
  },
}
```

OpenCode 也会按 `GOOGLE_VERTEX_PROJECT`、`GOOGLE_CLOUD_PROJECT`、`GCP_PROJECT`、`GCLOUD_PROJECT` 的顺序解析项目。位置从 `GOOGLE_VERTEX_LOCATION`、`GOOGLE_CLOUD_LOCATION` 或 `VERTEX_LOCATION` 解析，默认为 `us-central1`。

```bash
GOOGLE_CLOUD_PROJECT=my-project GOOGLE_VERTEX_LOCATION=europe-west4 opencode --standalone
```

服务账号通过相同的 ADC 路径工作。将 `GOOGLE_APPLICATION_CREDENTIALS` 指向服务账号 JSON 文件，并仍通过设置或上述项目变量之一提供项目。

```bash
GOOGLE_APPLICATION_CREDENTIALS=/secure/vertex.json \
GOOGLE_CLOUD_PROJECT=my-project \
opencode --standalone
```

对 Gemini、Anthropic 与 OpenAI 兼容的 Vertex 目录模型，统一使用 `google-vertex` 提供商 ID。旧的 `google-vertex-anthropic` 提供商 ID 在 V2 中不可用。

## Copilot

GitHub Copilot 支持设备 OAuth，而非手动输入 API 密钥。连接 **GitHub Copilot**，选择 GitHub.com 或 GitHub Enterprise，完成设备流程，然后打开 `/models`。

```text
/connect
# Select GitHub Copilot, then Login with GitHub Copilot.
/models
```

对于 GitHub Enterprise，请在提示时输入部署 URL 或域名。若可用，OpenCode 使用 GitHub 返回的 Copilot API 端点；否则从企业域名推导端点。

```text
company.ghe.com
```

所连接的账户需要 Copilot Chat 访问权限。如果 GitHub 报告无相应权益，请注册 Copilot Free 或请组织分配 Copilot 席位，然后重新连接。OpenCode 会在登录后以及当前 Copilot 账户变更时获取该账户的当前模型列表。

## Ollama

启动 Ollama 并拉取模型。OpenCode 会探测 `http://127.0.0.1:11434`，发现补全模型，并无需连接账户即可将它们添加到 `/models`。

```bash
ollama serve
ollama pull qwen3:8b
```

使用 `settings.baseURL` 将 OpenCode 指向远程或代理的 Ollama 服务器。请包含 `/v1`；OpenCode 会据此推导原生的 `/api/tags` 与 `/api/show` 发现路径。`apiKey` 为可选项，会作为 bearer 令牌随发现与模型请求发送。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "https://ollama.example.com/v1",
        "apiKey": "{env:OLLAMA_API_KEY}",
      },
    },
  },
}
```

发现过程会定期刷新，并在临时故障期间保留上一次成功的清单。仅用于嵌入的模型不会出现，因为 OpenCode 只添加 Ollama 元数据中包含 `completion` 能力的模型。

## 运行时

LM Studio 与 vLLM 也具备内置的本地发现能力。它们的默认端点分别为 `http://127.0.0.1:1234/v1` 与 `http://127.0.0.1:8000/v1`。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "lmstudio": {
      "settings": { "baseURL": "http://gpu-host:1234/v1" },
    },
    "vllm": {
      "settings": { "baseURL": "http://gpu-host:8000/v1" },
    },
  },
}
```

LM Studio 从 `/api/v1/models` 发现语言模型。vLLM 会先检查 `/health` 再读取 `/v1/models`；其发现过程无法推断工具支持，因此发现的 vLLM 模型默认禁用工具。对于其他 OpenAI 兼容运行时，请使用[自定义提供商](#custom)方案并显式列出其模型。

## 网关

OpenRouter 使用其原生运行时与目录。向 OpenCode 服务器提供 `OPENROUTER_API_KEY` 或连接 OpenRouter 账户，然后在提供商前缀之后使用完整的 OpenRouter 模型 ID 引用模型。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openrouter/anthropic/claude-sonnet-5.5",
}
```

覆盖其端点或通过 OpenRouter 兼容网关路由时，请保留原生 OpenRouter 包。这会保留 OpenRouter 的请求与推理行为。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openrouter": {
      "settings": {
        "baseURL": "https://openrouter-gateway.example.com/api/v1",
      },
      "headers": {
        "X-Gateway-Tenant": "engineering",
      },
    },
  },
}
```

对于暴露 OpenAI 兼容 API 但拥有自身模型清单的网关，请改为定义自定义提供商。配置键成为提供商前缀，每个 `models` 键成为可选的模型 ID。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "company/coder",
  "providers": {
    "company": {
      "env": ["COMPANY_GATEWAY_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://gateway.example.com/v1",
      },
      "models": {
        "coder": { "modelID": "upstream/coder-v2" },
      },
    },
  },
}
```

## 错误

提供商与模型错误通常会指明失败的阶段。在更改包之前，请检查服务器进程环境与确切的模型 ID。

| 错误或症状 | 检查 |
| --- | --- |
| `No model is available for session ...` | 当前没有可选的已启用模型。完成提供商相关设置，然后在 `/models` 中选择模型。 |
| `Model unavailable: provider/model` | 提供商未激活、模型 ID 不存在或已禁用，或动态发现不再返回该模型。对于自定义别名，请检查 `models` 映射键而非 `modelID`。 |
| `Cannot initialize provider/model: NAME is required to resolve the provider endpoint` | `baseURL` 中仍存在 `${NAME}` 占位符。请在 OpenCode 服务器上设置该变量，或将模板替换为完整端点。 |
| `Azure resource name is missing` | 设置 `providers.azure.settings.resourceName`、`AZURE_RESOURCE_NAME`，或完整的 `settings.baseURL`。 |
| Vertex 未出现 | 在提供商设置或受支持的项目变量中设置可解析的项目。仅有 ADC 不会激活该提供商。 |
| Bedrock 未出现 | 提供配置文件或其他受支持的 AWS 凭证链输入。仅有 `AWS_REGION` 只会选择区域。 |
| Ollama 没有模型 | 确认服务器在由 `baseURL` 推导的路径上暴露 `/api/tags` 与 `/api/show`，且 `/api/show` 报告 `completion` 能力。 |
| Copilot 没有模型 | 确认当前 OAuth 账户具有 Copilot Chat 访问权限。模型同步失败会记录为 `failed to sync GitHub Copilot models`。 |

V2 会拒绝已弃用的提供商 ID，并给出直接替代方案。请使用 `azure/<model>` 代替 `azure-cognitive-services/<model>`，使用 `google-vertex/<model>` 代替 `google-vertex-anthropic/<model>`。

## WebSockets

OpenAI、xAI 与受支持的 Azure Responses 模型可为每个会话保持一条 WebSocket 连接。连续步骤会复用未变更的请求前缀，仅发送自上一次响应以来新增的内容，从而减少长会话中的上传量。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "transport": "http" },
    },
  },
}
```

WebSocket 行为遵循以下规则：

- 内置提供商依据各自策略选择支持的路由启用该能力。
- 提供商的 `settings.transport: "websocket"` 启用该能力；`"http"` 禁用该能力。
- 在没有 WebSocket 通道的路由上使用 `"websocket"` 会记录警告并回退到 HTTP。
- OpenAI 提供商的上下文压缩使用同一连接。
- xAI 仅从已存储的响应继续。在其默认的 `store: false` 下，每一步都通过复用的连接完整发送。
- 已关闭的套接字会在下一步重连。若连接无法建立，会话将通过 HTTP 继续。
- 具有 `http.request` 或 `http.response` 钩子的提供商插件保持使用 HTTP，以便每个请求仍可观测。
