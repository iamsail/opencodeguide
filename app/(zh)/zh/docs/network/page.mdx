设置标准代理变量并排除回环地址。OpenCode 使用 CLI 与其后台服务之间的本地 HTTP 连接，因此在 CLI 环境中配置代理时必须排除回环地址。

```bash
export HTTP_PROXY=http://proxy.example.com:8080
export HTTPS_PROXY=http://proxy.example.com:8080
export NO_PROXY=localhost,127.0.0.1,::1

opencode
```

`HTTP_PROXY` 处理 HTTP 目标，`HTTPS_PROXY` 处理 HTTPS 目标。代理 URL 本身对这两个变量都可以使用 `http://`。`NO_PROXY` 是以逗号分隔的主机名和地址列表，这些目标将直接连接。

## 服务

Shell 导出的环境变量仅在后台服务从该 shell 启动时才会生效。请将变量持久化到受管理的服务配置中，以便后续服务启动时使用相同的网络设置。

```bash
opencode service set env HTTP_PROXY http://proxy.example.com:8080
opencode service set env HTTPS_PROXY http://proxy.example.com:8080
opencode service set env NO_PROXY localhost,127.0.0.1,::1
opencode service start
```

更改受管理的环境变量会停止正在运行的服务。`service start` 会使用新环境重新启动它。当 CLI shell 设置了代理时，也请在该 shell 中保留 `NO_PROXY`，因为受管理的服务变量作用于服务器进程，而非 CLI 进程。

使用 `service unset env` 移除已持久化的变量：

```bash
opencode service unset env HTTPS_PROXY
```

## 身份验证

对于接受 URL 凭据的代理，请在每个需要身份验证的代理 URL 中包含用户名和密码。对任一凭据中的 `@`、`:` 和 `/` 等字符进行百分号编码。

```bash
export HTTPS_PROXY='http://user:p%40ssword@proxy.example.com:8080'
```

对于后台服务，请持久化完整 URL。该值存储在私有服务配置中，并会由 `opencode service get env` 显示，因此请勿分享该输出。

```bash
opencode service set env HTTPS_PROXY 'http://user:p%40ssword@proxy.example.com:8080'
```

## 证书

当代理或目标使用由私有证书颁发机构签名的证书时，请将 `NODE_EXTRA_CA_CERTS` 设置为 PEM 文件。进程启动时，这些额外的颁发机构会被添加到运行时信任库。

```bash
export NODE_EXTRA_CA_CERTS=/etc/company/ca.pem
opencode --standalone
```

为后台服务持久化该文件路径，然后重启服务：

```bash
opencode service set env NODE_EXTRA_CA_CERTS /etc/company/ca.pem
opencode service start
```

## 前台

`--standalone` 和 `serve` 使用其自身进程的环境。`opencode service set env` 不会配置这些进程。

```bash
HTTP_PROXY=http://proxy.example.com:8080 \
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode --standalone
```

对前台服务器应用相同的模式：

```bash
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode serve
```

## 验证

应用设置后，检查 CLI 能否访问后台服务：

```bash
opencode api get /api/info
```

成功的健康检查响应可验证本地客户端到服务的连接。发起一次正常的提供商请求，以验证服务的出站代理和证书路径。
