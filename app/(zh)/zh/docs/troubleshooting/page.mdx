<Callout type="tip">
  你可以让 OpenCode 自行调试。描述问题，并要求它使用本故障排除页面；它可以阅读以下步骤、检查其服务与日志，并帮助定位问题。
</Callout>

OpenCode 采用客户端-服务器架构。后台服务持有会话、插件、权限及其他应用状态。排查时请先判断问题出在客户端、共享服务，还是特定项目。

## 检查后台服务

显示当前服务信息：

```bash
opencode service status
```

验证其 API 是否健康：

```bash
opencode api get /api/info
```

如果服务卡住或不健康，重启它：

```bash
opencode service restart
```

也可以显式停止并启动：

```bash
opencode service stop
opencode service start
```

<Callout type="note">
  OpenCode 通常会自动发现或启动共享的后台服务。仅在诊断服务生命周期时才需要这些服务命令。
</Callout>

## 允许浏览器来源

如果其他来源的浏览器客户端因 CORS 无法连接，请将该客户端的来源添加到服务配置中：

```bash
opencode service set cors http://192.168.1.10:3001
opencode service get cors
```

请使用精确的 HTTP 或 HTTPS 来源，必要时包含端口，且不含路径或结尾斜杠。要允许多个来源，请以单个参数传入以逗号分隔的列表；每个来源前后的空白会被去除：

```bash
opencode service set cors "http://192.168.1.10:3001, https://app.example.com"
```

`service get cors` 会打印一个 JSON 数组。使用以下命令移除已配置的列表：

```bash
opencode service unset cors
```

设置或取消设置服务配置会停止后台服务。下次启动时会读取新配置；使用 `opencode service start` 可显式启动。

对于前台服务器，为每个额外允许的来源重复 `--cors`：

```bash
opencode serve --cors http://192.168.1.10:3001 --cors https://app.example.com
```

使用 `serve --service` 时，提供的 `--cors` 标志会覆盖该进程的持久化列表。若不提供这些标志，服务模式将使用持久化列表。CORS 不会改变监听地址，也不会绕过服务端认证。

## 检查 API

`api` 命令使用本地服务发现与认证流程。它接受 HTTP 方法与路径，或 OpenAPI 操作 ID。

有关全部端点与操作 ID，请参阅 [API 参考](https://opencode.ai/v2/docs/api)。

使用 `--data` 或 `-d` 传递 JSON 请求体，使用 `--header` 或 `-H` 添加请求头。

<Callout type="warning">
  当没有兼容的健康服务可用时，运行 `opencode api` 可能会启动后台服务。
</Callout>

## 读取日志

已安装的构建会将日志写入：

```text
~/.local/share/opencode/log/opencode.log
```

复现问题时跟踪日志：

```bash
tail -f ~/.local/share/opencode/log/opencode.log
```

每行都包含进程 `run` ID 和 `role` 字段。使用 `role=server` 查看会话、提供商、插件、权限与工具相关活动。

```bash
grep 'role=server' ~/.local/share/opencode/log/opencode.log
grep 'run=8fc3b1d5' ~/.local/share/opencode/log/opencode.log
```

## 捕获堆快照

在任意平台上为正在运行的后台服务写入内存（堆）快照：

```bash
opencode debug heap-dump
```

该命令会等待快照完成，然后打印其路径：

```text
/home/me/.local/share/opencode/log/heap-48213-2026-10-23T013012345Z.heapsnapshot
```

使用 `--directory` 可将快照写入其他位置。若目录不存在，服务会创建它：

```bash
opencode debug heap-dump --directory ./snapshots
```

- 它只使用已在运行的服务。绝不会启动、替换或重启服务。
- 使用 `--server <url>` 可捕获你通过 `opencode serve` 启动的服务器。若其设置了密码，请设置 `OPENCODE_PASSWORD`。此时 `--directory` 是服务器所在机器上的路径。
- 在 Chrome DevTools 的 Memory 面板中打开该文件。

<Callout type="warning">
  服务在写入快照期间会暂停，其内存占用可能短时上升。快照可能包含提示词、文件内容与凭据。请勿公开分享。
</Callout>

### 在桌面应用中

从命令面板运行 **捕获堆快照**。它会在你的下载文件夹中写入一个文件夹，内含应用各部分的快照，以及快照无法展示的内存明细：

```text
opencode-heap-2026-10-23T013012345Z/
  memory.json                  where the memory is, per process, in MiB: start here
  memory-infra.json            Chromium's memory dump trace; open it in https://ui.perfetto.dev
  heap-48213-….heapsnapshot    the desktop's own server
  window-1-48390.heapsnapshot  one per app window
  main-48102.heapsnapshot      the desktop main process
  gpu.json                     the GPU and driver
  manifest.json                processes, PIDs, and memory before and after; written last
```

- 堆快照只包含 JavaScript 对象与页面。图像、布局、合成器层与 GPU 内存则记录在 `memory.json` 与 `memory-infra.json` 中。
- 不会捕获远程服务器。请改为在该机器上使用 `opencode debug heap-dump`。
- 服务会直接将快照写入该文件夹，因此不会移动或复制大文件。
- 不包含浏览器标签页，因为其快照会包含你访问过的页面内容。

## 捕获 CPU 与内存分析数据

在 macOS 与 Linux 上，可以向运行中的 OpenCode 进程发送信号以捕获诊断数据。从健康端点获取后台服务 PID：

```bash
opencode api get /api/info
```

将响应中的 `pid` 与以下信号之一配合使用：

- `SIGPROF` 会捕获十秒的 CPU 分析数据：

  ```bash
  kill -SIGPROF <pid>
  ```

  结果以 `cpu-<pid>-<timestamp>.cpuprofile` 的形式写入日志目录。

- `SIGUSR1` 会捕获内存（堆）快照：

  ```bash
  kill -SIGUSR1 <pid>
  ```

  结果以 `heap-<pid>-<timestamp>.heapsnapshot` 的形式写入日志目录。

打开文件前，请等待 `opencode.log` 中出现 `CPU profile written` 或 `heap snapshot written`。对应的日志条目包含完整路径。这两种文件都可以在 Chrome DevTools 中查看。

<Callout type="note">
  Windows 上不支持通过信号触发的分析数据。请改用 `opencode debug heap-dump` 捕获堆快照。写入堆快照可能会暂停进程，并暂时增加其内存占用。
</Callout>

## 服务文件

共享服务会将自己注册于：

```text
~/.local/state/opencode/service.json
```

其私有服务配置单独存储于：

```text
~/.config/opencode/service.json
```

数据库通常位于：

```text
~/.local/share/opencode/opencode.db
```

`OPENCODE_DB` 可覆盖数据库位置。

<Callout type="warning">
  排查期间请勿删除或编辑服务文件或数据库。请使用服务命令管理守护进程，并在使用外部工具检查持久化数据前先进行备份。
</Callout>

## 报告问题

报告可复现的问题时，请附上以下内容：

- `opencode --version` 的输出
- `opencode service status` 的输出
- 能复现该问题的最少步骤序列
- 该问题影响的是共享服务、特定客户端，还是某个项目
- 相关日志行，包括其 `run` 与 `role` 字段

分享日志前，请移除 API 密钥、授权请求头、提示词、文件内容及其他敏感数据。

可复现的问题请提交至 [GitHub Issues](https://github.com/anomalyco/opencode/issues)。
