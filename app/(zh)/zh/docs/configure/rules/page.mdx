添加一个 `AGENTS.md` 文件，为 OpenCode 提供持久的项目指导。可在其中记录构建命令、架构说明、代码约定与验证要求。

```md title="AGENTS.md"
# Project instructions

- Run `bun typecheck` after changing TypeScript.
- Keep database queries in `src/database`.
- Do not edit generated files directly.
```

将项目指令文件提交到版本库，以便在该仓库中工作的每个人都能获得相同的指导。

## 作用域

将 `AGENTS.md` 放在其指导内容应当生效的目录中。OpenCode 会先加载全局文件，然后从当前工作区目录向 home 目录方向加载每一个 `AGENTS.md`。对于 home 目录之外的工作区，加载会止于项目根目录。

```text
~/.config/opencode/AGENTS.md
~/code/my-project/AGENTS.md
~/code/my-project/packages/AGENTS.md
~/code/my-project/packages/web/AGENTS.md  ← current workspace
```

在本例中，四个文件都会被加载。它们按以下顺序合并：

```text
~/.config/opencode/AGENTS.md
packages/web/AGENTS.md
packages/AGENTS.md
AGENTS.md
```

将适用于所有场景的指导放在全局文件中。将适用于整个仓库的指导放在项目根目录，越具体的指导越靠近其所覆盖的代码。OpenCode 会合并这些文件，且不会解析它们之间的冲突。

如果工作区位于项目根目录之外，则只加载全局文件。设置 `OPENCODE_DISABLE_PROJECT_CONFIG=1` 可以跳过项目 `AGENTS.md` 的发现，而不禁用全局文件。

<Callout type="note">
  OpenCode V2 仅识别 `AGENTS.md`。它不会将 `CLAUDE.md` 作为回退。
</Callout>

## 发现

工作区之下的指令文件会在智能体（agent）探索项目时被发现。读取某个文件或列出某个目录时，会加载该目标与工作区之间的所有 `AGENTS.md` 文件。

```text
my-project/                         ← current workspace
├── AGENTS.md                       loaded initially
└── packages/
    └── web/
        ├── AGENTS.md               loaded when this area is read
        └── src/
            └── app.ts              read target
```

嵌套文件按由近及远的顺序加载，并在其指令条目仍保留在模型可见历史中时去重。再次读取同一区域通常不会重新注入这些文件。如果上下文压缩（compaction）或回退移除了该条目，则后续读取可以再次加载该文件。

嵌套文件加载后，对其的编辑不会被自动检测到。若更新后的文本必须立即生效，请开启新的会话。

## 排序

首先发送所选智能体或提供商的系统提示。随后 OpenCode 按以下顺序组装初始指令：

```text
1. Agent or provider system prompt
2. Code Mode tool guidance, when enabled
3. MCP server, reference, and skill guidance
4. Global and project AGENTS.md files, then configured instructions
5. Built-in date and environment context
6. Session-specific instruction entries supplied through the API
```

这些来源会被合并使用，而不是相互覆盖。随后发现的嵌套 `AGENTS.md` 文件会按发现顺序添加到会话历史中。

## 更新

在会话运行期间编辑全局的或向上发现的 `AGENTS.md`，即可更新其指导内容。

```bash
$ printf '\n- Run the integration suite before committing.\n' >> AGENTS.md
```

在下一次模型请求之前，OpenCode 会检测到该变更，并在传递待处理输入之前添加一次指令更新：

```text
AGENTS.md changes
→ instruction update
→ next prompt
```

- 移除所有环境 `AGENTS.md` 会告知会话：先前的环境指令不再适用。
- 临时读取失败会保留最后已知的指令，而不会将其视为已删除。
- 移动会话会保留其指令状态，因此目标位置的指导会以更新的形式引入。
- 提交会话回退会清除其指令状态，并在下一次提示之前重新加载指令。

指令值仍然具有特权。客户端可以查看哪些来源发生了变更，但无法查看其内容。

## 配置

使用 `instructions` 数组，可在已发现的 `AGENTS.md` 文件之外添加文件、glob 模式或 HTTP(S) URL：

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": [
    "CONTRIBUTING.md",
    "docs/guidelines/*.md",
    "~/rules/opencode.md",
    "https://example.com/instructions.md",
  ],
}
```

配置的指令会在 `AGENTS.md` 文件之后按列出顺序加载。每个配置文档中的条目都会被合并。

| 条目                    | 解析方式                                                             |
| ----------------------- | -------------------------------------------------------------------- |
| 相对路径或 glob         | 从工作区到项目根目录的每个目录中进行搜索                             |
| `~/` 路径               | 从你的 home 目录解析                                                 |
| 绝对路径                | 按原样使用；文件名可以是 glob                                        |
| `http://` 或 `https://` | 在配置加载时获取，超时时间为 5 秒                                    |

- 本地文件在变更时会像 `AGENTS.md` 一样更新。与 glob 匹配的新文件会在下一次配置变更时加载。
- 缺失的文件会被跳过。无法获取的 URL 会被跳过，或保留其最近一次获取的内容。
- 当设置了 `OPENCODE_DISABLE_PROJECT_CONFIG=1`，或工作区位于项目之外时，相对条目会相对于全局配置目录解析。

配置位置与优先级请参见[配置](/zh/docs/config)。
