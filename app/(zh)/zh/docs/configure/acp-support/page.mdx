`opencode acp` 将 OpenCode 作为 [Agent Client Protocol](https://agentclientprotocol.com) 智能体运行，因此你可以从 Zed 等 ACP 客户端中使用它。以下示例将 OpenCode 添加到 Zed：

```json title="~/.config/zed/settings.json"
{
  "agent_servers": {
    "OpenCode": {
      "command": "opencode",
      "args": ["acp"]
    }
  }
}
```

其他 ACP 客户端使用相同的命令和 `acp` 参数，但配置文件与字段名可能不同。如果图形化客户端找不到 `opencode`，请将 `command` 设置为 `which opencode` 输出的绝对路径。

## 身份验证

OpenCode 使用已有的提供商凭据。请在启动 ACP 客户端之前先在终端中登录：

```bash
opencode auth login
```

OpenCode 提供一种身份验证方法 `opencode-login`。默认情况下它是一种智能体身份验证方法。`authenticate` 请求只接受该方法，且不收集凭据。如果某个提示因提供商需要身份验证而失败，OpenCode 会返回 ACP 的 `auth_required` 错误。

如果客户端将 `clientCapabilities.auth.terminal` 设为 `true`，该身份验证方法即为终端身份验证方法：

```json
{
  "id": "opencode-login",
  "name": "Login with opencode",
  "description": "Run `opencode auth login` in the terminal",
  "type": "terminal",
  "args": ["--login"]
}
```

客户端不得将此方法发送给 `authenticate`。相反，它应在启动 OpenCode 的命令中加入 `--login`（例如 `opencode acp --login`），并在终端中运行。OpenCode 会执行 `opencode auth login` 流程后退出。退出状态 0 表示登录成功。随后客户端重新连接并再次发送 `initialize`。

如果客户端将 `clientCapabilities._meta["terminal-auth"]` 设为 `true`，该身份验证方法会包含登录命令：

```json
{
  "id": "opencode-login",
  "name": "Login with opencode",
  "description": "Run `opencode auth login` in the terminal",
  "_meta": { "terminal-auth": { "command": "opencode", "args": ["auth", "login"], "label": "OpenCode Login" } }
}
```

## 故障排查

`opencode acp` 在 stdin 上等待 ACP 消息，因此直接在终端中运行时看起来像是卡住了。请改为从 ACP 客户端启动它。

如果客户端报告进程已退出或写入了无效的协议输出，请在客户端参数中的 `acp` 之前加入 `--print-logs`。此后 OpenCode 会将其 ACP 与私有服务器日志写入 stderr。stdout 仅承载 ACP 消息。

```bash
opencode --print-logs acp
```

## 协议参考

本节面向 ACP 客户端作者，列出 OpenCode 所支持的 ACP 各部分，以及 OpenCode 新增的 `_meta` 键。无法识别这些键的客户端可以忽略它们。消息定义见 [ACP 文档](https://agentclientprotocol.com)。

### 传输

客户端以子进程方式启动 `opencode acp`。双方通过 stdin 与 stdout 交换以换行符分隔的 JSON-RPC 消息，使用 ACP 协议版本 1。

`opencode acp` 会启动一个仅供自身使用的私有 OpenCode 服务器。它不连接共享的后台服务，也不为 ACP 打开网络端口。一个进程可以服务多个 ACP 会话。当客户端关闭 stdin 时它退出。

### 能力

OpenCode 的 `initialize` 响应包含以下智能体能力：

```json
{
  "loadSession": true,
  "mcpCapabilities": { "http": true, "sse": false },
  "promptCapabilities": { "embeddedContext": true, "image": true },
  "sessionCapabilities": {
    "additionalDirectories": {},
    "close": {},
    "delete": {},
    "fork": {},
    "list": {},
    "resume": {}
  }
}
```

OpenCode 读取以下客户端能力：

| 能力                                   | 效果                                                             |
| -------------------------------------- | ---------------------------------------------------------------- |
| `auth.terminal` 设为 `true`            | 该身份验证方法是[终端身份验证方法](#authentication)。            |
| `elicitation.form`                     | OpenCode 以表单形式提出[问题](#questions)。                      |
| `session.compaction`                   | OpenCode 通过 ACP 的更新报告[上下文压缩](#compaction)。          |
| `_meta["terminal-auth"]` 设为 `true`   | 该身份验证方法包含[登录命令](#authentication)。                  |

### 会话

客户端在创建会话时设置工作目录。OpenCode 使用该目录的配置，包括其模型、智能体、命令、技能、指令、插件与 MCP 服务器。

- `cwd` 必须是绝对路径。OpenCode 会以 invalid params 错误拒绝相对路径的 `cwd`。
- `session/load` 会重放已保存的消息。`session/resume` 与 `session/fork` 不会重放它们。
- 要加载、恢复或分叉某个会话，客户端必须将该会话的目录作为 `cwd` 传入。OpenCode 会以 invalid params 错误拒绝不同的 `cwd`。
- `session/list` 每页最多返回 100 个会话。它接受 `cwd` 过滤器与 `cursor`。
- `session/close` 会中断进行中的工作，并将会话从 ACP 进程分离。OpenCode 保留已保存的会话。
- `session/delete` 会像 `session/cancel` 一样结束进行中的提示，然后移除该会话。删除不存在的会话会成功。
- 一个会话一次只运行一个提示。当第一个提示仍在进行时，OpenCode 会对第二个 `session/prompt` 返回错误。

### 取消

`session/cancel` 以 `stopReason: "cancelled"` 结束进行中的提示。针对该提示请求的 `$/cancel_request` 作用相同。OpenCode 会拒绝挂起的权限请求。取消后未完成的工具调用会被报告为 `failed`。

### 附加目录

客户端可以在 `session/new`、`session/load`、`session/resume` 与 `session/fork` 上传递 `additionalDirectories`：

```json
{ "cwd": "/work/app", "additionalDirectories": ["/work/shared"], "mcpServers": [] }
```

- 每一项必须是绝对路径，且不含 `*` 或 `?`。
- OpenCode 允许在每个根目录内访问外部目录。读取、编辑与 shell 权限规则仍然适用。
- 如[附加目录 RFD](https://agentclientprotocol.com/rfds/additional-directories) 所规定，每个请求中的列表会替换该会话之前的列表。
- OpenCode 将这些授权存储在会话上，因此当另一个 OpenCode 客户端使用该会话时它们同样适用。OpenCode 创建子会话时会复制这些授权。

`session/list` 在 `additionalDirectories` 中返回每个会话存储的列表。

### 配置选项

新会话使用该目录的默认模型与主智能体。对 `session/new`、`session/load`、`session/resume` 与 `session/fork` 的响应包含以下配置选项：

| ID       | 类别             | 取值                                                                          |
| -------- | ---------------- | ----------------------------------------------------------------------------- |
| `model`  | `model`          | 已启用的模型，格式为 `provider/model`。`/variant` 后缀还会设置 effort。       |
| `effort` | `thought_level`  | 该模型的变体与 `default`。仅对具有变体的模型出现。                            |
| `mode`   | `mode`           | 可见的主智能体。                                                              |

`session/set_config_option` 接受字符串值：

```json
{ "sessionId": "ses_123", "configId": "model", "value": "anthropic/claude-sonnet-5-5" }
```

`session/set_mode` 也会设置智能体。当可用的模型或智能体发生变化时，OpenCode 会发送 `config_option_update`。当另一个客户端更改了该会话的模型或智能体时，它也会发送一次。

### 提示内容

提示可以包含文本、图像、嵌入资源与资源链接。OpenCode 忽略音频块。对其他块的处理方式如下：

| 块                                                     | OpenCode 的处理方式                                                                  |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| `text`                                                 | 将其发送给模型。                                                                     |
| 仅面向 `assistant` 的 `text`                           | 作为独立上下文发送给模型，置于用户消息之外。                                         |
| 仅面向 `user` 的 `text`                                | 不将其纳入模型的输入。                                                               |
| 含 `data` 的 `image`                                   | 将其附加到提示。                                                                     |
| 仅含 `uri` 的 `image`                                  | 将其作为资源链接处理。                                                               |
| 含 `text` 的 `resource`                                | 将文本内联在该资源的路径或 URI 之后。                                                |
| 含 `blob` 的 `resource`                                | 如果带有 `mimeType` 则附加，否则丢弃。                                               |
| 指向 `file://` URI 的 `resource_link`                  | 附加该文件。如果文件缺失或不可读，则改为发送 Markdown 链接。                         |
| 指向带 `path` 查询的 `zed://` URI 的 `resource_link`    | 附加 `path` 处的文件。                                                               |
| 指向其他 URI 的 `resource_link`                        | 发送 Markdown 链接，例如 `[spec](https://example.com/spec.md)`。                     |

受众来自块的 `annotations`。OpenCode 会拒绝既没有 `data` 也没有 `uri` 的 `image` 块。以下块仅作为模型的上下文：

```json
{ "type": "text", "text": "Open file: src/app.ts", "annotations": { "audience": ["assistant"] } }
```

### 命令

在 `session/new`、`session/load`、`session/resume` 或 `session/fork` 之后，OpenCode 会发送 `available_commands_update`，其中包含该目录的命令与内置的 `compact` 命令。当命令发生变化时，它会再发送一次更新。

```json
{
  "sessionUpdate": "available_commands_update",
  "availableCommands": [{ "name": "compact", "description": "Compact the session" }]
}
```

如果提示以 `/` 加某个可用命令的名称开头，OpenCode 会运行该命令，并将其余文本作为参数。OpenCode 会把其他以 `/` 开头的文本作为普通提示发送。`/compact` 运行[上下文压缩](/zh/docs/configure/compaction)。

### MCP 服务器

客户端可以在 `session/new`、`session/load`、`session/resume` 与 `session/fork` 上传递 stdio 与 HTTP MCP 服务器。OpenCode 会在 `opencode acp` 进程的存续期内将它们添加到该会话的目录，因此该目录中的其他会话可以使用它们。OpenCode 会透传 HTTP 头，且不对这些服务器使用 OAuth。它不广播基于 SSE 的 MCP，也不支持基于 ACP 的 MCP。

| 情况                         | 行为                                                             |
| ---------------------------- | ---------------------------------------------------------------- |
| 与已配置服务器同名           | 客户端的服务器会在该目录中替换已配置的那个。                     |
| [策略](/zh/docs/configure/policies) | `integration.use` 规则仍然适用。                          |

```json
{ "type": "http", "name": "docs", "url": "https://mcp.example.com", "headers": [] }
```

### 权限

权限请求提供三个选项：

```json
[
  { "optionId": "once", "kind": "allow_once", "name": "Allow once" },
  { "optionId": "always", "kind": "allow_always", "name": "Always allow" },
  { "optionId": "reject", "kind": "reject_once", "name": "Reject" }
]
```

当请求会更改文件时，如果 OpenCode 能够构建该变更的预览，就会包含 `diff` 内容。

### 问题

如果客户端声明支持 `elicitation/form`，OpenCode 会以表单模式通过 `elicitation/create` 提出问题。当 OpenCode 已将该工具调用作为本会话的 `session/update` 发送时，请求会包含 `toolCallId`。

```json
{
  "mode": "form",
  "sessionId": "ses_123",
  "toolCallId": "call_1",
  "message": "Which package manager?",
  "requestedSchema": {
    "type": "object",
    "properties": { "pm": { "type": "string", "oneOf": [{ "const": "bun", "title": "Bun" }] } },
    "required": ["pm"]
  }
}
```

- OpenCode 从不发送可能收集机密信息的表单。
- 如果某个字段除选项外还接受键入的答案，schema 会添加一个可选的 `<key>_custom` 字符串属性。对于单选，非空的自定义答案会替换所选选项；对于多选，OpenCode 会将其加入所选项。
- 如果用户拒绝或取消该表单，OpenCode 会取消该问题。

如果 OpenCode 无法显示问题，它会取消该问题，并告知模型在没有答案的情况下继续。

### 上下文压缩

如果客户端声明支持 `session.compaction`，OpenCode 会使用 ACP 处于 Preview 阶段的[会话上下文压缩](https://agentclientprotocol.com/rfds/session-compaction) RFD 中的 `compaction_update` 与 `compaction_summary_chunk` 更新来报告上下文压缩。当客户端加载会话时，OpenCode 会将每次已完成或已失败的上下文压缩作为一条更新重放。

```json
{
  "sessionUpdate": "compaction_update",
  "compactionId": "msg_123",
  "status": "completed",
  "summary": [{ "type": "text", "text": "..." }]
}
```

其他客户端改为接收[上下文压缩标记](#compaction-marker)。子会话的上下文压缩也是如此。

### 用量

提示响应包含来自仍处于草案阶段的[结束轮次用量](https://agentclientprotocol.com/rfds/end-turn-token-usage) RFD 的 `usage`。`usage` 汇总本会话中该提示的模型调用，不包含子会话。

```json
{ "stopReason": "end_turn", "usage": { "inputTokens": 1200, "outputTokens": 340, "totalTokens": 1540 }, "_meta": {} }
```

在响应之前，OpenCode 会发送来自[会话用量](https://agentclientprotocol.com/rfds/session-usage) RFD 的 `usage_update`。仅当该提示消耗了 token 且 OpenCode 已知模型的上下文大小时才会发送。`cost` 是该会话以 USD 计的总费用。

```json
{ "sessionUpdate": "usage_update", "used": 1540, "size": 200000, "cost": { "amount": 0.012, "currency": "USD" } }
```

### 子会话

当提示运行时，OpenCode 会将其子会话的更新作为该提示所在会话上的 `session/update` 通知发送。每条更新都带有 `_meta["opencode/child-session"]`。OpenCode 在工具调用 ID 前加上 `<childSessionId>:` 前缀。如果子会话有标题，它还会在工具调用标题前加上该子会话的标题。

```json
{
  "sessionUpdate": "tool_call",
  "toolCallId": "ses_child:call_1",
  "title": "Explore the codebase: src/app.ts",
  "_meta": {
    "opencode/child-session": { "id": "ses_child", "parentID": "ses_123", "depth": 1, "title": "Explore the codebase" }
  }
}
```

| 字段       | 类型     | 描述                                                                                 |
| ---------- | -------- | ------------------------------------------------------------------------------------ |
| `id`       | `string` | 子会话的 ID。                                                                        |
| `parentID` | `string` | 该子会话的父会话 ID。                                                                |
| `depth`    | `number` | 提示所在会话的子会话为 1，该子会话的子会话为 2，依此类推。                           |
| `title`    | `string` | 子会话的标题。当子会话没有标题时，OpenCode 会省略它。                                |

来自子会话的权限请求会在 `toolCall._meta` 上携带相同的键。提示结束后，OpenCode 停止发送子会话更新。来自子会话的权限请求与问题仍会到达客户端。

### 重试状态

当模型调用失败且 OpenCode 安排了重试时，它会发送带有 `_meta["opencode/retry"]` 的 `session_info_update`。重试开始时，OpenCode 发送 `"opencode/retry": null`。当提示响应到达时，请清除任何重试状态。

```json
{
  "sessionUpdate": "session_info_update",
  "_meta": {
    "opencode/retry": {
      "attempt": 1,
      "nextRetryAt": "2026-10-02T12:00:05.000Z",
      "error": { "type": "provider.rate-limit", "message": "Rate limit exceeded", "status": 429 }
    }
  }
}
```

| 字段           | 类型     | 描述                                                                                   |
| -------------- | -------- | -------------------------------------------------------------------------------------- |
| `attempt`      | `number` | 重试的尝试次数编号。                                                                   |
| `nextRetryAt`  | `string` | 下一次尝试的时间，ISO 8601 格式。                                                      |
| `error`        | `object` | 包含 `type` 与 `message`。如果提供商发送了 `status` 与 `response.body`，也会包含它们。  |

### 上下文压缩标记

如果客户端未声明支持 `session.compaction`，OpenCode 会以带有 `_meta["opencode/compaction"]` 的 `session_info_update` 报告上下文压缩进度。对于子会话的上下文压缩，OpenCode 始终使用该标记。

```json
{
  "sessionUpdate": "session_info_update",
  "_meta": { "opencode/compaction": { "status": "started", "messageId": "msg_123", "reason": "auto" } }
}
```

| 字段        | 类型     | 描述                                                                             |
| ----------- | -------- | -------------------------------------------------------------------------------- |
| `status`    | `string` | `started`、`completed` 或 `failed`。被取消的上下文压缩为 `failed`。              |
| `messageId` | `string` | 将一次上下文压缩的开始与结束配对。将其视为不透明键。                             |
| `reason`    | `string` | `auto` 或 `manual`。                                                             |
| `error`     | `object` | 当 `status` 为 `failed` 时存在。结构与[重试](#retry-status)的 `error` 相同。      |

该标记不包含摘要。自动触发的上下文压缩可能在没有 `started` 标记的情况下失败。当客户端加载会话时，OpenCode 会将每次已完成或已失败的上下文压缩作为一条标记重放。
