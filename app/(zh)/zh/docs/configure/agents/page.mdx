创建 Markdown 文件即可添加可复用的智能体。以下示例添加一个只读的审查智能体，主智能体可将其启动用于代码审查：

```md title=".opencode/agents/reviewer.md"
---
description: Reviews changes for correctness and regressions
mode: subagent
model: anthropic/claude-sonnet-5-5#high
permissions:
  - action: edit
    resource: "*"
    effect: deny
  - action: shell
    resource: "*"
    effect: deny
---

Review the current changes. List findings in severity order with file and line references.
```

请你的主智能体使用它：

```text
Use the reviewer subagent to review my current changes.
```

智能体将系统提示、模型偏好、权限与展示信息组合为一个具名的助手配置。

## 位置

可将 Markdown 智能体保存在全局位置（适用于所有项目），或保存在项目内部：

```text
~/.config/opencode/agents/<name>.md
.opencode/agents/<name>.md
```

OpenCode 会从当前目录向上查找项目根目录中的 `.opencode` 目录。嵌套路径会成为智能体 ID 的一部分：

```text
.opencode/agents/team/reviewer.md  →  team/reviewer
```

## 格式

### Markdown

Frontmatter 接受与 `agents` 配置项相同的字段。Markdown 正文将作为智能体的 `system` 提示：

```md title=".opencode/agents/explainer.md"
---
description: Explains code without changing it
mode: subagent
---

Explain the relevant code with short examples. Do not edit files.
```

V1 frontmatter 字段已弃用。仍使用这些字段的文件将如何被读取，请参阅[智能体文件](/zh/docs/migrating-to-v2#agent-files)。

### JSONC

在任意 [OpenCode 配置文件](/zh/docs/config)的 `agents` 下定义智能体：

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "agents": {
    "reviewer": {
      "description": "Reviews current changes",
      "mode": "subagent",
      "system": "Report findings in severity order.",
      "permissions": [
        { "action": "edit", "resource": "*", "effect": "deny" },
      ],
    },
  },
}
```

## 选择

设置会话尚未选择智能体时所使用的主智能体：

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "default_agent": "writer",
  "agents": {
    "writer": { "mode": "primary" },
  },
}
```

所选的默认智能体必须存在、可见，并支持作为主智能体使用。否则 OpenCode 会依次使用 `build`，再退回第一个可见的、可担任主智能体的智能体。更改此设置不会替换已存储在现有会话上的智能体。

## 模式

根据智能体应当运行的位置设置 `mode`：

```jsonc
{
  "agents": {
    "reviewer": { "mode": "subagent" },
  },
}
```

| 模式 | 行为 |
| --- | --- |
| `primary` | 作为会话的主智能体运行。这是新建自定义智能体的默认值。 |
| `subagent` | 仅在子会话中通过 `subagent` 工具运行。 |
| `all` | 既可作为主智能体运行，也可作为子智能体运行。 |

子智能体在前台或后台子会话中以全新上下文运行。父智能体的 `subagent` 权限控制其可启动哪些智能体；子智能体则使用其自身配置的权限。

```jsonc
{
  "agents": {
    "orchestrator": {
      "permissions": [
        { "action": "subagent", "resource": "*", "effect": "deny" },
        { "action": "subagent", "resource": "reviewer", "effect": "allow" },
      ],
    },
  },
}
```

## 内置智能体

OpenCode 包含以下可见的智能体：

| 智能体 | 模式 | 用途 |
| --- | --- | --- |
| **Build** (`build`) | `primary` | 默认的编码智能体。默认允许工作区之外的工具与访问；读取敏感环境文件时会请求批准。 |
| **Plan** (`plan`) | `primary` | 在不编辑普通项目文件的前提下进行探索与规划。被要求时可写入 OpenCode plan 文件，shell 命令仍受权限控制。 |
| **General** (`general`) | `subagent` | 以广泛的工具访问权限处理研究与多步骤工作，但不能启动更多子智能体。 |
| **Explore** (`explore`) | `subagent` | 搜索并阅读代码或网络来源，不编辑文件。 |

使用相同 ID 即可覆盖内置智能体：

```jsonc
{
  "agents": {
    "build": {
      "permissions": [
        { "action": "shell", "resource": "git push *", "effect": "ask" },
      ],
    },
  },
}
```

隐藏的 `compaction`、`title` 与 `summary` 智能体负责维护工作，无法被直接选择。V2 没有内置的 `scout` 智能体。

## 合并

智能体定义按配置顺序合并。较后的标量值会替换较早的值，request 映射按键合并，权限规则则追加：

```jsonc
{
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
  ],
  "agents": {
    "build": {
      "permissions": [
        { "action": "shell", "resource": "git status", "effect": "allow" },
      ],
    },
  },
}
```

全局 `permissions` 先于智能体专属规则生效，因此后续的智能体规则可对其加以细化。

## 选项

### 描述

`description` 说明智能体的用途。请为子智能体添加该字段，因为 OpenCode 会将其展示给负责选择要启动哪个智能体的模型：

```yaml
description: Reviews database migrations for safety
```

### 模式

`mode` 接受 `primary`、`subagent` 或 `all`。新建自定义智能体若省略该字段，默认为 `primary`：

```yaml
mode: all
```

### 模型

`model` 使用 `provider/model` 格式，并可附带可选的 `#variant`：

```yaml
model: anthropic/claude-sonnet-5-5#high
```

JSON 配置也接受展开形式：

```jsonc
{
  "agents": {
    "reviewer": {
      "model": {
        "providerID": "anthropic",
        "model": "claude-sonnet-5-5",
        "variant": "high",
      },
    },
  },
}
```

- 子智能体使用其配置的模型；若未配置，则继承父会话的模型。
- 会话单独存储其所选模型。按 ID 选择主智能体不会更改该模型。

### 系统提示

`system` 设置智能体的系统提示。非空值会替换提供商为该智能体提供的基础提示：

```jsonc
{
  "agents": {
    "reviewer": { "system": "Review only. Do not modify files." },
  },
}
```

项目指令、技能、引用及其他指令来源仍会被添加。在 Markdown 智能体中，请将此文本写在文档正文中，而不是 `system` frontmatter 字段里。

### 权限

`permissions` 是一个有序的匹配规则列表：

```jsonc
{
  "agents": {
    "reviewer": {
      "permissions": [
        { "action": "*", "resource": "*", "effect": "deny" },
        { "action": "read", "resource": "src/**", "effect": "allow" },
      ],
    },
  },
}
```

| 字段 | 含义 |
| --- | --- |
| `action` | 工具或权限动作。支持通配符。 |
| `resource` | 被该动作匹配的路径、命令、智能体 ID 或其他值。支持通配符。 |
| `effect` | `allow`、`ask` 或 `deny`。 |

最后一条匹配的规则生效，因此请将宽泛规则放在例外规则之前。常见动作包括：

| 动作 | 覆盖范围 |
| --- | --- |
| `shell` | Shell 命令 |
| `edit` | 编辑、写入与补丁工具 |
| `subagent` | 子智能体 |
| `read`、`glob`、`grep` | 本地发现工具 |
| `webfetch`、`websearch` | 网络工具 |
| `skill` | 技能加载 |

对于 `read`、`edit` 与 `external_directory` 资源，OpenCode 会展开 `~` 与 `$HOME`：

```jsonc
{ "action": "read", "resource": "~/notes/**", "effect": "allow" }
```

Shell 资源保持原始命令文本，不会展开这些值。

### 步骤

`steps` 设置正整数形式的模型步骤上限：

```yaml
steps: 8
```

在最后一步，OpenCode 会移除工具，并要求模型以文本形式进行总结。新的用户输入会重置该额度。

### 隐藏

`hidden` 会将智能体从常规列表、交互式发现与子智能体目录中移除：

```yaml
hidden: true
```

这控制的是可见性，而非安全性。请使用权限来限制行为。

### 颜色

`color` 使用六位十六进制值设置智能体的 UI 颜色：

```yaml
color: "#ff6b6b"
```

### 禁用

`disabled` 会在配置加载的相应位置移除内置或自定义智能体：

```jsonc
{
  "agents": {
    "plan": { "disabled": true },
  },
}
```

### 请求

`request` 接受按智能体分别设置的请求头与 JSON 请求体覆盖项：

```jsonc
{
  "agents": {
    "reviewer": {
      "request": {
        "headers": { "x-agent": "reviewer" },
        "body": { "temperature": 0.1 },
      },
    },
  },
}
```

<Callout type="warning">
  V2 会话运行器会保留这些值，但尚未随模型请求一起发送。请改为在提供商、模型或模型变体上配置实际生效的请求设置。
</Callout>

在新的 V2 智能体配置中，请勿使用遗留的顶层字段，例如 `temperature`、`top_p`、`prompt`、`permission`、`tools`、`disable` 或 `maxSteps`。
