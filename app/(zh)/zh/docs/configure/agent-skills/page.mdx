创建技能可为智能体提供针对特定任务的可复用指令。在 `.opencode/skills/<skill-id>` 中放置 `SKILL.md` 文件，并在 `description` 中说明何时使用该技能。

```markdown title=".opencode/skills/git-release/SKILL.md"
---
name: Git Release
description: Prepare release notes, version bumps, and GitHub releases
---

## Workflow

1. Read `references/release-policy.md`.
2. Summarize merged changes since the previous tag.
3. Propose the version bump before changing files.
4. Run `scripts/changelog.ts` only after the user approves the version.
```

OpenCode 会在相关时展示该技能。智能体随后可通过 `skill` 工具加载其指令，而不必将所有技能都加入每次提示。

## 创建

将相关的脚本、引用和模板放在 `SKILL.md` 旁边：

```text
.opencode/skills/
└── git-release/
    ├── SKILL.md
    ├── scripts/
    │   └── changelog.ts
    └── references/
        └── release-policy.md
```

技能中书写的路径相对于包含 `SKILL.md` 的目录。推荐使用目录形式，因为它为支持文件提供了私有的基础目录。

## 发现

OpenCode 会自动搜索以下位置：

| 范围 | 来源 |
| --------------------- | -------------------------------------- |
| 全局 | `~/.config/opencode/skills` |
| 全局兼容 | `~/.claude/skills`, `~/.agents/skills` |
| 项目 | `.opencode/skills` |
| 项目兼容 | `.claude/skills`, `.agents/skills` |

对于项目来源，OpenCode 会从当前目录向上搜索到项目根目录，并在每一级包含匹配的目录。

每个来源可以包含任一形式：

```text
skills/
├── review.md
└── git-release/
    └── SKILL.md
```

- Markdown 文件必须位于来源根目录，例如 `skills/review.md`。
- 名为 `SKILL.md` 的文件可以嵌套在分组目录中，例如 `skills/git-release/SKILL.md` 或 `skills/teams/release/SKILL.md`。
- 包含 `SKILL.md` 的目录即为一个技能。OpenCode 不会在其内部继续搜索更多技能。
- 隐藏文件、隐藏目录以及 `node_modules` 会被跳过。
- 搜索在来源根目录以下六级目录处停止。

## 来源

可在任意 `opencode.json` 或 `opencode.jsonc` 中通过 `skills` 数组添加更多本地目录或 HTTP 目录：

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "skills": [
    "./team-skills",
    "~/shared/opencode-skills",
    "/opt/company-skills",
    "https://example.com/opencode/skills/",
  ],
}
```

| 值 | 解析方式 |
| ----- | ---------- |
| 相对路径 | 从当前活动的 OpenCode 工作目录解析，而非配置文件所在目录 |
| `~/` 路径 | 从当前用户的主目录解析 |
| 绝对路径 | 按写入的内容直接使用 |
| `http://` 或 `https://` URL | 作为 HTTP 目录加载 |

每个被发现的配置文件都会贡献其条目。`skills` 数组会被合并，而非替换。

## HTTP 目录

HTTP 目录是一个带有 `index.json` 文件的基础 URL：

```json title="index.json"
{
  "skills": [
    {
      "name": "git-release",
      "version": "3",
      "files": ["git-release.md", "references/release-policy.md"]
    }
  ]
}
```

对于该条目，OpenCode 会从 `<base-url>/git-release/<file>` 下载每个文件。

| 规则 | 要求 |
| ---- | ----------- |
| 路径 | 必须安全、相对且同源 |
| 条目文件 | 包含 `SKILL.md` 或 `<name>.md`，例如 `git-release.md` |
| 更新 | 文件变更时递增 `version`，以便 OpenCode 刷新缓存 |

每个下载的技能目录都会成为以条目命名的来源根目录，因此 `git-release.md` 与 `SKILL.md` 的 ID 都是 `git-release`。

## Frontmatter

使用 frontmatter 为技能命名并控制其出现位置：

```markdown title="SKILL.md"
---
name: Git Release
description: Prepare a repository release
metadata:
  opencode/autoinvoke: false
---

Prepare the changelog, version bump, tag, and release notes.
```

| 字段 | 行为 |
| ------------------------------ | ----------------------------------------------------------------- |
| `name` | 显示名称；默认为路径推导出的 ID |
| `description` | 用于向模型展示该技能的摘要 |
| `metadata.opencode/autoinvoke` | 设为 `false` 可将该技能从模型的可用列表中省略 |
| `disable-model-invocation` | 设为 `true` 效果等同于 `opencode/autoinvoke: false` |

运行时所有 frontmatter 字段均为可选。若希望模型能发现该技能，请添加清晰的 `description`；没有描述的技能不会被展示。

`opencode/autoinvoke: false` 仅从模型的可用列表中隐藏该技能。技能仍处于已注册状态，仍可通过 ID 显式加载。当 `disable-model-invocation` 与 `opencode/autoinvoke` 同时设置时，以 `opencode/autoinvoke` 为准。V2 接受 `license` 和 `compatibility` 等可移植性字段，但不对其做解释。

## ID

文件路径决定技能 ID。frontmatter 中的 `name` 仅是显示标签。

| 文件 | ID |
| --------------------------------- | ------------- |
| `<source>/git-release.md` | `git-release` |
| `<source>/git-release/SKILL.md` | `git-release` |
| `<source>/teams/release/SKILL.md` | `release` |

ID 精确匹配且区分大小写。对于可移植的技能，请使用 1–64 个字符的唯一小写 kebab-case ID，并使其与目录名保持一致：

```text
^[a-z0-9]+(-[a-z0-9]+)*$
```

V2 目前不强制执行该模式、1–64 个字符的建议长度、`name` 与目录名的匹配，或描述的最大长度。

## 优先级

技能按 ID 选择。如果两个来源都定义了 `git-release`，则后注册的来源提供 OpenCode 加载的技能：

```text
~/.config/opencode/skills/git-release/SKILL.md  ← lower precedence
.opencode/skills/git-release/SKILL.md           ← loaded
```

来源按优先级从低到高注册：

1. 内置技能
2. `.claude/skills`，先全局，然后从最远祖先目录朝当前目录方向
3. `.agents/skills`，先全局，然后从最远祖先目录朝当前目录方向
4. `~/.config/opencode/skills`
5. 项目 `.opencode/skills`，从项目根目录朝当前目录方向
6. 显式 `skills` 配置条目，按配置优先级与数组顺序

除非有意覆盖较早的技能，否则请避免重复 ID。

## 加载

在模型的每一步中，OpenCode 会列出被允许的、具有描述且未将 `opencode/autoinvoke` 设为 `false` 的技能。该列表仅包含 ID、名称和描述，不含完整的 Markdown 正文。

模型通过以确切 ID 调用 `skill` 工具来加载技能：

```json title="skill tool input"
{
  "id": "git-release"
}
```

随后 OpenCode 会：

1. 选择该 ID 的当前定义。
2. 检查所选智能体的 `skill` 权限。
3. 将不含 frontmatter 的 Markdown 正文加入对话。
4. 提供技能的基础目录，以及最多十条支持文件路径的样本。

若要自行加载技能，可在提示中以 `@skill-id` 形式提及它。

支持文件的内容不会自动加载。智能体会在技能指示时读取它们。文件样本适用于基于目录的 `SKILL.md` 技能；扁平的 Markdown 技能不会收到相邻文件列表。

## 权限

使用 `skill` 动作，并以技能 ID 作为资源。规则按顺序执行，最后一条匹配的规则生效：

```jsonc title="opencode.jsonc"
{
  "permissions": [
    { "action": "skill", "resource": "*", "effect": "allow" },
    { "action": "skill", "resource": "internal-*", "effect": "deny" },
    { "action": "skill", "resource": "experimental-*", "effect": "ask" },
  ],
}
```

| 效果 | 行为 |
| ------ | -------- |
| `allow` | 展示并加载匹配的技能，无需批准 |
| `ask` | 展示匹配的技能，并在加载前询问 |
| `deny` | 对模型隐藏匹配的技能并拒绝加载 |

将相同规则放在 `agents.<id>.permissions` 下，即可仅对某个智能体生效。

## 故障排除

例如，该技能的 ID 是 `release`，而非其 frontmatter 中的名称 `Git Release`：

```text
.opencode/skills/release/SKILL.md
                      └─ ID: release
```

如果技能缺失或加载了错误的内容：

1. 确认该文件要么是根目录下的 `*.md`，要么是嵌套的、名称恰为 `SKILL.md` 的文件。
2. 检查由路径推导的、区分大小写的 ID，而非 frontmatter 中的 `name`。
3. 若要让模型发现该技能，请添加 `description`。
4. 检查 `opencode/autoinvoke` 以及所选智能体的 `skill` 权限。
5. 查找是否有更晚注册的来源定义了相同的 ID。
6. 对于 HTTP 目录，请验证 `index.json`、同源的文件路径，以及已变更的 `version`。
